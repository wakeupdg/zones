## Goal

- `LayoutMath.unitRects(root)` turns a SplitNode into leaf rectangles that tile the unit square; `LayoutMath.layoutRect` subtracts the Surround from a visible frame.
- `Grid.round` takes unit rects, the Layout rectangle, Margin and Gap and a scale, rounds every divider and the Gap once to 1/scale, so neighbours share dividers, every Gap is the same whole pixel count, and a mirror-image tree gives mirror-image pixels. Never "remainder to the last Zone".
- `LayoutMath.resolve` chains surround, insets, `Grid.round`, numbering into a `ResolvedLayout` whose Zones are sorted 1...N, so Overlay and Snap read the same rectangles.
- `ZoneNumbering.numbers` is row-major (top edge, then left edge, with epsilon), derived from unit rects and never stored.
- `CoordinateSpace` bodies: AppKit <-> AX round trip, `display(for:)` by maximum intersection, `panelLocal`.
- Property tests over `Generator` trees and `Fixtures.threeDisplays` prove it: `LayoutTilingTests.randomTreesTile`, `ZoneNumberingTests.rowMajorBijection`, `GridRoundingTests.overlayEqualsSnapTarget` and `uniformPixelGapsAndSharedDividers`, `CoordinateSpaceTests.roundTripAndDisplayFor`.

Rules the contracts imply:
- Unit space: x grows right, y grows DOWN (y = 0 is the top edge; numbering sorts by top edge). `.horizontal` split: first = left, width share = ratio. `.vertical`: first = top, height share = ratio.
- Every CGRect leaving `Grid`/`resolve` is AppKit global (origin bottom-left, y up): frame.y = layoutRect.maxY - (u.y + u.height) * layoutRect.height.
- Path: `false` = first child, `true` = second, `[]` = root (a single-leaf tree yields one rect at path `[]`).

## Algorithm notes (decisions already made)

- `layoutRect`: top/bottom fractions are of visibleFrame.height, left/right of width. AppKit y-up: bottom raises minY, top lowers maxY. Surround all 0 returns visibleFrame unchanged (every Template but Focus; Focus is 0.2 per side, one Zone, centered 60 percent).
- `Grid` edge rule (Resolved disagreement "Rounding": dividers and Gap once, never remainder-to-last-Zone): compute every divider position as a pure function of its unit coordinate, not of traversal order, so two neighbours that touch the same unit coordinate get the identical value (shared dividers). Snap to whole pixels = round(value * scale) / scale. Break exact .5 ties toward the Layout rectangle's centre, so reflecting the tree reflects the pixels exactly (mirror symmetry).
- Margin: outer Zone edges sit exactly Margin inside the layoutRect (rounded once to pixels). Gap: g = max(0, round(gap * scale)) whole pixels, rounded once; an interior divider d yields zone edges d - g/2 and d + g/2 pixels, so every Gap is the same whole pixel count and the divider lies on a pixel boundary (AC-069 text). An odd g puts zone edges on half pixels; that is allowed by the AC wording. Pick one rule, document it in a doc comment, and put one ledger line stating it.
- `ZoneNumbering`: sort by rect.y ascending; rects whose y differ by <= `Constants.numberingEpsilon` count as the same row; within a row sort by x ascending; if x ties too, break by lexicographic path steps (false before true) so the result is deterministic. Return number 1...N. Input is unit rects only, so numbers are invariant under Display size, scale, Margin and Gap by construction. Do not make the comparator epsilon-intransitive: cluster rows first (compare each y with the first y of its cluster), then sort inside clusters.
- `resolve`: layoutRect from surround; `unitRects`; `Grid.round(layout.insets, scale)`; `ZoneNumbering.numbers` on the UNIT rects; build `Zone`s sorted by number; `ResolvedLayout(layoutID: layout.id, display: key, visibleFrame:, layoutRect:, scale:, zones:)`. The `display:` overload forwards `display.key`, `display.visibleFrame`, `display.scale`. Same inputs give `==` outputs (no hidden state).
- `CoordinateSpace`: AX origin is the top-left of the primary display, y down. `axRect`: x, width, height unchanged; y = primaryFrame.maxY - (appKit.y + appKit.height). `appKitRect` is the exact inverse, so a rect on the portrait Display above the primary gets negative AX y. Round trip is identity up to floating error: compare with tolerance 1e-9. `display(for:)`: the Display whose `frame` has the largest intersection area with the rect; ties go to the earlier Display in `snapshot.displays`; zero intersection with all returns nil. `panelLocal`: same size, origin = appKit.origin - panelFrame.origin (still y-up; flipping for SwiftUI is the view's job).
