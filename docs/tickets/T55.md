# T55: Detect Accessibility revocation with the trust probe in the granted health tick (AC-007, AC-009, SPK-006)

Kind: fix (orchestrator, from the human run on 2026-10-24). Blocked by: none.

## Evidence
- AC-009 failed in the human run (docs/qa/priority-manual-acs.md, docs/qa/logs/ac009-watch-2026-10-24.log): the toggle was off for about 12.5 min; Zones showed no badge and no onboarding window; a Shift-drag did nothing.
- SPK-006 trial 1 (docs/spikes/logs/revoke-system-1.jsonl): after revocation `AXIsProcessTrusted()` turned false within one 250 ms row and stayed false; the brief read stayed -25204 and the alternate `kAXRoleAttribute` read stayed success (never apiDisabled); the listen-only tap stayed enabled and kept delivering events.
- So on macOS 27.0.1 no runtime signal of AC-007 fires on revocation, and `heartbeatEnabled = false` leaves the granted state blind.

## Goal
1. In `granted`, every `.timer(.healthTick)` emits `.probe` (the driver answers with `.probe(probe.isTrusted())`). `.probe(false)` already moves to `suspect`; `.probe(true)` re-arms the tick.
2. In `suspect`, return to `granted` only when a trust probe reads true. A recreated tap or a trivial AX read is not evidence of a grant (SPK-006: both look healthy after revocation). Otherwise, after the 3 s resolve window, go to `revoked` with the existing effects (badge, showOnboarding, unregisterWindowHotkeys, drainEnhancedUI).
3. Keep the heartbeat AX read off (`heartbeatEnabled = false`, SPK-006 verdict). Do not add a timer: the probe runs inside the existing 5 s health tick, so the AC-156 timer set is unchanged.
4. Amend AC-007 and AC-009 in docs/LOCKED-SPEC.md through challenge C12 (one line in the challenge list, like C11). AC-009: the badge and onboarding window appear within 5 s of revocation while idle (one health tick), not "at the next Drag Session".

## Acceptance
AC-006, AC-007 (amended), AC-156 (unchanged timer set), AC-009 (manual, amended; re-run by a human after the merge).

## Test plan (test-first, fake Clock and fake probe)
1. Red, then green: granted + healthTick with probe false → suspect; after 3 s with probe still false → revoked with exactly the four effects in order.
2. Granted + healthTick with probe true → granted, one health tick re-armed, no other timer (AC-156).
3. Suspect + `tapRecreated(true)` + trivial read ok, but probe false → revoked after 3 s (the SPK-006 case).
4. Suspect + probe true within 3 s → granted, no badge.
5. Full `swift test` green; Debug xcodebuild green.
