# T03: Spike: click-through panel, overlay frame time, per-Space witness windows (SPK-002, SPK-009, SPK-001)

Kind: spike. Blocked by: T01 (root Package.swift and scripts exist). Estimate: 90k tokens.

## Goal
- Build a throwaway probe at `Spikes/PanelProbe` (its own `Package.swift`, one executable target, NOT part of the root package or XcodeGen).
- Mode `panel`: orders a `.screenSaver`-level, click-through, non-key `NSPanel` during a title-bar drag (Shift held). It logs frontmost pid, key window, panel visibility over a full-screen Space, a Split View Space and a Space created after launch, whether a managed window can be dropped on a Display whose active Space is full-screen, and `visibleFrame` vs `frame` with the menu bar auto-hidden.
- Mode `frametime`: measures per-dragged-event CALayer update time at 120 Hz (persistent layers) and the same for an `NSHostingView` SwiftUI variant.
- Mode `witness`: creates one hidden managed witness window per (Display, Space) and checks `isOnActiveSpace` over 20 Space switches.
- Output is three verdict notes (`docs/spikes/SPK-002.md`, `SPK-009.md`, `SPK-001.md`) with pass/fail and the recorded tables. SPK-001 pass or fail decides whether a document-v2 Space token ticket is added later.
- The verdict fixes expectations for AC-043, AC-044, AC-045, AC-046, AC-062 and the SwiftUI-vs-CALayer decision for T31.

## Acceptance
No acceptance_ids. The spike blocks from LOCKED-SPEC section 7 (verbatim; "Depends" lists the ACs the verdict fixes):

- SPK-001 Per-Space identification via hidden witness windows (ADR-0013). Method: one invisible managed window per (Display, Space); on each active-Space change the witness with isOnActiveSpace true identifies the Space. Pass: identifies the Space correctly in 20 of 20 switches across Space creation, deletion, Display reconnect and a full-screen Space, with no private API. Fail: per-Space Assignments move to out of scope. Depends: none in v1; a pass adds an optional Space token to the Assignment record (document version 2).
- SPK-002 Click-through panel during a drag. Pass: a screenSaver-level, click-through, non-key panel ordered front during a title-bar drag leaves the drag, the frontmost app and the key window unchanged; visibility recorded over a full-screen Space, a Split View Space and a Space created after launch; whether a managed window can be dropped on a Display whose active Space is full-screen; what visibleFrame reports with the menu bar auto-hidden. Depends: AC-044, AC-046, AC-045, AC-062.
- SPK-009 Overlay frame time. Pass: persistent CALayers updated per dragged event stay under one frame at 120 Hz; SwiftUI hosting measured and adopted only if it also passes. Depends: AC-040, AC-039.

ACs whose expected result this verdict fixes (context only, do not implement them here):

## Interface contracts
From docs/CONTRACTS.md (section 3.0 seams and 3.8 overlay model).

IMPLEMENTS: none. The probe is a separate package and must not import Zones targets. It prototypes the panel recipe that App's `PanelOverlayPresenter` will use.

CONSUMES (as shape reference only):
```swift
public protocol OverlayPresenter: Sendable {   // Production: App's PanelOverlayPresenter. Fake: FakeOverlayPresenter
  @MainActor func show(_ scene: OverlayScene); @MainActor func highlight(_ h: Highlight); @MainActor func hide()
  @MainActor func reassert(); @MainActor func orderOut(); @MainActor func resize(to snapshot: TopologySnapshot) }
public struct PanelModel: Hashable, Sendable { public var display: DisplayKey; public var frame: CGRect; public var zones: [ZoneDrawing]; public var style: PanelStyle; public var spanOutline: Bool }
public struct ZoneDrawing: Hashable, Sendable { public var number: Int; public var rect: CGRect; public var fill: RGBA; public var label: ZoneLabel }
```
- Use `PanelModel` to size the frametime load: one panel per screen, panel frame = `screen.frame`, 4 to 12 zone layers (use 12 for the worst case) plus one highlight layer, rects inside `visibleFrame`.
- The SPK-002 note must state whether `reassert()` (re-`orderFrontRegardless` on active-Space change) is needed, and what `hide()` vs `orderOut()` must do. That is the input for AC-062 and T31.

## Test plan
`swift test` cannot drive AppKit UI (LESSONS), so there are no XCTest targets. Each slice is "red" = the named probe check fails or the mode is missing, "green" = it runs and its output is recorded. Keep pure logic (percentiles, table rendering, verdict rules) in functions covered by `--self-test`.

1. Slice `selfTest.statsAndTables`. Add `--self-test`: asserts p50/p95/p99/max and "share over 8.33 ms" on a fixed array, and that the markdown table renderer emits the expected header and rows. Exercises: none (pure helpers).
2. Slice `panel.configuration`. Build the panel per ADR-0023 recipe (borderless + nonactivatingPanel, `.screenSaver`, collection behavior `canJoinAllSpaces, fullScreenAuxiliary, stationary, ignoresCycle` and a second run adding `canJoinAllApplications`, `ignoresMouseEvents`, `canBecomeKey/Main` false, no shadow, clear background, `.accessory` policy). `--self-test` asserts the panel reports exactly the AC-043 values. Exercises: `PanelModel` frame = `screen.frame`.
3. Slice `panel.dragProbe` (manual). A global `NSEvent` monitor (mouse down, dragged, up, flagsChanged) arms on Shift + title-bar drag; on arm call `orderFrontRegardless()` once; on mouse up `orderOut`. Log per run: frontmost pid and key window before, during and after; CGWindowList layer of the panel (expect 1000 only while armed); drag continued without interruption. Exercises: `show`/`hide`/`orderOut`.
4. Slice `panel.spaces` (manual). Repeat 3 over: a full-screen Space, a Split View Space, a Space created after launch (with and without `reassert()` from `NSWorkspace.activeSpaceDidChangeNotification`), and a second Display whose active Space is full-screen (does the panel show; can a managed window be dropped there; where does it land). Log `frame` vs `visibleFrame` and `NSApp.currentSystemPresentationOptions` with the menu bar auto-hidden. Exercises: `reassert`, `resize`.
5. Slice `frametime.layers` (manual and synthetic). One panel, 12 zone CALayers plus a highlight layer, updated per dragged event inside `CATransaction.setDisableActions(true)`; time the handler through commit with `ContinuousClock`; at least 2000 events per run, real drag and a `--synthetic` run. Record p50, p95, p99, max, share over 8.33 ms (1 frame at 120 Hz), `NSScreen.maximumFramesPerSecond`, OS version. Exercises: `highlight`.
6. Slice `frametime.swiftui`. The same load through `NSHostingView` with a state-driven highlight; same table. SwiftUI is adopted only if it also passes.
7. Slice `witness.create`. Create one hidden `.managed` witness `NSWindow` per (Display, Space), lazily on first visit, not `canJoinAllSpaces`; test two hidden variants (ordered out; alpha 0, ordered front, `ignoresMouseEvents`). Log which witnesses report `isOnActiveSpace` true. Exercises: none.
8. Slice `witness.switches` (manual). Plan file lists the expected Space label per switch. Run 20 switches covering Space creation, deletion, Display reconnect and a full-screen Space (full-screen Spaces have no witness: record how the probe detects them). Table: switch number, expected label, witnesses true, correct yes/no. 20 of 20 is a pass.
9. Slice `verdicts`. Fill the three notes from the recorded output.
