# T67: Span Zone numbers after a topology change during a drag

Kind: fix (v0.1.1, CHANGELOG 0.1.0 known issue from the T39 review). Blocked by: none.

## Known issue
After a topology change during a drag (a display is added, removed or rearranged while the Activation Modifier drag is live), Span Zone numbers come from the old Layout; a number missing from the new Layout shrinks the drop rectangle silently.

## Goal
1. Reproduce it in a pure test (SpanLogic / drag reducer inputs: span set from Layout A, then the topology changes to Layout B).
2. Decide the correct behavior from the spec (LOCKED-SPEC: Span, topology change, drag). Likely: on a topology change mid-drag, re-resolve the span set against the new Layout or cancel the span; never a silent shrink. If the spec does not say, ask DG with 2 options.
3. Fix test-first.

## Spec note (DG, 2026-10-25: option A)
LOCKED-SPEC is silent on a Layout change under a live Span (AC-060 re-arms and re-hits; US-060, US-062 and US-063 cover sweeps, freeze and seams). Rule, in `SpanLogic.rebase`, applied by the armed `topologyChanged` before the re-hit's `accumulate`:
1. The Span's Display keeps the Layout the Span was swept on (same LayoutID and same Zone numbers): the set is kept and its rectangle re-resolves (a resolution change, another Display added or removed).
2. The Span's Display has a different Layout: the set is cleared and the re-hit starts it again with the Zone under the cursor when the Span Modifier is held. Old numbers name other areas in a new Layout, so none is kept.
3. The Span's Display is gone: the set stays suspended (US-063). When it comes back, the set is kept only if every member exists in its Layout; otherwise rule 2.
4. `frozen` is kept in every case (US-062). The highlight is derived from the same Span, so it shows the new set at once (LI-009): never a silent shrink.
No AC changes: AC-060 still holds. Tests: `swift test --filter SpanTopologyTests`.
