# T08: Spike: login item on a clean account, identical Displays, hotkey key status, sleep/wake (SPK-011, SPK-012, SPK-014, SPK-018)

Kind: spike. Blocked by T01 (root Package.swift and App/ exist). No acceptance ids; the four spike verdicts are the deliverable.
Contracts: IMPLEMENTS none (no production code). CONSUMES none from the packages: the probe is a standalone throwaway package that mirrors three contract shapes so the verdicts map straight onto them.

## Goal

1. Build `Spikes/HardwareProbe`, a standalone SPM executable (own Package.swift, NOT part of the root package) with subcommands: `login`, `displays`, `hotkey`, `sleepwake`.
2. `login` prints SMAppService.mainApp status and drives register/unregister, so the manual protocol records status after disabling in System Settings, after register from a quarantined DMG copy, and after moving the app.
3. `displays` prints per-Display UUID, vendor/model/serial and localizedName, and checks two same-model Displays give distinct UUIDs; the zero-serial fallback is recorded.
4. `hotkey` registers Control+Option+Comma via Carbon, opens a plain window from the handler (with and without a prior `NSApp.activate`), and logs `isKeyWindow`/`isVisible` and whether typing lands; the result is a per-OS key-status table for macOS 14 and 15.
5. `sleepwake` logs a listen-only tap's liveness, panel visibility and every Display UUID before sleep and after wake (lid-closed, docked).
6. Verdicts go in docs/spikes/SPK-011.md, SPK-012.md, SPK-014.md, SPK-018.md. SPK-014's table fixes the expected key status in AC-023 (T32); SPK-011 informs AC-027/028; SPK-012 informs AC-119/123; SPK-018 informs AC-024/025.

## Interface contracts

None implemented or consumed from code. The verdicts constrain these declarations (docs/CONTRACTS.md, section 3 seams; do not edit that file):

```swift
public enum DisplayKey: Hashable, Sendable { case uuid(String), unstable(String) }     // unstable: session only, never encoded
public enum HotkeyRegistration: Hashable, Sendable { case registered, inUse, invalid }
public protocol HotkeyRegistrar: Sendable {   // Production: CarbonHotkeyRegistrar. Fake: FakeHotkeyRegistrar
  @MainActor func register(_ chord: Chord, for action: ShortcutAction) -> HotkeyRegistration
  @MainActor func unregister(_ action: ShortcutAction); @MainActor func bound(_ action: ShortcutAction) -> Chord?; var presses: AsyncStream<ShortcutAction> { get } }
public enum LoginItemStatus: Hashable, Sendable { case enabled, requiresApproval, notFound, notRegistered }
public enum LoginItemError: Error, Hashable, Sendable { case launchDeniedByUser, invalidSignature, other(String) }
public protocol LoginItemService: Sendable {   // Production: SMLoginItemService. Fake: FakeLoginItemService
  @MainActor func status() -> LoginItemStatus; @MainActor func register() throws(LoginItemError)
  @MainActor func unregister() throws(LoginItemError); @MainActor func openLoginItemsSettings() }
```

Map: SPK-011 states which `LoginItemStatus` each step yields (and whether `notFound` or `requiresApproval` follows a user disable). SPK-012 states whether `DisplayKey.uuid` is distinct for identical Displays or `.unstable` is needed. SPK-014 states which OS lets the `HotkeyRegistrar` press handler take key status.

## Test plan

Manual spike, protocol none, fake none. `swift test` cannot drive AppKit UI, so no automated tests; the run log in docs/spikes/SPK-014.md is the evidence. Slices, one per commit:

1. Skeleton: Package.swift plus main.swift that parses a subcommand and prints usage; asserts `swift build` succeeds. Exercises no contract.
2. `login`: prints `SMAppService.mainApp.status` mapped to the `LoginItemStatus` names; `register`/`unregister`/`open-settings` options. Exercises LoginItemService shape. Then run the manual protocol: signed copy in /Applications on a clean account (register, disable in System Settings, read status); copy via a mounted DMG with quarantine (`xattr -w com.apple.quarantine`) and register; move the app after register and re-read status. Write SPK-011.md.
3. `displays`: lists UUID, vendor, model, serial, `localizedName`, `CGDisplayIsMain`; prints PASS if all UUIDs distinct, and prints the fallback fingerprint when a UUID is nil or serial is 0. Exercises DisplayKey. Run with two Displays of one model; if only one model is on hand, record that and mark the identical-model result untested. Write SPK-012.md.
4. `hotkey`: Carbon `RegisterEventHotKey` for Control+Option+Comma opens a window; modes `--activate` and `--no-activate`; logs `isVisible`, `isKeyWindow`, `NSApp.isActive`, frontmost app; a typed key echoes into the window to prove typing lands. Exercises HotkeyRegistrar. Run on macOS 14 and 15 with TextEdit frontmost, both modes. Write SPK-014.md with the table. If one OS is not available, say so in the table, never guess.
5. `sleepwake`: listen-only session tap for left mouse down/dragged/up plus flagsChanged, one click-through panel per Display, `NSWorkspace.didWakeNotification` and `willSleepNotification` logging; before and after, print tap-enabled state, panel `isVisible` and frames, and all Display UUIDs; a manual-trigger `post-wake` subcommand re-prints the same state. Exercises DisplayKey and the AC-024 wake path. Run lid-closed on a docked Mac. Write SPK-018.md.

Manual ACs (AC-023, AC-025, AC-028, AC-119): need no test here; the verdicts are their inputs.
