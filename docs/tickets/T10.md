# T10: Documents and preferences: codec, atomic DocumentStore, quarantine, migration with golden fixtures, Preferences coercion

Kind: build. Blocked by: T01. Estimate: 150k tokens. Branch: ticket/T10. Module: ZonesCore only (no AppKit).

## Goal

- `ZonesDocument` encodes and decodes with the section 1.8 field names; `PersistentDisplayKey` rejects non-UUID keys (`DocumentError.nonUUIDKey`).
- `DocumentStore` runs over the `FileSystem` seam: synchronous atomic writes, timestamped backups, quarantine of undecodable files, newer-version files left byte-identical.
- `Migrator` is the single decoder for disk and export. Golden fixtures exist per version, and a fixture-hash test fails if a golden changes without a version bump.
- `PreferencesCodec` coerces field by field and sets notice flags; `Preferences.defaults` exists; Span Modifier is always coerced to differ from Activation Modifier.
- `Appearance` round-trips through preferences; `AppearancePaneModel` lists the Layouts that follow the default Insets.

Contract gaps this brief resolves (record each in the ledger; do not ask):
- `CGRect` default Codable is nested arrays. `lastVisibleFrame` must encode as `{"x","y","width","height"}`; `lastSeen` as ISO 8601 UTC. Use private wrapper types in Documents.swift.
- `SplitNode` encodes as `{"kind":"leaf"}` or `{"kind":"split","axis","ratio","first","second"}`. If T01 did not write that Codable, add it by extension in Documents.swift. `Layout.builtIn` is never encoded.
- `layouts.json` writes only `version` and `layouts`; `assignments.json` writes only `version` and `assignments`. Export writes both. Decoding treats a missing array or map as empty. Encoding uses sorted keys so bytes are stable.
- `ShortcutRules.defaults` lives in ZonesWindowing, which Core cannot import. Declare `Preferences.defaultShortcuts` in Core (AC-097: Control+Option+1..9 sendToZone, Right/Left cycle, R restore, E openEditor, Comma openSettings). The Shortcuts ticket makes `ShortcutRules.defaults` return it.
- Defaults not in the spec; use: fill RGBA(0.2, 0.5, 1.0, 1.0), opacity 0.3, defaultInsets margin 8 gap 8, notices empty, exclusions empty.
- `backupName(_:now:)` takes `now` as seconds since 1970 and formats `<kind>.<yyyyMMdd-HHmmss>.bak` in UTC (fixed formatter, deterministic). Quarantine name is `<kind>.<yyyyMMdd-HHmmss>.corrupt`. `load` passes `Date().timeIntervalSince1970` unless a test injects a wall time through an internal `init(..., wallClock:)`; `Clock.now` is monotonic and must not be formatted.
- A missing file loads as `.loaded` with an empty document at the current version and emits no event.
- `DocumentStore` internal init takes `currentVersion` (default `Constants.documentVersion`) and `Migrator` has an internal `migrate(_:current:steps:)` taking a step table `[Int: (inout [String: Any]) throws -> Void]`. Tests use these to exercise migration while the real version is 1.
- `DocumentError.message` must name both numbers for `newerVersion`, e.g. "document version 2 is newer than supported version 1".
- `AppearancePaneModel` is not in CONTRACTS.md. Declare `public struct AppearancePaneModel { public static func followers(of defaults: Insets, in layouts: [Layout]) -> [LayoutID] }`. A Layout follows when `builtIn != nil` or its `insets == defaults`. Do not edit docs/CONTRACTS.md; note the new declaration in the ledger.

## Test plan

Swift Testing. One red-green slice per commit, in this order.
1. `DocumentTests.codecFieldNames` (contract ZonesDocument): decode the layouts and assignments golden JSON; re-encode; assert keys `version`, `layouts`, `assignments`, `lastVisibleFrame.x`, `kind` exactly; decoded content equals a hand-built document; bytes are stable on a second encode.
2. `DocumentTests.rejectsNonUUIDKey` (PersistentDisplayKey, DocumentError.nonUUIDKey): a key like "unstable:3" or "abc" fails decode with `.nonUUIDKey`; an uppercase UUID passes. (AC-123's named test belongs to T25; the rule lives here.)
3. `DocumentTests.exportRoundTrip` (AC-145): a document with both arrays, and one with a single Layout, encode with `encoded(for: nil)`, decode through `Migrator.migrate`, equal content, top-level `version` present.
4. `DocumentTests.atomicWriteSurvivesFailure` (AC-150, DocumentStore, FileSystem): save once; FakeFileSystem `failAfterBytes:` set below the payload; second save throws `.io`; `load` still returns `.loaded` of the first document; no temp file left. Add one real-disk test of FoundationFileSystem in a temp dir (write, overwrite, read).
5. `DocumentTests.corruptFileQuarantined` (AC-149): garbage bytes; `load` returns `.defaults(quarantined:)` naming the moved file; the original path is gone, the quarantined file holds the original bytes; exactly one `.notice` LogEvent in the category `.core`; a second load returns the empty default without another event.
6. `DocumentTests.newerVersionRefusedAndUntouched` (AC-147): `Migrator.migrate` of version 2 returns `.newerVersion(found: 2, supported: 1)` and its `message` contains "2" and "1"; a disk file at version 2 loads as `.newerLeftUntouched(version: 2)`, bytes identical, no move, no backup, and `save` over it throws `.newerVersion` without writing.
7. `MigrationTests.goldenFixturesMigrate` (AC-152, Migrator): every `*.v<N>.json` for N from 1 to `Constants.documentVersion` decodes via Migrator and equals the expected document; table-driven so a future version adds a row.
8. `MigrationTests.migrationWritesBackupFirst` (AC-152, DocumentStore): with `currentVersion: 2` and a step 1 to 2, loading the v1 golden returns `.migrated(doc, from: 1, backup:)`; the backup file exists with the original bytes and the name `<kind>.<yyyyMMdd-HHmmss>.bak`; the migrated file on disk decodes at version 2; the backup is written before the migrated file (check the fake's write log order).
9. `FixtureHashTests.goldensUnchanged` (AC-152): SHA-256 (CryptoKit) of each golden against a table in the test; plus `highestFixtureMatchesDocumentVersion`: for each kind the highest fixture version equals `Constants.documentVersion`, so a version bump without a new golden fails. Record the hashes after slice 1 writes the fixtures.
10. `PreferencesTests.modifiersMustDiffer` (AC-087, Preferences.coerced): all 16 modifier pairs; result Span differs from Activation, Activation unchanged, `.modifiersCoerced` set only when a change happened. Rule: keep Activation; Span becomes `.control`, or `.shift` when Activation is control.
11. `PreferencesTests.fieldByFieldCoercion` (AC-153, PreferencesCodec): start from a valid blob with Activation option, opacity 0.5, one custom exclusion, schemaVersion 1. (a) Span "hyper" (unknown) gives Span `.control`, every other field equal to the input, `coercedFields == ["spanModifier"]`, `.preferencesCoerced` in notices. (b) One shortcut chord lacking Command and Control gives only that action's chord back to its default, `coercedFields == ["shortcuts.<action>"]`, other shortcuts intact. (c) A blob that is not a JSON object gives `Preferences.defaults` and `coercedFields == ["*"]`. (d) A clean blob gives empty coercedFields and no new notices.
12. `PreferencesTests.appearanceRoundTrip` (AC-140): fill, opacity, defaultInsets encode and decode equal; opacity outside 0...1 or non-finite coerces to the default with `coercedFields == ["appearance.opacity"]`. Property check: 200 seeded random Appearance values round-trip (ADR-0016 in-house generator in ZonesTestSupport if present, else a seeded `SplitMix64` local to the test file).
13. `AppearancePaneModelTests.listsFollowers` (AC-140): built-ins and a custom Layout with insets equal to the defaults are listed; a custom Layout with different insets is not; after changing the defaults the lists change accordingly; order follows input order.
