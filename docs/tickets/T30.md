## Goal

- `EditorModel.open` builds an `EditorState` for a Layout on a Display. A connected Display resolves from the topology snapshot; a disconnected Display (no snapshot) resolves from its stored `Assignment.lastVisibleFrame` and `lastScale`.
- `EditorModel.reduce` applies `EditorEngine` commands with undo and redo, and recomputes `preview` (a `ResolvedLayout`), `warnings`, and therefore the labels in the same step. Margin and Gap edits show up in the preview rectangles immediately. After every command the editor's label model equals the Overlay label model for the same draft.
- `switchDisplay` emits `promptUnsaved` when the draft is dirty and not confirmed; with a clean draft it switches and re-resolves against the new Display.
- `assign` emits exactly one `writeAssignment` for the edited Display's key and the draft's Layout id. `save` validates, then emits one atomic `writeLayouts` followed by `replaceLive`. `cancel` emits no write.
- The Save path is tested through `DocumentStore` over `FakeFileSystem`: after the effect is interpreted, the file decodes to the saved document.

Design decisions (made here; record any deviation in the ledger):
- Geometry resolver, one private func used by `open` and `switchDisplay`: `topology.display(key)` gives `visibleFrame` and `scale`. Else, for `.uuid(u)`, `assignments[u]` gives `lastVisibleFrame` and `lastScale`. Else fall back to the main Display in the topology. Use `LayoutMath.resolve(layout, key:, visibleFrame:, scale:)` in every case so connected and disconnected paths share code.
- `open`: `EditorDraft(layout: l, selection: nil, dirty: false)`, empty undo and redo, `preview` resolved, `warnings = EditorEngine.warnings(preview)`.
- `.command(c)`: call `EditorEngine.apply(c, to: draft, geometry: (s.visibleFrame, s.scale))`. On `.failure(e)` return the state unchanged and `[.error(e)]`. On success record in `UndoStack` (every changing command, `select` included, is recorded; T18), then recompute `preview` and `warnings` from the new draft in this same call. No effects.
- `.undo` / `.redo`: through `UndoStack`; nothing to undo or redo is a no-op with no effects. Recompute `preview` and `warnings` after restoring the draft.
- `EditorModel.labels(_ s: EditorState, appearance: Appearance) -> [ZoneLabel]` returns `LabelModel.labels(s.preview, appearance:)`. It is the editor's label model; there is no stored label field. Labels therefore cannot go stale as long as `preview` is recomputed every step.
- `.switchDisplay(key, confirmed)`: if `draft.dirty && !confirmed` return the state unchanged and `[.promptUnsaved(key)]`. Otherwise set `display`, `visibleFrame`, `scale` via the resolver (context topology and `context.document.assignments`), re-resolve `preview` and `warnings`, keep the draft and stacks, no effects.
- `.assign`: state unchanged. Exactly one `.writeAssignment(PersistentDisplayKey, draft.layout.id)`. Check `Sources/ZonesCore` for how to construct `PersistentDisplayKey` from the `.uuid` string. For an `.unstable` display key return no effects (it is never persisted).
- `.save`: `LayoutValidator.validate(draft.layout)` non-nil: return the state unchanged and `[.error(...)]`, mapping `.leafTooSmall` to `.tooSmall`, everything else to `.invalidRatio` (same mapping T18 uses). No write. Do not add an `EditorError` case for empty names; log that gap in the ledger. Valid: new document = `context.document` with the layout (builtIn forced to nil) replacing the entry of the same id in `layouts`, or appended. Return `[.writeLayouts(newDoc), .replaceLive(layout)]` in that order and nothing else. New state: `draft.dirty = false`, undo and redo cleared.
- `.cancel`: state unchanged, `[.close]`. No `writeLayouts`, `writeAssignment` or `replaceLive`.
- The reducer is pure: it never touches `DocumentStore`. Only the test acts as the effect interpreter.

## ADRs

- ADR-0003 A layout is a binary split tree; zones are its leaves. Amendment 2026-10-24 (C1): the tree tiles the Layout rectangle, which is the visible frame minus a normalized surround per side (default 0, Focus 0.2, max 0.45); `LayoutMath.resolve` already applies it, so the editor just calls it.
- ADR-0004 Zone numbers are row-major by origin and recomputed after every edit (preview numbering comes from `LayoutMath.resolve`).
- ADR-0012 Displays are identified by CGDisplay UUID (`PersistentDisplayKey`, `Assignment` keyed by UUID).
- ADR-0017 Layouts and assignments are JSON files in Application Support with a top-level `version`; the saved file is a `ZonesDocument` (layouts.json).

## Test plan

Red-green slices in order; each is one failing test, then the minimum code, then a commit. Use `Fixtures.threeDisplays` and `Fixtures.nineZone`; build edited Layouts with `Templates.generate`.

1. `disconnectedDisplayUsesStoredGeometry` (AC-125; `open`, `Assignment`): key `.uuid(X)` absent from the topology, `assignments[X]` has `lastVisibleFrame` (0,0,2560,1415) and `lastScale` 2. Assert `state.visibleFrame`, `state.scale`, `state.display`, and that `state.preview == LayoutMath.resolve(layout, key:, visibleFrame: stored, scale: 2)`. Contrast: the same Layout opened on a connected Display uses the snapshot's `visibleFrame`.
2. `marginGapLive` (AC-131; `reduce`, `EditorEngine`): from one `reduce(.command(.setMargin(20)))` assert `draft.layout.insets.margin == 20`, `dirty`, and `preview` equals a fresh `LayoutMath.resolve` of the new draft, with zone frames different from before. Repeat for `.setGap(12)`. Also assert `.undo` restores the old preview, `.redo` restores the new one, and a failing command (for example `.merge` with no selection) returns the state unchanged plus `[.error(.nothingSelected)]`.
3. `labelsMatchOverlay` (AC-132; `EditorModel.labels`, `LabelModel`, `OverlayModel`): run a fixed sequence (select, split horizontal, split vertical, setGap, setMargin, rename, undo, redo). After each step assert `EditorModel.labels(state, appearance:)` equals the labels of `OverlayModel.panels(OverlayScene(layouts: [freshResolve(state.draft.layout)], appearance:, options:))` flattened and sorted by number, where `freshResolve` calls `LayoutMath.resolve` from scratch (this is what catches a stale preview). If `OverlayModel` is not in the tree yet, compare against `LabelModel.labels(freshResolve(...))` instead and note that in the ledger. Optional property loop: a seeded `Generator` over 50 random valid commands, failure message carries `seed=`.
4. `switchDisplayPromptsWhenDirty` (AC-133; `reduce`): clean draft plus `.switchDisplay(other, confirmed: false)` switches and re-resolves (`display`, `visibleFrame`, `scale`, `preview` all match the other Display; effects empty). Dirty draft: the state is unchanged and the effects are exactly `[.promptUnsaved(other)]`. Dirty draft with `confirmed: true` switches. Also switch to a disconnected Display that has an `Assignment` and assert stored geometry is used.
5. `assignWritesOnce` (AC-134; `reduce`): `.assign` yields exactly `[.writeAssignment(PersistentDisplayKey(uuid), draft.layout.id)]` for the edited Display, state unchanged, no `writeLayouts`. After a `.switchDisplay` the key is the new Display's. Assert the effect list has count 1.
6. `saveWritesOnceCancelWritesNothing` (AC-136; `reduce`, `DocumentStore`, `FakeFileSystem`): edit the Layout (split, setGap). `.save` yields effects `[.writeLayouts(doc), .replaceLive(layout)]` with `doc.layouts` containing the edited Layout and `layout == draft.layout`. Interpret `.writeLayouts(doc)` with `DocumentStore(fs: FakeFileSystem(), directory:, clock: FakeClock())`: `save(doc, as: .layouts)`, then `store.load(.layouts) == .loaded(doc)`; also decode the bytes read from the fake file system and compare. Assert the fake file system saw exactly one write. State after save: `dirty == false`. Invalid draft (force a ratio outside the limits by constructing the draft directly) yields `[.error(...)]` and no write effect. `.cancel` yields `[.close]` and no write effect, and a `FakeFileSystem` that receives nothing from the interpreter has zero writes.
