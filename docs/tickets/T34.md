## Goal

- The Settings window shows four working panes bound to existing models; nothing here reimplements a model.
- Layouts pane: attached Displays (name, resolution, Layout picker, "not saved" on unstable keys) and disconnected Displays (stored Assignment, "Copy Assignment to <attached>", "Forget"). Per Layout: Duplicate, Rename, Delete (a replacement Layout is required when Displays use it). Export all, or export one Layout. Import offers one Merge/Replace choice per file; Replace names the timestamped backup before writing; newer-version and validation errors show inline and change nothing.
- Shortcuts pane: one chord recorder row per action over `ShortcutRules.recorderState`, showing accepted, warning (acceptable), conflict (names the other action), rejected, and `inUse` from the registrar. Clear leaves the action unbound.
- Appearance pane: fill color and opacity with a live sample that names the Layouts following the default Margin and Gap, default Insets sliders, and the Enhanced UI policy. Exclusions pane: running-apps list and a file picker add bundle identifiers; each row shows the identifier beside the name.
- Every change goes through one `PreferencesController` that encodes with `PreferencesCodec` into UserDefaults key `zones.preferences`, so the next Drag Session reads it with no relaunch (AC-141).

## ADRs

- 0002 One root Package.swift with ZonesCore, ZonesLayout, ZonesWindowing (App target is the only code outside the packages).
- 0008 Activation modifier defaults to Shift, span modifier to Control; both user-selectable (they must differ, AC-087).
- 0010 Default shortcuts use Control+Option (Reset to defaults = `ShortcutRules.defaults`).
- 0011 Global hotkeys use Carbon RegisterEventHotKey; zero third-party dependencies (build the recorder yourself with an NSEvent key-down capture; no KeyboardShortcuts-style package).
- 0012 Displays are identified by CGDisplay UUID (unstable keys are session only, shown "not saved").
- 0015 All AX calls run on WindowActor; UI on MainActor (panes and controllers are @MainActor, Swift 6 strict concurrency).
- 0017 Layouts and assignments are JSON files in Application Support; preferences in UserDefaults; the export format is the same document with a version field.
- 0018 Automatic exclusions (amended 2026-10-24, C4): user exclusions are bundle identifiers; phase 1 skips excluded bundles from CG facts.
- 0019 Menu-bar-only app, hardened runtime, no App Sandbox (so NSOpenPanel/NSSavePanel and NSWorkspace.runningApplications work without entitlements).

## Test plan

AC-141 is manual: implement it and record "AC-141 manual, not run" in the ledger; it has no test. No property tests are required. SwiftUI rendering is not headless-testable (LESSONS), so slices 1 to 6 test the controllers and extracted flow logic; slice 7 is the smoke test. Each slice is red first, then green, then one commit.

1. `SettingsPanesSmokeTests.preferencesControllerPersists` (Preferences, PreferencesCodec): a set opacity 0.8, activationModifier .command, exclusions and a shortcut change each write a blob under `zones.preferences` that `PreferencesCodec.decode` returns equal to the controller value with no coerced fields; a fresh controller on the same suite reads the same values; an empty suite yields `Preferences.defaults`. Setting both modifiers equal is rejected or coerced as AC-087 says (use the existing rule, do not re-implement).
2. `SettingsPaneFlowTests.exportAllAndOne` (ImportExport.export): export all returns custom Layouts plus all assignments with `version == Constants.documentVersion`; export one returns only that Layout; the controller writes the document encoded by the one document codec.
3. `SettingsPaneFlowTests.importMergeReplaceSheet` (ImportExport.importDocument, ImportMode): the controller asks for a mode before applying; Merge keeps existing and renames incoming duplicates; Replace shows `backupName` before writing and the applied result is saved to both documents; cancel changes nothing; `dormant` Assignments are reported not dropped.
4. `SettingsPaneFlowTests.importErrorsInline` (DocumentError): `.newerVersion(found:supported:)` message names both numbers; `.invalidLayout(name:...)` names the first offending Layout; `.corrupt`/`.nonUUIDKey` show a message; in every refusal the current document and files are unchanged and the error clears on the next successful import.
5. `SettingsPaneFlowTests.layoutActions` (LayoutStore, LayoutsPaneModel): Duplicate adds a custom copy; Rename updates the name; Delete of a Layout in use is refused until a replacement is chosen and then reassigns (AC-115); Delete of an unused Layout needs none; Copy Assignment copies to the chosen attached Display; Forget removes the stored record; each action persists through `DocumentStore`. Picker change updates the session/persistent Assignment (`unstable` keys session only).
6. `SettingsPaneFlowTests.recorderDisplay` (ShortcutRules.recorderState, ShortcutStore.reduce): recorder output maps each `RecorderState` to the displayed message (conflict names the other action, warning needs explicit Accept, rejected is not stored); a stored chord emits `set(action, chord)`; Clear emits `set(action, nil)` and leaves the action unbound (no default restored); `failed(action, .inUse)` shows an in-use message and keeps the previous chord; Reset restores `ShortcutRules.defaults`.
7. `SettingsPanesSmokeTests.panesBuild` (all consumed models): LayoutsPane, ShortcutsPane, AppearancePane and ExclusionsPane each construct with fixture models (two attached plus one disconnected Display, a conflicting chord, followers, three exclusions) and produce a non-nil body; the Exclusions add path stores a bundle identifier and the row shows identifier and name (AC-142 behavior through the controller); the Appearance sample lists the same Layout names as `AppearancePaneModel.followers` and changes after the Margin slider changes.
