# T22: Drag reducer: Span accumulation, freeze/resume/clear, cross-Display suspend, nearest-zone drops and mouse Restore cue

Kind: build. Blocked by T16 (the reducer skeleton with idle/pressed/moving/armed and the single-Zone armed branch). Estimate 140k tokens. Protocol: none. Fake: none.

## Goal

- Extend the `armed` branch of `DragSessionReducer` with Span behaviour, all pure.
- Zones swept while the Span Modifier is down accumulate into `SpanState.zones`, drawn as `Span.rect`. Releasing the Span Modifier freezes the set, re-pressing resumes adding, releasing the Activation Modifier clears it.
- Both modifiers held before the move: the arming sample starts the Span with the Zone under the cursor (empty set over a Gap until the first Zone is entered).
- The cursor leaving the Span's Display suspends the Span (secondary style); the highlight then follows the cursor Zone and a drop there uses that Zone. Returning resumes.
- A `nearest` hit (Gap, Margin, surround) always snaps and never restores. A `none` hit (outside the visible frame) emits `updateHighlight(dimAll)` only when `ArmContext.hasOriginalFrame` is true and mouseUp emits `restore`; otherwise it clears the highlight and mouseUp emits nothing.
- Highlight must equal the mouseUp drop set (LI-009); `hideOverlay` precedes `snap`/`restore` (AC-053).

### AC-084 (auto) — Suspend across a seam

## Interface contracts

IMPLEMENTS (behaviour, not new declarations; types already exist from earlier tickets, signatures must not change):

```swift
public enum DragSessionReducer { public static func reduce(_ s: DragState, _ e: DragEvent) -> (DragState, [DragEffect]) }   // pure; no Clock, no actor
public struct SpanState: Hashable, Sendable { public var zones: Set<Int>; public var display: DisplayKey?; public var frozen: Bool; public var suspended: Bool }
public struct Highlight: Hashable, Sendable { public var display: DisplayKey?; public var primary: Set<Int>; public var secondary: Set<Int>; public var dimAll: Bool }
```

CONSUMES (do not edit; HitTest and Span live in ZonesLayout):

```swift
public enum Hit: Hashable, Sendable { case zone(Int), nearest(Int), none }   // none only outside the visible frame
public enum HitTest { public static func hit(_ point: CGPoint, in layout: ResolvedLayout) -> Hit   // nearest = min edge distance, ties to lower number (AC-080)
  public static func display(at point: CGPoint, in snapshot: TopologySnapshot) -> DisplayKey? }
public enum Span { public static func rect(_ zones: Set<Int>, in layout: ResolvedLayout) -> CGRect }   // bounding union incl. gaps (AC-081)
public struct ArmContext: Hashable, Sendable { public var topology: TopologySnapshot; public var layouts: [DisplayKey: ResolvedLayout]; public var appearance: Appearance; public var options: AccessibilityOptions; public var hasOriginalFrame: Bool }
```

State and effects the reducer uses (same file, CONTRACTS.md section 3.1):

```swift
case armed(window: WindowRef, downFrame: CGRect, flags: ModifierSet, config: ModifierConfig, context: ArmContext, display: DisplayKey?, hit: Hit, span: SpanState)
case dragged(point: CGPoint, flags: ModifierSet), mouseUp(point: CGPoint, flags: ModifierSet), flagsChanged(ModifierSet)
case showOverlay(OverlayScene), updateHighlight(Highlight), hideOverlay, reassertPanels
case snap(SnapPlan), restore(WindowRef, downFrame: CGRect), skip(SkipReason, WindowRef?), log(String)
```

Guarantees to keep: `hideOverlay` precedes `snap`/`restore` in the mouseUp step (AC-053); `showOverlay` only on entry to `armed`; `requestSample` only in `pressed`; highlight == drop set (LI-009).
`ArmContext.hasOriginalFrame` is read-only here: it gates the `none` branch (dimAll and restore). `DragEffect.restore(window, downFrame:)` is emitted on mouseUp only for a `none` hit with `hasOriginalFrame == true`.

Design rules (from the Goal and spec section 8):
- `SpanState.display` is the Display the Span was started on; `suspended` is true while the cursor Display differs from it.
- Suspended: `Highlight.primary` = the cursor Zone on the cursor Display, `Highlight.secondary` = the suspended set, and mouseUp snaps to the cursor Zone only. Span Modifier release/press while suspended must not change the stored set.
- Put pure helpers (accumulate, freeze/resume, suspend/resume, drop-set) in `SpanLogic.swift` so `DragSessionReducer.swift` stays a thin dispatcher.

## ADRs

- ADR-0006 Drag detection: mouse events drive the gesture, AX frame polling confirms a window move (reducer context only).
- ADR-0007 Snap target is the zone under the cursor; snap requires the activation modifier at drop; zones may hold many windows. No amendment.
- ADR-0008 Activation modifier defaults to Shift, span modifier to Control; both user-selectable. No amendment. Modifiers come from `ModifierConfig` fixed at mouseDown (AC-111).
- ADR-0009 Original frame is captured at first snap, restored by shortcut or by a modifier-drag that ends over no zone. Amendment 2026-10-24 (LOCKED-SPEC challenge C2): "no zone" means outside the Display's visible frame; a drag ending on a Gap, Margin or surround snaps to the nearest Zone (min edge distance, ties to lower Zone Number) and never restores. The Overlay stays up with the highlight cleared and every fill dimmed only when an Original Frame exists.

## Test plan

Write each test red, then the minimum code to make it green, one commit per slice. Build fixtures with a small helper that makes a 2x2 and a 1x3 `ResolvedLayout` and a two- or three-Display `TopologySnapshot`/`ArmContext`.

1. HitTestTests.gapAndMarginAreNearest. Points in a Gap, in the Margin and in the surround (inside the visible frame) return `.nearest(n)` with n the min-edge-distance Zone; an equidistant point returns the lower Zone Number; a point outside the visible frame returns `.none`. Exercises `HitTest.hit`. If it already passes, record that in the ledger and still commit the test.
2. DragSessionReducerTests.nearestSnaps. Armed state with `hit: .nearest(2)`, Activation Modifier down, mouseUp: effects contain `hideOverlay` then `snap`, and no `restore`, regardless of `hasOriginalFrame`. Exercises the reducer mouseUp path and `Hit`.
3. DragSessionReducerTests.noneHitDimsOnlyWithOriginalFrame. Two cases. With `hasOriginalFrame: true`: dragged to a `none` point emits `updateHighlight(Highlight(... primary: [], secondary: [], dimAll: true))`; mouseUp emits `hideOverlay` then `restore(window, downFrame:)`. With `false`: highlight is cleared (`dimAll: false`, empty sets), mouseUp emits no `snap`, `restore` or `skip`, only `hideOverlay`, and state returns to `idle`. Exercises `Highlight`, `DragEffect.restore`, `ArmContext.hasOriginalFrame`.
4. SpanTests.accumulateAndUnion. With the Span Modifier down, sweep Zones 1, 2, 3: `span.zones == {1,2,3}`, highlight primary == that set, and `Span.rect` equals the bounding rectangle including Gaps. In a 2x2, sweep 1 then 4: zones {1,4} and the rect equals the whole Layout rectangle. Re-sweeping 2 leaves the set unchanged. Exercises `SpanState`, `Span.rect`, `Highlight`.
5. SpanTests.freezeResumeClear. Release the Span Modifier (flagsChanged): `frozen == true`, set kept, moving over new Zones does not add (highlight is the frozen set plus nothing else, per spec drop-set rule); re-press: `frozen == false`, adding resumes; release the Activation Modifier: set cleared, `SpanState` empty, highlight reverts to the single cursor Zone. Exercises `flagsChanged`, `SpanState`.
6. SpanTests.bothModifiersBeforeMove. mouseDown with both modifiers held, then the armContext/arming sample: the armed state has `span.zones == {zoneUnderCursor}`; arming over a Gap yields an empty Span, then entering the first Zone adds it. Exercises `ArmContext` arming path and `SpanState`.
7. SpanTests.suspendAndResumeAcrossDisplays. Span {1,2,3} on Display A. Cursor moves to Display B over Zone 2: `span.suspended == true`, stored set unchanged, highlight `display == B`, `primary == {2}`, `secondary == {1,2,3}`. Cursor returns to A: `suspended == false`, highlight is the A set again. Suspend again and mouseUp on B: `snap` targets only B's Zone 2. Exercises `HitTest.display(at:in:)`, `SpanState.display`, `Highlight.secondary`.
8. Refactor slice (only if green): move shared logic into SpanLogic.swift, no behaviour change, all tests still green.
