# T31: Overlay panels (AppKit): one click-through NSPanel per Display, CALayer rendering, PanelOverlayPresenter

Kind: build. Blocked by: T26 (OverlayModel, PanelModel), T03 (spike verdicts SPK-002, SPK-009). Estimate: 120000 tokens. Branch: ticket/T31. Module: App/ and AppTests/ only (XcodeGen target). No new SPM code; consumes ZonesCore, ZonesLayout, ZonesWindowing.

## Goal

- `ZoneOverlayPanel` (an `NSPanel` subclass in App/) is configured exactly as ADR-0023: borderless nonactivating, level `.screenSaver`, `canJoinAllSpaces` + `fullScreenAuxiliary` + `stationary` + `ignoresCycle` (plus `canJoinAllApplications` per the research), `ignoresMouseEvents`, no shadow, clear non-opaque background, `canBecomeKey` and `canBecomeMain` false, `isAccessibilityElement` false on the panel, its view and its layers. Its frame is `screen.frame`.
- One panel exists per Display. Panels are created once, reused for every Drag Session, and only resized (`setFrame`) when `resize(to:)` receives a new `TopologySnapshot`. Never re-created per frame or per drag.
- `ZoneLayerView` is a layer-backed `NSView` that renders a `PanelModel`: one `CALayer` per Zone (fill), one label layer per Zone, one highlight layer and one secondary layer per panel. All layer mutation happens inside `CATransaction` with `setDisableActions(true)`; `contentsScale` on every standalone layer comes from the Display (`ZoneLabel.contentsScale`, fill layers from the panel's screen scale). No `draw(_:)` on the hot path, `drawsAsynchronously` stays off.
- `PanelOverlayPresenter` (`@MainActor final class`, conforms to `OverlayPresenter`) drives the panels: `show` builds models with `OverlayModel.panels` and calls `orderFrontRegardless()` once per session; `highlight` only repaints layers (never reorders); `hide`/`orderOut` call `orderOut(nil)`; `reassert` re-orders front; `resize` resizes panels.
- Manual behavior (120 Hz cost, drag uninterrupted, full-screen Space, resolution change, on-screen accessibility) has no test but must be implemented per the rules below. SwiftUI hosting (`NSHostingView`) is used only if `docs/spikes/SPK-009.md` records that SwiftUI passed; default and fallback is pure CALayer.
- Done when `OverlayPanelTests` (configuration, notAccessibilityElement, plus the slices below) is green under xcodebuild, the app target builds with strict concurrency and warnings as errors, and the hygiene rules hold.

## Interface contracts

Source: docs/CONTRACTS.md. Signatures are fixed; never rename. Any additive helper goes in the ledger. If a declaration below is already in `Sources/`, do not redeclare it (`grep -rn 'struct PanelModel' Sources`).

IMPLEMENTS: `PanelOverlayPresenter` (the production adapter of `OverlayPresenter`, section 3, line 263).
CONSUMES (declared elsewhere, do not redefine): `OverlayPresenter` (protocol), `PanelModel`, `OverlayModel`, `Highlight`, `OverlayScene`, `AccessibilityOptions`, `CoordinateSpace.panelLocal`, `ZoneDrawing`, `PanelStyle`, `ZoneLabel`, `RGBA`, `DisplayKey`, `DisplaySnapshot`, `TopologySnapshot`.

```swift
// §3 seam (the protocol PanelOverlayPresenter conforms to). Fake: FakeOverlayPresenter (@MainActor) in ZonesTestSupport.
public protocol OverlayPresenter: Sendable {   // Production: App's PanelOverlayPresenter. Fake: FakeOverlayPresenter
  @MainActor func show(_ scene: OverlayScene); @MainActor func highlight(_ h: Highlight); @MainActor func hide()
  @MainActor func reassert(); @MainActor func orderOut(); @MainActor func resize(to snapshot: TopologySnapshot) }

// §3.1 (CONSUMED)
public struct Highlight: Hashable, Sendable { public var display: DisplayKey?; public var primary: Set<Int>; public var secondary: Set<Int>; public var dimAll: Bool }
public struct OverlayScene: Hashable, Sendable { public var layouts: [ResolvedLayout]; public var appearance: Appearance; public var options: AccessibilityOptions }
public struct AccessibilityOptions: Hashable, Sendable { public var reduceTransparency: Bool; public var reduceMotion: Bool }

// §3.8 Overlay model (CONSUMED; delivered by T26)
public struct ZoneDrawing: Hashable, Sendable { public var number: Int; public var rect: CGRect; public var fill: RGBA; public var label: ZoneLabel }
public struct PanelStyle: Hashable, Sendable { public var idle: RGBA; public var highlight: RGBA; public var secondary: RGBA; public var dim: RGBA; public var animationDuration: Double? }
public struct PanelModel: Hashable, Sendable { public var display: DisplayKey; public var frame: CGRect; public var zones: [ZoneDrawing]; public var style: PanelStyle; public var spanOutline: Bool }
public enum OverlayModel { public static func panels(_ s: OverlayScene) -> [PanelModel]   // rects inside visibleFrame, panel = full frame (AC-059); highlight distinct at 0.10 (AC-042)
  public static func apply(_ h: Highlight, to panels: [PanelModel]) -> [PanelModel] }

// §1.1 (CONSUMED; the ONE coordinate conversion)
public enum CoordinateSpace { public static func panelLocal(_ appKit: CGRect, panelFrame: CGRect) -> CGRect }

// §2 (CONSUMED, for context)
public struct ZoneLabel: Hashable, Sendable { public var number: Int; public var text: String; public var frame: CGRect; public var outline: RGBA; public var contentsScale: Double; public var noChord: Bool }
```
Conventions that matter here: every `CGRect` in the models is in AppKit global coordinates (origin bottom-left of the primary display). Convert to layer geometry only through `CoordinateSpace.panelLocal(rect, panelFrame: model.frame)`; a layer-backed non-flipped `NSView` shares that bottom-left origin. `DisplaySnapshot.scale` is the Display's backing scale; `DisplaySnapshot.frame` is `screen.frame`.

## Behavior rules for the implementation

- Panel recipe (research "Implications" item 1): `styleMask [.borderless, .nonactivatingPanel]`, `backing .buffered`, `defer false`, `level .screenSaver` (never a hard-coded number, never `+1`), `collectionBehavior [.canJoinAllSpaces, .canJoinAllApplications, .fullScreenAuxiliary, .stationary, .ignoresCycle]`, `isFloatingPanel true`, `hidesOnDeactivate false`, `becomesKeyOnlyIfNeeded true`, `ignoresMouseEvents true`, `isOpaque false`, `backgroundColor .clear`, `hasShadow false`, `animationBehavior .none`, `isReleasedWhenClosed false`. If SPK-002 shows `.canJoinAllApplications` breaks anything, drop it; the AC only requires the four named behaviors.
- Never call `makeKey*`, `NSApp.activate`, `orderFront(_:)` or `makeMain`. Show with `orderFrontRegardless()` exactly once per session (`show`), hide with `orderOut(nil)`. `highlight(_:)` must never touch window order.
- Semantics: `show(scene)` ends any previous session state, builds models, creates missing panels (once), applies models, orders each front, marks the session started. `highlight(h)` computes `OverlayModel.apply(h, to: baseModels)` and diffs into layers; a no-op if no session. `hide()` and `orderOut()` both order every panel out and keep them for reuse; `hide()` also clears the session and the highlight. `reassert()` re-orders the panels front only while a session is active. `resize(to:)` calls `setFrame(frame, display: false)` on the panel whose `DisplayKey` persists, creates a panel for a new Display, and orders out and drops the panel of a removed Display; if a session is active it re-applies the models with the new geometry (AC-061). Record any semantic choice you make in the ledger.
- Layers: per Zone one fill `CALayer` and one `CATextLayer` label (text = `ZoneLabel.text`, outline from `ZoneLabel.outline`, `contentsScale = ZoneLabel.contentsScale`, `isAccessibilityElement` false); per panel one highlight layer and one secondary layer whose frame is the union of the primary / secondary Zone rects. When `spanOutline` is true the secondary layer draws as a border with no fill. Fill colors come from `ZoneDrawing.fill` and `PanelStyle`; do not recompute colors or contrast here, that is T26's job.
- Updates: every mutation inside `CATransaction.begin(); CATransaction.setDisableActions(true); ...; CATransaction.commit()`. Reuse layers across updates (same instances for the same Zone number); only touch layers whose value changed. If `PanelStyle.animationDuration` is non-nil, a short explicit `CABasicAnimation` on the highlight layer's opacity is allowed; if nil, nothing animates (Reduce Motion).
- Accessibility: panel, content view and every layer `isAccessibilityElement` false; no accessibility labels; no `NSHostingView` unless SPK-009.md says SwiftUI passed (then SwiftUI content gets `.accessibilityHidden(true)` and layers stay the hot path).
- Hygiene: no `try!`, `as!`, `fatalError(` (unless the line carries `zones:allow`), no `import ApplicationServices`, no `CGWindowList*`, no `@unchecked Sendable`. Keep these types `@MainActor`.

## Test plan

Red-green slices in order. Each slice: write the failing test, make it pass, commit, append a ledger line. Tests live in AppTests/OverlayPanelTests.swift, `@MainActor`, Swift Testing; build panels with a fixed `CGRect` (no real `NSScreen` dependency; pass the frame and scale in).

1. `OverlayPanelTests.configuration` (AC-043). Build a `ZoneOverlayPanel` for a 1440x900 frame. Assert `ignoresMouseEvents`, `!canBecomeKey`, `!canBecomeMain`, `level == .screenSaver`, `!hasShadow`, `backgroundColor == .clear` and `!isOpaque`, `collectionBehavior` contains `canJoinAllSpaces`, `fullScreenAuxiliary`, `stationary`, `ignoresCycle`, `styleMask` contains `nonactivatingPanel` and `borderless`, `frame == screen frame`. Exercises ZoneOverlayPanel.
2. `OverlayPanelTests.notAccessibilityElement` (AC-058). After applying a 3-Zone `PanelModel`, assert `panel.isAccessibilityElement() == false`, `contentView.isAccessibilityElement() == false`, `contentView.accessibilityChildren()` is nil or empty, and for every sublayer in the layer tree that exposes accessibility state it reports not an element (if `CALayer` does not expose `isAccessibilityElement` on this SDK, assert the view reports no AX children and write that in the ledger). Exercises ZoneOverlayPanel and ZoneLayerView.
3. `OverlayPanelTests.layersMatchModel`. Apply a `PanelModel` with N Zones; assert N fill layers and N label layers, one highlight and one secondary layer, frames equal `CoordinateSpace.panelLocal(zone.rect, panelFrame: model.frame)`, label `contentsScale` equals `ZoneLabel.contentsScale`. Exercises ZoneLayerView, PanelModel, CoordinateSpace.panelLocal.
4. `OverlayPanelTests.layersReusedAcrossUpdates`. Apply, hold layer references, apply a second model with a different highlight; assert the same layer instances and no extra sublayers. Exercises ZoneLayerView.
5. `OverlayPanelTests.updatesDoNotAnimate`. After a model update that moves the highlight frame and opacity, assert `highlightLayer.animationKeys()` is nil or empty and the presentation values equal the model values immediately (actions disabled). With `animationDuration == nil` assert still nothing animates. Exercises ZoneLayerView, PanelStyle.
6. `OverlayPanelTests.spanOutlineRendersAsBorder`. `spanOutline == true` gives the secondary layer a border and clear fill; false gives a fill and no border. Exercises ZoneLayerView, PanelModel.spanOutline.
7. `OverlayPanelTests.presenterOrdersFrontOncePerSession`. Use a `PanelOverlayPresenter` with a test screen provider (injected closure returning panel frames/scales from a `TopologySnapshot`, so no real screens). `show` once then several `highlight` calls: each panel's `orderFrontCount == 1`; `hide` then `show` again: count 2. Exercises PanelOverlayPresenter, OverlayPresenter.
8. `OverlayPanelTests.presenterReusesPanels`. Two sessions return the identical `ZoneOverlayPanel` instances (`===`). `hide`/`orderOut` leave `isVisible == false` and keep the panels. `highlight` with no session is a no-op. Exercises PanelOverlayPresenter.
9. `OverlayPanelTests.resizeOnTopologyChange`. `resize(to:)` with a changed frame resizes the same panel instance (`===`) to the new `frame`; a removed Display drops its panel and orders it out; an added Display gets a new panel; during an active session the layers are re-applied to the new geometry (AC-061 logic half). Exercises PanelOverlayPresenter, TopologySnapshot.
