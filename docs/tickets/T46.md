# T46: QA fix: size-locked windows get a position-only Snap on mouse and keyboard paths (AC-144, ADR-0018 C4)

Kind: fix (QA round 1). Blocked by T45, T21, T28 (all done). Estimate 80k tokens. Area: Sources/ZonesWindowing/Drag, Shortcuts. Protocol: DragState, DragSessionReducer, ShortcutResolver (edit). Fake: FakeWindowSystem.

## Goal

- Carry the `SnapMode` returned by `ExclusionPolicy.phaseTwo` (`.allow(.positionOnly)`) from the moved sample into `moving` and `armed` (a new associated value `mode: SnapMode`, default `.full`), and use it in the mouseUp `SnapPlan` instead of the literal `.full`.
- Keyboard path: `ShortcutResolver.plan` applies `ExclusionPolicy.phaseTwo(focused.facts)` (or maps `!facts.sizeSettable` to `.positionOnly`) before building the plan; `WindowWorker` passes the facts it already reads.
- `FrameWriter` with `.positionOnly` issues no `setSize` (T15 behavior; confirm with the fake's call log).
- Update every `.moving(`/`.armed(` construction and pattern (DragSessionReducer, SpanLogic, CandidateResolution, tests, App/Composition if it matches on them) and CONTRACTS.md section 3.1 for the new field.

## QA findings this ticket closes (verbatim evidence)

#### QA-1.10: Size-locked windows never get the position-only Snap: phaseTwo's allow(.positionOnly) is discarded and a size write is issued
- Where: `Sources/ZonesWindowing/Drag/DragSessionReducer.swift:189`
- Evidence: DragSessionReducer.swift:80-83 runs ExclusionPolicy.phaseTwo(facts) but only tests for .skip; the .allow(mode) payload is dropped (comment at :42 and :80 admits 'the mode has no carrier in moving/armed'). :189 builds the SnapPlan with the literal `mode: .full`. Keyboard path: WindowWorker.swift:168-171 passes only the phaseOne verdict (always .allow(.full), ExclusionPolicy.swift:26) to ShortcutResolver.plan, and ShortcutResolver.swift:36-50 never calls phaseTwo nor checks facts.sizeSettable, so `mode` is .full there too. FrameWriter.swift:96-98 then appends `system.setSize` twice for mode == .full. ADR-0018 C4 (LOCKED-SPEC.md:991) and T15.md:12 require 'no size write' for sizeNotSettable windows; AC-143 says sizeNotSettable returns allow(positionOnly) and AC-144 says Calculator snaps position-only. T21 ledger line 7 records this as GAP; still true on integration (grep of `positionOnly` in Sources shows no carrier outside ExclusionPolicy and SnapService.realign). Live Calculator run impossible here (Accessibility revoked).
- Repro: 1) sed -n '78,84p;186,190p' Sources/ZonesWindowing/Drag/DragSessionReducer.swift — phaseTwo verdict payload unused, SnapPlan mode hardcoded .full. 2) sed -n '94,98p' Sources/ZonesWindowing/Snap/FrameWriter.swift — setSize issued when mode == .full. 3) Scratch @Suite in Tests/ZonesWindowingTests: drive DragSessionReducer from idle through mouseDown/dragged/frameSample with winner.facts = WindowFacts(subrole: .standard, isFullScreen: false, positionSettable: true, sizeSettable: false), arm, mouseUp over a Zone; assert the .snap effect's plan.mode == .positionOnly -> fails (.full).
- Fix hint (verifiers agreed 3/3): Carry the SnapMode from phaseTwo in the moving/armed states (or in ArmContext) and use it at :189; in ShortcutResolver, apply phaseTwo(focused.facts) (or map !facts.sizeSettable to .positionOnly) before building the plan.
