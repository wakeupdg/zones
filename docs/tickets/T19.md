# T19: Enhanced UI policy and crash recovery record

Kind: build. Blocked by: T15 (FrameWriter, SnapService, AppHealth; T15 left the Enhanced UI hooks as stubs). Estimate: 100k tokens. Branch: ticket/T19.
Protocol: none (extends FrameWriter). Fakes consumed: FakeWindowSystem, FakeFileSystem (ZonesTestSupport). Tests: SnapServiceTests.enhancedUIRestoredOnEveryPath, EnhancedUIRecoveryTests.writeOnceRestoreOnMatch.

## Goal
- `FrameWriter` reads Enhanced UI first. It skips the off/on pair when the attribute is absent (`nil`) or already off, or when `EnhancedUIPolicy.leave` is set.
- Otherwise it sets Enhanced UI off before the first size write and restores the prior value in a `defer` on every path: applied, clamped, refused, elementGone, and the timedOut abort.
- `EnhancedUIRecovery` writes one `RecoveryRecord` per (bundleID, pid, launchDate) per session, after the first completed write sequence, so the hot path never waits on disk.
- At launch it restores only entries matching all three fields with `priorEnhancedUI == true`. It deletes the file on clean quit, and `drainAndDelete()` serves Quit and permission revocation.

## Design decisions (settled; do not reopen)
- Order inside `FrameWriter.write`: (1) cooldown gate stays first, with zero AX calls and no Enhanced UI read. (2) If policy is `.toggle`: `enhancedUI(pid:)`; `.value(true)` means toggle needed; `.value(false)`, `.value(nil)` or any failed read means skip. (3) If toggling: `setEnhancedUI(false, pid:)` once, before the first size write; ignore its status. (4) Run the write sequence unchanged. (5) A `defer` calls `setEnhancedUI(true, pid:)` only if step 3 ran; it must also run on the timedOut abort and on early returns. (6) After the defer's restore, outside the hot path, call `recovery.noteIfFirst` (see below).
- Policy `.leave` makes zero Enhanced UI calls (no read, no set), so the fake log shows none.
- The restore always writes `true` (the only value that triggers it is a prior `true`). Do not retry a failed restore.
- Record rule: after a write sequence that ended in `applied` or `clamped` (a completed sequence), when policy is `.toggle` and the read returned a value (`true` or `false`, not absent and not failed), `identify(pid)` is non-nil: `noteIfFirst(RecoveryRecord(bundleID:, pid:, launchDate:, priorEnhancedUI: <the value read>))`. No record on refused, timedOut, elementGone, noOp, `.leave` or absent attribute. A skipped-because-off app is still recorded with `false`.
- `noteIfFirst`: key = (bundleID, pid, launchDate). If the key is already in the session set, return and write nothing. Otherwise insert it, append the record to the in-memory array, and write the whole array through `store.saveRaw` (synchronous, atomic). A write error is swallowed (never throws into the Snap path).
- `restoreAtLaunch(running:)`: load the file; decode (corrupt or missing file gives `[]`); return the records for which an entry in `running` has the same bundleID, pid and launchDate (exact `Date ==`) AND `priorEnhancedUI == true`, in file order; then delete the file (stale entries are dropped). It performs no AX call; the caller sets Enhanced UI back on the returned pids. It does not touch the session noted set.
- `drainAndDelete()`: removes the file, clears the in-memory records array, keeps the noted set (nothing in-flight remains because every restore is synchronous in the `defer`). Idempotent; used for clean Quit and for revocation.
- No `@unchecked Sendable`. No `import ApplicationServices` (AC-162); `NSRunningApplication` needs `import AppKit` in the FrameWriter default only.
