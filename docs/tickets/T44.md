## QA findings this ticket closes (verbatim evidence)

#### QA-1.5: CI masks swift test and xcodebuild failures: `| tail -80` makes both gate steps exit 0 even when tests fail
- Where: `.github/workflows/ci.yml:17`
- Evidence: `.github/workflows/ci.yml:17` is `run: swift test 2>&1 | tail -80` and `:26` is `xcodebuild -quiet ... build 2>&1 | tail -80`. Neither step sets `shell: bash` nor `set -o pipefail`, so GitHub runs them with its default `bash -e {0}`, where a pipeline's status is the last command's (tail -> 0). Reproduced the shell semantics locally: `bash -e -c 'false | tail -1; echo "chain exit=$?"'` printed `chain exit=0` while `bash -e -c 'exit 3'` returned 3. A failing `swift test` or a failed Debug app build therefore yields a green CI job; only the hygiene-gate step (run directly, line 19) can actually fail the workflow. AC-160/US-137 exist so that regressions surface in CI before merge; this workflow cannot do that for the two steps it was written for.
- Repro: 1. On a ticket branch, break one test (or introduce a compile error in Sources/). 2. Push; the `Package tests` step prints the failure in its log but the step and the job are reported successful. Local equivalent: `bash -e -c 'false | tail -80; echo exit=$?'` -> `exit=0`.
- Fix hint (verifiers agreed 3/3): Add `defaults: run: shell: bash` at the job level (GitHub's explicit bash shell is `bash --noprofile --norc -eo pipefail {0}`), or prefix each piped step with `set -o pipefail`, or drop the `| tail -80` and use `swift test 2>&1 | tail -80; exit ${PIPESTATUS[0]}`.

#### QA-1.3: AC-146 Verify filter DocumentTests.mergeAndReplace runs 0 tests (test lives in ImportExportTests)
- Where: `Tests/ZonesLayoutTests/ImportExportTests.swift:52`
- Evidence: scripts/q.sh swift test --filter DocumentTests.mergeAndReplace -> 'warning: No matching test cases were run', 'Test run with 0 tests in 0 suites passed', exit=0. The test exists at Tests/ZonesLayoutTests/ImportExportTests.swift:52 (func mergeAndReplace in suite ImportExportTests); '--filter ImportExportTests.mergeAndReplace' runs 1 test and passes. Behavior is covered, but the locked Verify command as written is a silent no-op.
- Repro: cd repo; scripts/q.sh swift test --filter DocumentTests.mergeAndReplace  (see 0 tests ran, exit=0)
- Fix hint (verifiers agreed 2/3): Move mergeAndReplace into a DocumentTests suite, or correct the AC-146 Verify filter to ImportExportTests.mergeAndReplace.

#### QA-1.4: AC-161 Verify 'grep -c SWIFT_STRICT_CONCURRENCY: complete project.yml' prints 2, spec says 1 (same for TREAT_WARNINGS_AS_ERRORS)
