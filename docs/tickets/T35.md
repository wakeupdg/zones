# T35: Layout editor window: translucent backdrop at real scale, keyboard commands, Assign, Save and Close

Kind: build. Blocked by: T30, T32. Estimate: 120k tokens. Branch: ticket/T35. Module: App/Editor (XcodeGen app target) plus AppTests. Protocol: none. Fake: none.

## Goal

- A resizable `NSWindow` opens defaulting to `WindowPlacement.editorFrame(cursor:)` (the cursor Display's visible frame), non-opaque with a translucent backdrop so desktop windows stay visible behind it (AC-126).
- It draws the draft's Zones from `EditorState.preview` at real scale (1 view point = 1 screen point) with `LabelModel.labels` numbers, a selection highlight, and divider drag (snaps; Option = free drag). Zone 1 edges equal the Overlay's for the same draft because both come from `LayoutMath.resolve`; the editor never recomputes geometry.
- Key equivalents map to `EditorEvent`s: H split horizontal (side by side), V split vertical (stacked), M merge, arrows nudge 1 pt, Shift-arrows 10 pt, Command-Z undo, Shift-Command-Z redo, Command-S save, Command-W cancel/close, Command-Shift-A assign (window key equivalent, AC-139).
- Toolbar has a Display switcher (connected and disconnected Displays; unsaved draft shows the prompt, then re-sends `switchDisplay(_, confirmed: true)`), a Template picker (Template + count), and Margin and Gap sliders.
- Every `EditorEffect` is routed: `writeLayouts` to `DocumentStore.save(_, as: .layouts)`, `writeAssignment` to the assignments document, `replaceLive` to the live `LayoutStore.upsert`, `promptUnsaved` to a sheet, `error` to an inline message, `close` to closing the window. Save is the only moment the live Layout changes.

## Acceptance

### AC-126 (manual) — Editor backdrop
Statement: Control+Option+E opens the editor over a translucent backdrop through which the desktop windows behind it remain visible, drawing the Zones at real scale so that each editor Zone covers the same screen area the Overlay would highlight for it (frame rule: AC-022).
Covers: US-104
Verify: Open the editor over a desk with three visible windows; confirm all three show through the backdrop; Shift-drag a window with the editor still open and compare the Overlay's Zone 1 edges to the editor's Zone 1 edges in a screenshot (equal).

### AC-139 (manual) — Keyboard-only editor loop
Statement: From a fresh Layout with its single Zone selected, the keystrokes H, H, Command-S, Command-Shift-A, Command-W produce a three-column Layout (three Zones side by side, per AC-127) saved and assigned to the current Display without touching the mouse.
Covers: US-105, US-114, US-112
Verify: Perform the keystrokes; Shift-drag a window to confirm the Overlay shows three side-by-side Zones on that Display, and the Layouts pane shows the new Layout assigned to it.

## ADRs

- ADR-0001 Stack and platform: Swift 6.2 strict concurrency, macOS 14+, SwiftUI is allowed for the editor chrome, overlays are AppKit; no private APIs.
- ADR-0002 One root Package.swift with ZonesCore, ZonesLayout, ZonesWindowing: App/ imports these; do not add targets.
- ADR-0003 A layout is a binary split tree; zones are its leaves. Amendment 2026-10-24 (C1): the tree tiles the Layout rectangle (visible frame minus surround, Margin, Gap), not the whole Display.
- ADR-0010 Default shortcuts: Control+Option+E opens the editor (hotkey wiring is T30/T32, not this ticket).
- ADR-0012 Displays are identified by CGDisplay UUID: the switcher lists `DisplayKey`s; disconnected ones come from Assignment records.
- ADR-0015 AX calls on WindowActor; UI on MainActor: all editor code is `@MainActor`, no AX calls.
- ADR-0017 Layouts and assignments are JSON files in Application Support: persist only via `DocumentStore`.
- ADR-0019 Menu-bar-only app (LSUIElement), no sandbox: the app is an accessory, so activate the app and make the editor key explicitly when it opens.
- ADR-0023 Overlay is a click-through NSPanel at screenSaver level, never key: the editor is an ordinary key-capable `NSWindow`, NOT that panel; do not reuse its configuration.

## Test plan

`swift test` cannot drive AppKit (LESSONS), so put all logic in pure helpers inside App/Editor and test them in AppTests via xcodebuild. One red-green slice per commit, in order:

1. `EditorWindowTests.defaultFrameEqualsVisibleFrame`: for a `DisplaySnapshot` with a menu-bar-inset `visibleFrame`, the controller's initial frame equals `WindowPlacement.editorFrame(cursor:)` and the window's style mask contains `.resizable`. Exercises WindowPlacement.
2. `EditorWindowTests.keyEquivalentsMapToEvents`: table test of `EditorKeyMap`: H -> `.command(.split(.horizontal))`, V -> `.command(.split(.vertical))`, M -> `.command(.merge)`, Command-Z -> `.undo`, Shift-Command-Z -> `.redo`, Command-S -> `.save`, Command-W -> `.cancel`, Command-Shift-A -> `.assign`; unmapped keys and Command-H/V/M return nil (Command combos must not fire the bare-letter commands). Exercises EditorEvent/EditorCommand.
3. `EditorWindowTests.arrowKeysNudgeSelectedDivider`: Left/Up = -1, Right/Down = +1 point; Shift = 10; targets `nudge(selectionPath, points:)`; with no selection the map returns nil (no event). Document the sign convention in a comment. Exercises EditorCommand.nudge.
4. `EditorWindowTests.effectsRouteToStores`: a fake sink plus the real `DocumentStore` on an in-memory `FileSystem` fake (grep for the existing one): `writeLayouts` saves `.layouts`, `writeAssignment` saves `.assignments`, `replaceLive` calls `LayoutStore.upsert`, `close` closes, `promptUnsaved` shows the prompt, `error` surfaces the message. Drive it with `EditorModel.reduce` for save and assign on a dirty draft so the real effect lists are used. Exercises EditorEffect, DocumentStore, LayoutStore.
5. `EditorWindowTests.zoneRectsEqualResolvedFrames`: pure `EditorCanvasGeometry.zoneRects(preview:, contentOrigin:)` returns, for every zone, the `ResolvedLayout` zone frame shifted only by the window content origin (so at origin = visible frame origin they are equal, and Zone 1 edges equal `LayoutMath.resolve` for the same draft). Include a draft with Margin, Gap and Focus surround. Exercises LayoutMath.resolve via EditorState.preview.
6. `EditorWindowTests.dividerDragProducesSetRatio`: `EditorCanvasGeometry.event(forDragOf:to:optionHeld:)` yields `.command(.setRatio(path, ratio, snap: true))`, and `snap: false` when Option is held; ratio is the pointer's fraction of the parent's extent. Exercises EditorCommand.setRatio.
7. `EditorWindowTests.displaySwitcherListsDisconnectedAndPrompts`: pure `EditorToolbarModel.displayChoices(topology:, assignments:)` lists connected Displays first, then disconnected ones from Assignment records (`displayName`); picking one on a dirty draft yields `promptUnsaved`, and confirming sends `.switchDisplay(key, confirmed: true)`. Exercises Assignment data and EditorEvent.switchDisplay.
8. `EditorWindowTests.slidersAndTemplatePickerSendCommands`: slider values map to `.setMargin` / `.setGap` (clamp to the ranges the reducer accepts; read `EditorEngine` bounds); picker maps to `.template(t, count:)`. Exercises EditorCommand.

No property tests (the AC list requires none). AC-126 and AC-139 are manual: implement them, write no test for them, and add one ledger line per manual AC saying "manual, implemented, not yet eyeballed". Canvas drawing, backdrop alpha and focus behaviour are glue and are verified by the manual ACs plus the build.

Implementation notes:
- Backdrop: `isOpaque = false`, `backgroundColor` a low-alpha black (about 0.25), no `NSVisualEffectView` blur (blur hides the windows behind). Zones are drawn in the canvas view, which fills the content view.
- Real scale: map `preview` frames into view coordinates by subtracting the window content rect origin; check whether `ResolvedLayout` uses top-left or bottom-left screen coordinates and convert exactly as the Overlay does (grep the Overlay code from T30/T32 for the flip). Resizing or moving the window must not move the Zones on screen.
- The accessory app must call `NSApp.activate()` and `makeKeyAndOrderFront` so typing reaches the editor (ADR-0019).
- Command-W and Command-Shift-A are window key equivalents; handle them in `performKeyEquivalent` so they work while a toolbar control has focus.
- Do not duplicate reducer rules (min 1/12 ratio, merge sibling rule, snap, Zone 10+ "no chord" badge): the reducer and `LabelModel` own them; the view only shows `warnings` and `EditorError` text.
