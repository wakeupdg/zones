# T28: Shortcut resolver and cycle: send to Zone N, cycle table, command gates

Kind: build. Blocked by: T17 (LayoutStore, AssignmentLookup), T24 (OriginalFrameRegistry, RestorePlanner). Estimate: 120000 tokens. Branch: ticket/T28. Module: ZonesWindowing only (new folder Sources/ZonesWindowing/Shortcuts/). Pure functions. No AppKit, no App/ changes, no protocol work.

## Goal

- `ShortcutResolver.plan` turns one window-action press (`sendToZone(n)`, `cycleRight`, `cycleLeft`, `restore`) into a `CommandPlan` for the focused window. The target Display is the one the window overlaps most (`CoordinateSpace.display(for:in:)`), and the Zones come from that Display's resolved Layout (its Assignment) in `layouts`.
- A Snap plan is a `SnapPlan` with `via: .keyboard` and `originalFrame` = the pre-write read-back (`FocusedWindow.frame`); the resolver never mutates the registry (the caller captures from the plan).
- `sendToZone(n)` with n beyond the Zone count gives `noOp(.zoneAbsent)`. A focused window that is absent, excluded, full-screen or position-not-settable gives `noOp(reason)` with exactly one log line and no write.
- `CycleResolver.base` uses the last-Snap record when its frame matches the read-back within 2 pt (`Constants.cycleTolerance`), so a Span continues after its highest member (Right) or before its lowest (Left) and a clamped window (Calculator at Zone 3) still cycles to 4. Otherwise it picks the Zone of maximum intersection (ties to the lower number); with no intersection Right starts at Zone 1 and Left at the last Zone. Both directions wrap.

## Behavior to implement (decisions this brief fixes; do not re-litigate)

Gate order in `ShortcutResolver.plan` (first hit wins; each hit emits exactly one `LogEvent`, category `.shortcuts`, no window title, `bundleID`/`pid` allowed; the plan makes no write and never touches the registry):
1. `focused == nil` -> `noOp(.windowAbsent)`.
2. `verdict` is `.skip(r)`: `.fullScreen` -> `.fullScreen`; `.positionNotSettable` -> `.positionNotSettable`; every other `SkipReason` (ownProcess, systemAgent, excludedBundle, unresponsive, ambiguousMatch, nonStandardSubrole, sheetOrPopover, systemDialog) -> `.excluded`. For these use `Log.skip(r, focused.record.ref, category: .shortcuts)` as the one event.
3. Belt and braces on facts: `focused.facts.isFullScreen` -> `.fullScreen`; `!focused.facts.positionSettable` -> `.positionNotSettable`.
4. Non-window actions (`openEditor`, `openSettings`) are never routed here (the dispatcher handles them); return `noOp(.windowAbsent)` with no log, add a one-line comment, and note it in the ledger.

Then per action. Display = `CoordinateSpace.display(for: focused.frame, in: topology)`; layout = `layouts[display.key]`. A nil display or a missing layout means there are no Zones: `noOp(.zoneAbsent)` plus one log line.
- `sendToZone(n)`: n < 1 or n > `layout.zones.count` -> `noOp(.zoneAbsent)`, one log line (message names the action and count, not the title). Else `.snap(SnapPlan(window: record.ref, display: layout.display, zones: [n], target: layout.zones[n-1].frame, mode: <the SnapMode inside .allow(mode)>, via: .keyboard, originalFrame: focused.frame))`.
- `cycleRight` / `cycleLeft`: `base = CycleResolver.base(registry.lastSnap(key), frame: focused.frame, layout: layout)`; `span = CycleResolver.matchedRecord(...)?.zones` when it has 2 or more members, else nil; `n = CycleResolver.next(from: base, direction:, count: layout.zones.count, span: span)`; then the same SnapPlan as send-to-Zone with zones `[n]`. The `WindowKey` comes from the window's registry key: derive it exactly as T24 and `FocusedWindow` do (`WindowKey(pid: ref.pid, elementHash: ...)` from the handle); read T24's sources for the helper and do not invent a new hashing scheme.
- `restore`: `registry.entry(key)` nil -> `noOp(.noEntry)` + one log line; else `RestorePlanner.plan(entry, window: ref, facts: facts, topology:)`: `.failure(r)` -> `noOp(r)` + one log line; `.success(t)` -> `.restore(entry, target: t)`. (Restore is a window command, so AC-108 gates apply to it.)

`CycleResolver` rules:
- `matchedRecord(_ last:, frame:, layout:) -> LastSnapRecord?` (additive public helper, used by `base` and by `ShortcutResolver`): non-nil only when `last.display == layout.display`, every zone in `last.zones` is in `1...layout.zones.count`, and all four of `minX, minY, width, height` differ by at most `Constants.cycleTolerance` (2.0, inclusive) between `last.frame` and `frame`. The record frame is the Snap read-back, so a clamped window (Calculator) still matches.
- `base`: matched record -> `last.zones.min()` for a single Zone, and for a Span the lowest member (`next` uses `span` to pick the correct end, so `base` for a Span only needs to be a member). No match -> the Zone with the largest intersection area with `frame` (iterate ascending, replace only on strictly greater area beyond 1e-6, so ties go to the lower number). Zero area for every Zone -> `nil`.
- `next(from:direction:count:span:)`: `span` non-nil (2+ members): Right = `span.max()! + 1`, Left = `span.min()! - 1`, wrapped into `1...count`. `span` nil: Right = `base % count + 1`, Left = `(base - 2 + count) % count + 1`. `base == nil`: Right = 1, Left = `count`. `count >= 1` always; with count 1 the answer is 1.

Test seams: pass `ResolvedLayout` values built with `LayoutMath.resolve(layout, key:, visibleFrame:, scale:)` from `Templates` built-ins (e.g. `builtin:columns:3`, `builtin:grid:4`), not hand-built frames, so Zone frames are real grid-rounded rectangles. The log assertions install an `ArrayLogSink` on `Log.shared`: mark those suites `.serialized` and uninstall/reset in teardown because `Log.shared` is global.
