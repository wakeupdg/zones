## QA findings this ticket closes (verbatim evidence)

#### QA-2.4: Editor error messages (e.g. M on a single-Zone Layout) are not announced to VoiceOver; only AXValueChanged fires on an unfocused static text
- Where: `App/Editor/EditorToolbar.swift:163`
- Evidence: `func show(message: String) { messageLabel.stringValue = message }`. Nothing in App/ calls `NSAccessibility.post(... .announcementRequested ...)` (grep -rn 'accessibility' App finds no post). AXObserver on the app element (QaA11yR2.editorAnnouncement, run4.log): a control `NSAccessibility.post(.announcementRequested)` is observed as `AXR2-NOTE AXAnnouncementRequested`. Sending `.command(.merge)` to a fresh one-Zone editor produced only `AXR2-NOTE AXValueChanged` (x2). The label then reads 'The whole Layout is one Zone; there is nothing to …' (run3.log editorAfterMerge). VoiceOver does not speak value changes of an unfocused static text, so a keyboard-only VoiceOver user who presses M, or tries an invalid split, hears nothing.
- Repro: Run `-only-testing:AppTests/QaA11yR2/editorAnnouncement()` and grep AXR2-NOTE. Live: open the editor with VoiceOver on, press M on a fresh Layout: the red message appears silently.
- Fix hint (verifiers kept it 2/3): In show(message:), when the message is non-empty, post `NSAccessibility.post(element: messageLabel, notification: .announcementRequested, userInfo: [.announcement: message, .priority: NSAccessibilityPriorityLevel.high.rawValue])`.
