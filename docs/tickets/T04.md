# T04: Spike: listen-only tap with Accessibility only; CGWindowList with Screen Recording denied (SPK-003, SPK-017)

Kind: spike. Blocked by: T01 (root Package.swift, scripts, ZonesCore types). Estimate: 80k tokens.
A spike writes a throwaway probe and two verdict notes. No production code, no protocol, no fake, no automated tests.

## Goal

- Build `Spikes/TapProbe`, a standalone SwiftPM executable (its own Package.swift, outside the root package) that creates a `.listenOnly` session tap at `.tailAppendEventTap` for left mouse down, dragged, up and flagsChanged, with only Accessibility granted.
- The probe logs every event delivered plus callback latency, at 120 Hz drag rate, so a human can run it on macOS 14, 15 and the current release.
- The same probe reads `CGWindowListCopyWindowInfo` with Screen Recording denied and confirms bounds, layer and pid are present, window names are nil, and that pid plus frame resolves the dragged window.
- Verdicts go in `docs/spikes/SPK-003.md` and `docs/spikes/SPK-017.md` (pass, fail or pending per OS, with the raw run log).
- A SPK-003 failure must be escalated as an ADR-0020 revisit (state this in the verdict file and in your return value).
- The verdict fixes the expectations of AC-003, AC-065, AC-066 and unblocks T23 (EventTapInputSource) and T14 (CGWindowEnumerator).
- You can only run on the host OS you are on. Clean-OS rows you cannot run are recorded `PENDING-HUMAN` with exact run steps. Never invent a result.

## ADRs

- ADR-0006 Drag detection: mouse events drive the gesture, AX frame polling confirms a window move. Window under pointer comes from the public CGEvent field on mouse-down, CGWindowList hit test as fallback.
- ADR-0020 Accessibility is the only TCC permission Zones asks for. Listen-only tap needs only Accessibility; window matching uses pid plus frame, never titles. A SPK-003 fail revisits this ADR.
- ADR-0001 Stack and platform: Swift 6.2, SwiftUI + AppKit panels, Accessibility API, macOS 14+, no private APIs. The probe uses public API only (Swift 6 strict concurrency).
- ADR-0021 (amended 2026-10-24, challenge C5): polling AXIsProcessTrusted cannot detect revocation of a running process. Out of scope here (SPK-006); do not test revocation.
- No amendment line in ADR-0006 or ADR-0020 applies to this ticket.

Probe design (keep it under about 250 lines):
1. Preflight: print `AXIsProcessTrusted()`. Do NOT call `AXIsProcessTrustedWithOptions` with a prompt, and never call any Screen Recording or Input Monitoring API (`CGPreflight*`, `CGRequest*`, `IOHID*`). The probe itself must satisfy AC-003.
2. Tap: `CGEvent.tapCreate(tap: .cgSessionEventTap, place: .tailAppendEventTap, options: .listenOnly, eventsOfInterest: mask of leftMouseDown, leftMouseDragged, leftMouseUp, flagsChanged, callback:, userInfo:)`. Print whether it returned nil. Run its run-loop source on a dedicated `.userInteractive` thread. Callback does O(1) work: copy location, flags, timestamp, the window-under-pointer field (`CGEventField.mouseEventWindowUnderMousePointer`), enqueue to a lock-protected buffer, return. Keep strong refs to the tap and thread; on exit `CFMachPortInvalidate`.
3. Latency, two numbers per event: (a) delay = `mach_absolute_time` at callback entry minus the event's `CGEvent.timestamp` (both in mach ticks; convert with `mach_timebase_info`), (b) callback body duration. Also call `CGGetEventTapList` once per second and print this tap's min/avg/max usec latency. Report count, p50, p99, max for dragged events, and the measured dragged-event rate (expect about 120 Hz on a ProMotion display; record display refresh rate and note if the rate was lower).
4. CGWindowList: on every mouse-down, call `CGWindowListCopyWindowInfo([.optionOnScreenOnly, .excludeDesktopElements], kCGNullWindowID)`. For each entry log `kCGWindowNumber`, `kCGWindowOwnerPID`, `kCGWindowLayer`, `kCGWindowBounds`, and whether `kCGWindowName` / `kCGWindowOwnerName` are present. Count entries with a non-nil name; with Screen Recording denied expect zero names for other apps' windows (record owner name behavior exactly as observed).
5. Resolution: on first leftDragged after a mouse-down, take the window id from the event field, and also resolve by candidates = layer-0 entries whose bounds contain the mouse-down point. After about 10 dragged events, re-read the list and check that exactly one candidate's origin changed and that it equals the event-field id. Print `RESOLVED pid=<pid> id=<id> byField=<bool> byPidFrame=<bool>`.
6. Exit on Ctrl-C after printing the summary. All output to stdout so the human can redirect to a file.

Verdict file format (both notes): Date (12-hour Pacific, e.g. `5:46 PM PT`), Verdict (`PASS`, `FAIL`, or `PARTIAL: host OS only, rest PENDING-HUMAN`), a table of rows macOS 14 / macOS 15 / current release with columns tap created, events delivered, p99 delay ms, max callback ms, Screen Recording state, result (`PASS`/`FAIL`/`PENDING-HUMAN`), the exact run steps for a clean VM (grant only Accessibility to the built binary or its terminal host, drag a window for 10 s), and the raw log excerpt. SPK-003 must add a line "Escalation: ADR-0020 revisit required" only on FAIL, and state which downstream ACs change.
