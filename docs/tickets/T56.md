# T56: Onboarding explains a stale Accessibility entry after a re-signed build (AC-004, AC-014)

Kind: fix (orchestrator, from the human run on 2026-10-24). Blocked by: none.

## Evidence (user report, 2026-10-24)
- The user installed dist/Zones-0.1.0.dmg (ad-hoc signed) after testing a Debug build signed with the Zones Dev identity.
- System Settings showed one "Zones" entry, already ON, from the Debug build. The DMG copy was not trusted (its menu-bar icon reported "Zones, needs Accessibility access"), so Next in the onboarding window stayed disabled. Turning the toggle off and on did not help, and the window gave no instruction. The user closed the window.
- Cause: TCC keys the grant to the code signature. Every ad-hoc build has a new signature, so every update of an ad-hoc release meets this state. A toggle that shows ON but does not apply is invisible to the app: `AXIsProcessTrusted()` is false either way.

## Goal
1. While the onboarding window is open in `notGranted` (or `revoked`) for 10 s on the Clock, show a second line of help:
   "Is Zones already on in the list? Select Zones, click the minus button (−) to remove it, then click Open System Settings and turn Zones on again."
   Keep the Open System Settings button. Do not add a prompt (ADR-0021) and do not run `tccutil` from the app.
2. The help line is part of `OnboardingViewState` (pure, derived from state plus elapsed time) so it is unit-tested without a window.
3. README install section and the CHANGELOG known issue: one sentence each about removing and re-adding Zones after an update of an ad-hoc build.

## Acceptance
AC-004 (unchanged first-launch behavior: one window, the button opens the pane), AC-014 (ad-hoc release warning). Add the help-line rule to AC-004's statement through challenge C13.

## Test plan (test-first, fake Clock)
1. Red, then green: `notGranted` at 9.9 s → no help line; at 10 s → the exact help sentence.
2. Grant at 12 s → the window dismisses as before (AC-005 path unchanged).
3. `granted` and `suspect` never show the help line.
4. VoiceOver reads the help line (accessibility label equals the sentence).
5. Full `swift test` green; Debug xcodebuild green.
