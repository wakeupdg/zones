# T42: QA fix: Shortcuts pane row alignment and VoiceOver-reachable recorder fields (AC-103)

Kind: fix (QA round 1). Blocked by T34 (all done). Estimate 60k tokens. Area: App/Settings. Protocol: RecorderField, ShortcutsPane (edit). Fake: none needed (AppKit view test).

## Goal

- Each Shortcuts row has the action label and the recorder/Clear controls on one centre line; the per-row message line stays below without shifting the label.
- Every RecorderField is an accessibility element: role button, label `Shortcut for <action>`, value = the current chord text (or `Not set`), updated when the chord or recording state changes (not in `draw(_:)`).
- Keyboard-only: Tab reaches each recorder; Space/Return starts recording; Escape cancels; Delete clears (keep T27/T34 behavior).

## QA findings this ticket closes (verbatim evidence)

#### QA-1.1: Shortcuts pane rows: action label is top-aligned ~16 pt above the recorder/Clear control center
- Where: `App/Settings/ShortcutsPane.swift:61`
- Evidence: Renders scratchpad/qa/round1/screens/png/settings-shortcuts-light.png and settings-shortcuts-dark.png: every row is 58 pt tall; "Send to Zone N" sits at the row top (y≈38 pt) while the recorder field and Clear button are centred at y≈55 pt. Cause: App/Settings/ShortcutsPane.swift:61-73 wraps the LabeledContent in a `VStack(alignment: .leading, spacing: 4)` that reserves the message line, and the LabeledContent label aligns to the first text baseline of the HStack whose recorder is a fixed 150x24 NSViewRepresentable with no baseline.
- Repro: Open Settings > Shortcuts; compare the vertical position of "Send to Zone 1" with its recorder box.
- Fix hint (verifiers agreed 2/3): Put the LabeledContent directly in the Form row and the message as a separate row (or `.alignment(.center)` on the HStack), so label and control share a centre line as in the General pane.

#### QA-1.6: Shortcut recorder fields (14) are accessibility-ignored: VoiceOver never sees the 'Shortcut for …' label, the button role or the chord value
- Where: `App/Settings/ChordRecorderView.swift:53`
- Evidence: In-process AppKit check (scratch suite QaA11yScratch.settingsTabs, log a11y-run4.log): `A11Y[recorder] elem=false unignoredSelf=0 unignoredTypes=[] parentChildren=0 parentUnignored=[] axParent=Optional(SwiftUI.HostingScrollView)` and for every field `role=AXButton elem=false label='Shortcut for Send to Zone 1' value='⌃⌥1' enabled=false`. `NSAccessibility.unignoredChildren(from: [field])` returns [] so the field has no representation in the AX hierarchy; `configure()` sets `setAccessibilityRole(.button)` and `updateNSView` sets the label, but nothing calls `setAccessibilityElement(true)` on a plain NSView, whose default is ignored.
- Repro: Add the archived scratch test /private/tmp/claude-501/-Users-dganesh--MY-PROJECTS-open-source-clones-fancy-zones/faae5a4c-2276-4507-97e4-667cc6d49ef2/scratchpad/qa/round1/accessibility/QaA11yScratchTests.swift to AppTests in a worktree, `xcodegen generate`, run `Q_LOG=<f> scripts/q.sh xcodebuild -project Zones.xcodeproj -scheme Zones -configuration Debug -derivedDataPath .build/DerivedData CODE_SIGN_IDENTITY="Zones Dev" -only-testing:AppTests/QaA11yScratch test`, grep `A11Y\[recorder\]`: elem=false, unignoredSelf=0.
- Fix hint (verifiers agreed 2/3): In RecorderField.configure() add `setAccessibilityElement(true)`; also move `setAccessibilityValue` out of draw(_:) into the `chord`/`recording` didSet so the value is current before the first display.
