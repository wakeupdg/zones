# T21: Drag reducer: candidate resolution, phase-one and phase-two skips, cross-Display drops, topology and Space changes

Kind: build. Blocked by: T16, T14 (both merged before you start). Estimate: 140000 tokens. Branch: ticket/T21.

## Goal

- `DragSessionReducer` gains the candidate table: up to four z-ordered candidates are read in ONE batched `requestSample` per tick; the candidate whose first sample moved wins; five candidates give `skip(ambiguousMatch)` before any sampling; two movers after three returned samples give idle; a timed-out sample is retried once, then idle with `skip(unresponsive)`.
- Phase one: a skip `Verdict` on `mouseDown` ends the press at once, with no sample ever requested and no `showOverlay`.
- Phase two: facts riding on the first moved sample are run through `ExclusionPolicy.phaseTwo`; `fullScreen`, `sheetOrPopover`, `nonStandardSubrole` and `positionNotSettable` end the press with `stopSampling` and `skip`, never arming.
- Cross-Display: a window straddling two Displays hit-tests and snaps on the CURSOR's Display; a drop on a Display absent from the arm snapshot is a logged no-op.
- `topologyChanged` re-arms from the new snapshot (armed) or leaves state alone (pressed, moving); `spaceChanged` emits `reassertPanels` and a re-hit without leaving armed.
- T16 built the base reducer (mouseDown, dragged, mouseUp, flags, single-candidate path, Span). Read it first and extend it; do not rewrite it. Pure functions only: no Clock, no actor, no AppKit.

public struct ArmContext: Hashable, Sendable { public var topology: TopologySnapshot; public var layouts: [DisplayKey: ResolvedLayout]; public var appearance: Appearance; public var options: AccessibilityOptions; public var hasOriginalFrame: Bool }

## ADRs

- ADR-0014 No re-layout on display topology change; nothing happens in full-screen Spaces.
- ADR-0018 Besides per-app exclusions, Zones skips windows it cannot or should not move. Amendment 2026-10-24 (C4): phase 1 (CG facts, before any AX call) skips own pid, system agents, excluded bundles, unresponsive-cooldown pids; phase 2 (AX facts) skips non-standard subroles, sheets and popovers, system dialogs, full-screen and positionNotSettable; size-not-settable with position settable is `allow(positionOnly)`; every skip is logged once with its reason.
- LOCKED-SPEC section 8 (lines 956-986) records: candidate cap four with one batched read per tick; sampling stops at `moving`; one immediate retry on timeout, then abort and cooldown; mouse-path Original Frame is the mouse-down frame of the resolved window.

## Test plan

Each slice is red, then green, then one commit. Tests are pure `reduce` calls; assert state AND the exact effect list. Name sub-tests with the AC's name as prefix (the verify filter is a substring match, e.g. `candidateTableFiveCandidates` runs under `--filter candidateTable`).

1. `phaseOneSkipBeforeSampling` (AC-067; `mouseDown`, `Verdict`, `SkipReason`): for each of ownProcess, systemAgent, excludedBundle, unresponsive, `mouseDown(phaseOne: .skip(r))` returns `.idle` and exactly `[.skip(r, firstCandidate)]`; then feed `dragged`, `frameSample`, `mouseUp` to the result and assert no `requestSample` and no `showOverlay` appear anywhere. A control row with `.allow(.full)` reaches `.pressed`. Phase-one skip wins over the candidate cap.
2. `candidateTableFiveCandidates` (AC-056; `Constants.candidateCap`): `mouseDown` with 5 candidates (phaseOne allow) returns `.idle` and `[.skip(.ambiguousMatch, nil)]`, no `requestSample`. Four candidates is accepted and `pressed` keeps them in the given z-order. Zero candidates returns `.idle` with a `log` and no skip.
3. `candidateTableBatchedRead` (AC-056; `requestSample`): with 4 candidates, `pressed` then the first `dragged` yields ONE `requestSample([id1, id2, id3, id4])` in z-order, not four effects (keep T16's rule that sampling starts at the first dragged event, never at mouseDown).
4. `candidateTableFirstMoverWins` (AC-056; `frameSample`, `SampleResult`): with 2 stacked candidates, a tick where only the second moved resolves to the second: the resolved window is that `WindowRef`, `downFrame` is that window's own entry in `downFrames`, effects include `.stopSampling`, and the state leaves `pressed` the same way T16's single-candidate path does (reuse that code, do not fork it). "Moved" means the sample's `origin` differs from the stored down frame origin by more than `Constants.frameTolerance` in x or y. A tick with no mover keeps `pressed` with `samples + 1` and another batched `requestSample`.
5. `candidateTableTwoMoversSettle` (AC-056; `Constants.settleSamples`): two movers on returned samples 1 and 2 keep `pressed` (samples counted 1, 2, re-request each time); two movers on the 3rd returned sample give `.idle` with `[.stopSampling, .skip(.ambiguousMatch, nil)]`. Count every processed `frameSample`, including the retry tick. A single mover on any tick wins immediately, even if another candidate timed out in that tick.
6. `candidateTableTimeoutRetry` (AC-056; `SampleResult.timedOut`): no mover and at least one `timedOut`, `retried == false`: stay `pressed` with `retried: true` and one more batched `requestSample`; a second such tick: `.idle`, `[.stopSampling, .skip(.unresponsive, thatRef)]`. `.gone` candidates are dropped from the list; if none remain, `.idle` with `[.stopSampling]`. Never reset `retried` within one press (worst case 0.5 s).
7. `phaseTwoFailureEndsPress` (AC-047; `ExclusionPolicy.phaseTwo`, `frameSample`): table over facts for fullScreen (`isFullScreen: true`), sheetOrPopover (`.sheet`, `.popover`), nonStandardSubrole (`.floating`, `.unknown`), positionNotSettable (`positionSettable: false`): the first moved sample carrying those facts returns `.idle` with `[.stopSampling, .skip(reason, ref)]` and no `showOverlay`, and a later `dragged` or `frameSample` requests nothing. Compare to `ExclusionPolicy.phaseTwo` output rather than re-deriving the mapping. Positive rows: standard facts give the normal moving path; `sizeSettable: false` with position settable gives `allow(.positionOnly)` and moves on. A moved sample whose facts are `nil` ends the press as `skip(.unresponsive, ref)` (decision: no facts means no safe phase two; record it in the ledger).
8. `dropOutsideSnapshotIsNoOp` (AC-045; `mouseUp`, `ArmContext.topology`): armed with a snapshot of Displays A and B; `mouseUp` with the point on a Display C that is not in `context.topology` returns `.idle` and `[.hideOverlay, .log(_)]` with exactly one `log`, no `snap`, no `restore`. Also assert `dragged` over C leaves `armed` with `display == nil`, `hit == .none`, and `dimAll` highlight (mirrors T16's outside-visible-frame behavior).
9. `straddlingWindowSnapsOnCursorDisplay` (AC-052; `HitTest.hit`, `SnapPlan`): Displays A and B side by side with different Layouts; the armed window `frame` spans the seam with most of its area on A; cursor on B. Assert `display == B`, `hit` equals `HitTest.hit(point, in: layoutB)`, and `mouseUp` emits `snap` whose `plan.display == B` and `plan.target` lies inside B's `visibleFrame` and equals the Zone rect of B's Layout. Run it again with the cursor on A to prove the choice follows the cursor, not the window. The cursor's Display is the `DisplaySnapshot` whose `frame` contains the point.
10. `topologyChangeRearms` (AC-060; `topologyChanged`): armed plus `topologyChanged(newCtx)` returns armed with `context == newCtx`, `display` and `hit` recomputed against `newCtx`, and effects `[.showOverlay(scene from newCtx), .updateHighlight(h)]` using T16's scene and highlight builders. If the previous Display is gone from `newCtx.topology`: `display == nil`, `hit == .none`, `dimAll`. In `pressed` and `moving`: state unchanged, effects `[]` (neither holds a snapshot; the next `armContext` answer already carries the fresh one; do not add fields to `DragState`). In `idle`: unchanged, `[]`.
11. `spaceChangeReasserts` (AC-062; `spaceChanged`): armed returns the same armed state (context, display, hit, span unchanged) and effects `[.reassertPanels, .updateHighlight(h)]` where `h` is the current drop set, with no `hideOverlay` and no `showOverlay`. In `pressed`, `moving`, `idle`: unchanged, `[]`.

Contract gap, handle it this way: `armed` stores no cursor point, but the re-hit in slices 10 and 11 needs one. First check whether T16 retains the last cursor point somewhere (its `armed` or a helper); use that. If it does not, use the center of the previous `hit` Zone rect in the OLD context's layout for `display` as the re-hit point (a pure stand-in), keep `DragState` and CONTRACTS unchanged, and write the gap in the ledger so the orchestrator can decide on a contract change. Same for `SnapMode`: pass `allow(.positionOnly)` to `SnapPlan.mode` exactly the way T16 does; if `moving` and `armed` have no carrier for it, note that in the ledger too, do not change `DragState`.

Property tests: none required by these ACs. Manual, no test: AC-057 (four identical terminals, SPK-008); implement the candidate path and add a ledger note "AC-057 manual".
