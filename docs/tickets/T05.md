# T05: Spike: windowNumber equals CGWindowID, stacked identical windows, CG description polling (SPK-004, SPK-008, SPK-016)

Kind: spike. Blocked by: T01 (root package exists). Estimate: 90000 tokens. Branch: ticket/T05.
A spike answers questions with measurements. The product is three verdict files, not shipping code.

## Goal

- Build `Spikes/WindowIDProbe`, a standalone SPM executable (its own Package.swift, NOT a target of the root package).
- SPK-004: for 50 windows per OS, check `NSWindow.windowNumber == CGWindowID`, check the CGEvent window-under-pointer field equals the CGWindowList id, and check `CGWindowListCopyWindowInfo(.optionIncludingWindow, id)` alone returns the window.
- SPK-008: stack four same-size windows of one pid; over 20 trials record which candidate's origin changes on the first frame sample after the first dragged event. Pass only if exactly one candidate changes in 20 of 20.
- SPK-016: measure `CGWindowListCreateDescriptionFromArray` polling at 60 Hz as a move-confirmation source: samples to confirm a move, and cost against a SIGSTOP'd app.
- Write verdicts to `docs/spikes/SPK-004.md`, `SPK-008.md`, `SPK-016.md` (raw numbers, OS version, pass or fail, one-line consequence).
- A SPK-016 pass is recorded as a PROPOSED new ADR inside SPK-016.md. Do not create or edit any file under docs/adr/.

## Acceptance

Spike ticket, no AC ids. The SPK blocks from LOCKED-SPEC section 7, verbatim:

- SPK-004 NSWindow.windowNumber equals the CGWindowID, and the CGEvent window-under-pointer field equals the CGWindowList id, on macOS 14 and 15; optionIncludingWindow alone returns the window. Pass: equality in 50 of 50 windows per OS. Depends: AC-044, AC-056, AC-067.
- SPK-008 Stacked identical windows. Pass: for four same-size windows of one pid, the first frame sample after the first dragged event changes exactly one candidate's origin in 20 of 20 trials. Depends: AC-056, AC-057.
- SPK-016 CG window description polling as the move-confirmation source (ADR-0006 alternative). Pass: polling CGWindowListCreateDescriptionFromArray for the candidate ids confirms a move within two samples at 60 Hz and costs the target app nothing while SIGSTOP'd. A pass opens a new ADR; until then AX frame polling stands. Depends: AC-055, AC-056, AC-078.

Dependent expectations the verdicts fix: AC-044 and AC-067 (window identity at phase 1), AC-056 and AC-057 (candidate resolution, four identical terminals), AC-055 and AC-078 (move confirmation, hung app). The verdict also fixes the candidate mapping in T14 and T21.

Known facts from the research (verify, do not assume): Apple says windowNumber "isn't the same as the global window number"; an earlier probe on macOS 27.0.1 matched exactly. Apple says `optionIncludingWindow` should be combined with another option; Rectangle and Loop call it alone. The field is `kCGMouseEventWindowUnderMousePointerThatCanHandleThisEvent` (read on leftMouseDown). `CGWindowListCreateDescriptionFromArray` silently drops vanished ids, so match by `kCGWindowNumber`, not array index.

## Test plan

No XCTest: the root package cannot drive AppKit or the window server (LESSONS), and the probe is not a root target. Each slice is red-green by probe run: red = the subcommand exits nonzero with "unimplemented"; green = the subcommand runs to completion and prints its verdict line. Commit the code plus the verdict file in the same slice. Slices in order:

1. Package skeleton: `swift build --package-path Spikes/WindowIDProbe` succeeds; `spk004` stub exits 1 "unimplemented". Contract: none.
2. `spk004` identity: create 50 NSWindows (varied sizes, titles; borderless and titled mix), assert `Int(window.windowNumber)` equals a `kCGWindowNumber` present in `CGWindowListCopyWindowInfo(.optionAll)`, and that `CGWindowListCopyWindowInfo(.optionIncludingWindow, id)` ALONE returns exactly that window. Exercises: WindowID, WindowRef.id, WindowEnumerator.windows(ids:).
3. `spk004` event field: install a listen-only session tap (leftMouseDown), post a synthetic or real click at the center of each window, read the window-under-pointer field, assert it equals the CGWindowList id of that window. If the tap cannot be created (no Accessibility for the host terminal), stop, write the cause in the verdict as "blocked: needs human grant", and return blocked-needs-human. Exercises: WindowEnumerator.candidates(under:hint:) hint source, InputEvent.windowUnderPointer.
4. Record SPK-004 verdict in docs/spikes/SPK-004.md for the OS you are on (record `sw_vers`). The "macOS 14 and 15" requirement cannot be met on this host if it runs a different release: write the row you ran, write "not run: needs a macOS 14/15 machine" for the others, and set the overall verdict to "partial". Never invent a row.
5. `spk008` stacking: open four same-size, same-origin NSWindows in one pid, post a left-down on the top window's title bar plus a leftDragged event, take the first frame sample (AX frame read with 250 ms timeout of all four plus a CG description read), and record which candidates' origins changed. Repeat 20 trials, shuffling which window is on top each trial. Pass = exactly one changed in 20 of 20. Exercises: WindowRef.frame, WindowEnumerator.candidates(under:hint:) z-order.
6. Record SPK-008 verdict in docs/spikes/SPK-008.md. A fail is a valid verdict: state what to change in AC-056/AC-057 expectations (for example, hold the sample until a second tick).
7. `spk016` move confirmation: a child process (`--child-window`) shows one window and moves it on a command from the parent. The parent polls `CGWindowListCreateDescriptionFromArray([id])` at 60 Hz (match by `kCGWindowNumber`), and counts samples from the move command until the origin differs; 20 trials. Pass needs confirmation within 2 samples. Exercises: WindowEnumerator.windows(ids:).
8. `spk016` SIGSTOP cost: `kill -STOP` the child, poll the description for 5 s at 60 Hz, record latency p50, p95, p99 and max; compare with an AX frame read (250 ms timeout) of the same window, which should time out. Always `kill -CONT` the child (and on any exit path, including a trap) so no stopped process is left behind. Pass = description polling latency unchanged from the live case and no errors.
9. Record SPK-016 verdict in docs/spikes/SPK-016.md. On pass include the proposed ADR text (title, decision, rejected alternative), marked "PROPOSED, not applied; ADR-0006 stands until the orchestrator accepts it". On fail state that AX polling stands.

Manual ACs touched: AC-044, AC-057, AC-078 are manual and need no test here. This ticket only supplies evidence for them in the verdicts and writes no test for them. No property tests are called for.
