# T39: Drag reducer fix: armed keeps the last cursor point; topologyChanged re-hits at it (LI-009)

Kind: fix. Blocked by T21, T22 (done). Estimate 60k tokens. Protocol: `DragSessionReducer`, `DragState` (edit). Fake: none (pure reducer). Origin: T37 property `ReducerInvariantTests.highlightEqualsDropSet` found seeds 82, 132, 160, 212, 237 where the highlight after `topologyChanged` is empty while a mouseUp at the real cursor point snaps to the nearest remaining Display's Zone. The orchestrator ruled: LI-009 and AC-082 stand unchanged; the reducer is wrong; fix it here.

## Goal

- `DragState.armed` gains a ninth associated value `point: CGPoint?`: the last cursor point seen in armed (nil right after `armContext`, before the first `dragged`).
- `.dragged(point, _)` in armed stores `point`.
- `.topologyChanged(newCtx)` in armed: when `point` is non-nil, re-hit with `SpanLogic.cursor(at: point, in: newCtx)` (the same call the mouseUp path uses, so the highlight equals the drop set even when the cursor's previous Display is gone). When `point` is nil keep the current stand-in (`lastHitPoint` + `rehit`).
- Delete nothing else. `mouseUp` keeps recomputing from its own point.
- Update every `.armed(` construction and pattern in Sources/ZonesWindowing and Tests/ZonesWindowingTests (24 sites: DragSessionReducer.swift, SpanLogic.swift, DragSessionReducerTests.swift, SpanTests.swift, MessageTests.swift). Existing tests keep their meaning.
- Update docs/CONTRACTS.md section 3.1: add `point: CGPoint?` to the `armed` case and the sentence "armed stores the last cursor point; topologyChanged re-hits at it (LI-009)". Do not add any exception to "highlight == drop set".
