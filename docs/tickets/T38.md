# T38: Release, signing and gates: release.sh dry-run, hygiene gate, ticket lint, release checklist, bundle checks

Kind: build. Blocked by: T01 (scaffold, project.yml, App shell), T07 (SPK-005 verdict). Est. 120k tokens. Branch: `ticket/T38`. Ledger: `docs/tickets/T38/ledger.md` (create it with your first slice line).

## Goal
When done, `scripts/release.sh` builds a universal (arm64 + x86_64) Zones.app and, outside `--dry-run`, wraps it in a DMG under `dist/`. It signs with Developer ID when `ZONES_SIGN_IDENTITY` is set, else ad-hoc, printing exactly one stderr line containing `ad-hoc` in that case. `--dry-run` performs every step except signing, notarization and DMG creation and exits 0. `Casks/zones.rb` exists. Dev builds sign with "Zones Dev" so `codesign -d -r-` shows the identifier and certificate and no cdhash. The bundle is hardened-runtime with no app-sandbox entitlement, and `scripts/check-symbols.sh` proves no forbidden TCC or private symbols via `nm -u`. `scripts/hygiene-gate.sh` prints `unsafe-ops`, `ax-imports`, `cgwindowlist-uses` counts and exits 1 on any non-zero. `scripts/ticket-lint.sh` checks the `protocol`, `fake`, `tests` fields of `docs/tickets/graph.json`. CI runs the hygiene gate after `swift test`. `docs/release-checklist.md` has one row per AC-168 check.

### release.sh design
- Usage `scripts/release.sh [--dry-run]`. Run from any cwd (cd to repo root). `set -euo pipefail`. Build into `DerivedData/release` (git-ignored); DMG to `dist/Zones-<version>.dmg` (`dist/` and `*.dmg` are git-ignored).
- Version: `MARKETING_VERSION` read from `project.yml` with grep/sed; fallback `0.1.0`.
- Steps in order, each announced on stdout as `[release] step N: ...`:
  1. `xcodegen generate`.
  2. Release build: `xcodebuild -quiet -project Zones.xcodeproj -scheme Zones -configuration Release -derivedDataPath DerivedData/release ARCHS="arm64 x86_64" ONLY_ACTIVE_ARCH=NO CODE_SIGNING_ALLOWED=NO build`. Send xcodebuild output to a log file under DerivedData and `tail -20` it to stdout on failure only (stderr must stay clean for AC-014).
  3. Universal check: `lipo -archs` of the executable contains both `arm64` and `x86_64`.
  4. `scripts/check-symbols.sh <app>` (AC-003).
  5. Signing decision. Identity set: stdout `[release] signing: <identity> (Developer ID)`. Unset: stdout `[release] signing: ad-hoc` AND exactly one stderr line: `[release] WARNING: ZONES_SIGN_IDENTITY not set; signing ad-hoc (not notarizable, Gatekeeper will warn)`. Print the decision in both dry and real runs. No other stderr line may contain `ad-hoc` (case-sensitive), and the identity-set path must never print it to stderr.
  6. Sign (skipped in dry-run): `codesign --force --options runtime --timestamp --entitlements App/Zones.entitlements --sign "$ID" <app>`; ad-hoc uses `--sign -` and no `--timestamp`. Then `codesign --verify --strict <app>` and `scripts/check-symbols.sh --signature <app>` (AC-002 part only; the AC-013 part applies to dev builds).
  7. Notarize (skipped in dry-run; only when an identity is set AND `ZONES_NOTARY_PROFILE` names a notarytool keychain profile): `xcrun notarytool submit <zip> --keychain-profile "$ZONES_NOTARY_PROFILE" --wait`, then `xcrun stapler staple`. Otherwise print `[release] notarization skipped: <reason>` to stdout.
  8. DMG (skipped in dry-run): `hdiutil create -volname Zones -srcfolder <staging dir with Zones.app and an /Applications symlink> -ov -format UDZO dist/Zones-<version>.dmg`, then print `shasum -a 256` of it as a ready-to-paste cask `sha256` line.
  In dry-run, print `[release] dry-run: skipped signing, notarization, dmg` last, and call none of `codesign`, `notarytool`, `stapler`, `hdiutil`.
- Test hook (document it in the script header): `ZONES_RELEASE_SKIP_BUILD=1` makes steps 1 to 4 print `skipped (test hook)` so `GateScriptTests` is fast and hermetic. The real AC-014 command in the Done check runs WITHOUT it.

### hygiene-gate.sh design
- Usage `scripts/hygiene-gate.sh [ROOT]` (default: repo root). Scans `ROOT/App/**/*.swift` only. `Sources/ZonesWindowing/Adapters/` and `Seams/` are never scanned, which is the exemption. No `App/` dir: stderr message, exit 2.
- Output exactly three lines, this order, nothing else on stdout: `unsafe-ops: N`, `ax-imports: N`, `cgwindowlist-uses: N`. Exit 1 if any N > 0, else 0.
- Count LINES. unsafe-ops: lines matching `try!`, `\bas!` or `fatalError(` that do NOT contain `zones:allow`. ax-imports: lines matching `^[[:space:]]*import[[:space:]]+ApplicationServices`. cgwindowlist-uses: lines containing `CGWindowList`. Use `grep -E` and `grep -v`; no PCRE. Do not skip comment lines (strict). So never write those tokens in App/ comments.

### ticket-lint.sh design
- Usage `scripts/ticket-lint.sh [GRAPH]` (default `docs/tickets/graph.json`). Needs `jq`. The file is a JSON array of ticket objects with `.id`. Missing or non-array file: stderr message, exit 2.
- A field is missing when absent, not a string, empty or whitespace-only. `protocol` and `fake` accept the literal `none`. `tests` must not be `none` (case-insensitive after trim).
- Pass: stdout `tickets: <N>, missing-fields: 0`, exit 0. Fail: stdout `tickets: <N>, missing-fields: <M>`, then one line `FAIL <id>: <field>[, <field>]` per failing ticket in file order, exit 1. The first FAIL line names the first failing ticket id.
- Caveat: the live graph.json may not carry the three fields yet (the orchestrator adds them; you must never edit it). AC-167 is proven on scratch fixtures. On the live file just record the result in the ledger.

### check-symbols.sh design
- Usage `scripts/check-symbols.sh [--signature] [APP_OR_EXECUTABLE]`. Default target: the Debug build (`xcodebuild -project Zones.xcodeproj -scheme Zones -configuration Debug -showBuildSettings`, `BUILT_PRODUCTS_DIR`/`FULL_PRODUCT_NAME`). Accept a `.app` (executable at `Contents/MacOS/*`, plist at `Contents/Info.plist`) or a bare Mach-O (symbol check only).
- Symbols: `nm -u` (works on fat files; take the last field, strip one leading `_`). Fail on exact names CGRequestScreenCaptureAccess, CGPreflightScreenCaptureAccess, CGPreflightListenEventAccess, CGRequestListenEventAccess, IOHIDRequestAccess, IOHIDCheckAccess, and on any name starting `SLS` or `CGS`. Resolved gap: public CoreGraphics `CGSize...` functions (such as `CGSizeCreateDictionaryRepresentation`) start with `CGS` but are public; exclude names starting `CGSize` from the `CGS` rule and say so in a script comment and a ledger line. Print each offender, exit 1; print `symbols: ok` and exit 0 otherwise.
- Plist: `plutil -p` must show neither `NSScreenCaptureUsageDescription` nor `NSInputMonitoringUsageDescription`.
- `--signature` (needs a `.app`): AC-002: `codesign -dv --entitlements :- <app>` output has a `flags=` token whose parenthesised list contains `runtime` (ad-hoc shows `0x10002(adhoc,runtime)`, still pass) and the entitlements text has no `com.apple.security.app-sandbox`. AC-013: `codesign -d -r- <app>` contains `identifier "com.dganesh.zones"`, contains a `certificate` term, and does NOT contain `cdhash`. A self-signed cert usually renders as `certificate leaf = H"<sha1>"` rather than the literal name; follow SPK-005.md for the exact format and, when `security find-identity -p codesigning` lists "Zones Dev", also assert the printed hash matches it. Exit 1 with the failing check named.

### Casks/zones.rb design
Standard cask: `cask "zones"`, `version` matching `MARKETING_VERSION`, `sha256` as a clearly marked placeholder (release.sh prints the real line), `url "https://github.com/wakeupdg/zones/releases/download/v#{version}/Zones-#{version}.dmg"`, `name "Zones"`, `desc`, `homepage "https://github.com/wakeupdg/zones"`, `depends_on macos: ">= :sonoma"`, `app "Zones.app"`, `zap trash:` for `~/Library/Application Support/Zones` and `~/Library/Preferences/com.dganesh.zones.plist`. One attribution line at most in `desc`; no "FancyZones" marketing text. Syntax gate: `ruby -c Casks/zones.rb`.

### release-checklist.md design
- Header lines (no `AC-nnn` text on them): `Release tag:`, `macOS version:`, `Tester:`, each followed by a blank value to fill.
- One markdown table `| # | Check | Pass condition (AC) | Result |` with exactly 15 rows, one per semicolon-separated check in AC-168 (menu-bar drop with and without an Original Frame is ONE row). Each row is a single physical line, ends with a trailing `|` (the fail grep needs it), names its AC ids as `AC-ddd`, and leaves Result blank. The header and separator lines must contain no `AC-ddd` and no cell equal to `fail`.
- Any prose under the table must avoid `AC-ddd` text too, so `grep -cE 'AC-[0-9]{3}'` equals 15.
