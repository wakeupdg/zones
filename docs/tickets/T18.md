# T18: Editor commands: split, merge, divider snapping and nudging, validator limits, undo/redo, template picker; SPK-015 note

Kind: build. Blocked by: T12 (Templates, LayoutMath, LayoutValidator, LabelModel exist). Estimate: 140k tokens. Module: ZonesLayout (pure, headless, no AppKit).

## Goal
- `EditorEngine.apply(_:to:geometry:)` takes one `EditorCommand` and returns a new `EditorDraft` or an `EditorError`; on error the input draft is untouched.
- Commands: select, split (H side by side, V stacked, ratio 0.5), merge (siblings only; hint "split the parent the other way first"; root merge refused), setRatio with snapping to 1/2, 1/3, 1/4 and collinear dividers within 6 pt unless Option, nudge by 1 pt or 10 pt as ratio deltas for the current Display, setMargin, setGap, template replacement keeping the name, rename.
- Limits: a ratio leaving any leaf under 1/12 returns `tooSmall`; `EditorEngine.warnings` flags Zones resolving under 120x80 pt; the tenth Zone is accepted and `LabelModel` badges it `noChord`.
- `UndoStack` (value arrays of `EditorDraft`) gives an exact undo/redo round trip of 100 random commands.
- Also writes `docs/spikes/SPK-015.md`: the same-axis chain-merge formula and a golden table over every Template-derived tree. Recorded, not applied: merge stays sibling-only and AC-129 holds.

## Design decisions (made here so you do not have to guess; record any deviation in the ledger)
- Paths: `NodePath.steps` false = first, true = second. `select(path)` takes a leaf path (a Zone) or a split path (that node's divider). A path that does not exist returns `.nothingSelected`; `select(nil)` clears.
- Every successful command except `select` sets `dirty = true`. `select` changes only `selection`.
- split: needs a selected leaf (`.nothingSelected` if none or if the selection is a split). H gives `.split(axis: .horizontal, ratio: 0.5, first: .leaf, second: .leaf)`, V uses `.vertical`. New selection = the first child (`path + [false]`). After building, run `LayoutValidator.validate`; `.leafTooSmall` maps to `.tooSmall`, `.ratioOutOfRange` to `.invalidRatio`.
- merge: needs a selected leaf. Root path `[]` returns `.rootMerge`. If the sibling (last step flipped) is a leaf, replace the parent with `.leaf`, selection = parent path. Otherwise `.notSiblings(hint: "split the parent the other way first")`, draft unchanged. A selected split returns `.nothingSelected`.
- setRatio(path, ratio, snap): path must name a split node and ratio must be in (0,1), else `.invalidRatio`. With `snap: true`, candidates are 1/4, 1/3, 1/2, 2/3, 3/4 plus the position, in this parent's ratio space, of every other same-axis divider that is not this node or its descendant. Snap to the nearest candidate with `abs(ratio - c) * parentExtentPoints <= Constants.dividerSnapRadius`. `snap: false` (Option held) never snaps. Then validate as for split.
- `parentExtentPoints` = the parent node's unit extent along its axis times the Layout rectangle's width (horizontal) or height (vertical) from `LayoutMath.layoutRect(visibleFrame:surround:)` with `geometry.visibleFrame`. Margin and gap are ignored.
- nudge(path, points): new ratio = old ratio + points / parentExtentPoints (negative points move up or left). No snapping. Same validation. The UI maps arrow to 1, Shift+arrow to 10; the engine takes raw points.
- setMargin / setGap: set `layout.insets.margin` / `.gap`; a negative or non-finite value returns `.invalidRatio`. Never refuses for zone size; small Zones only show in `warnings`.
- template(t, count): `count` must be in `t.counts` else `.invalidRatio`. Take root and surround from `Templates.generate(t, count:, insets: draft insets)`, keep the draft's `id`, `name` and `insets`, set `builtIn = nil`, selection = nil.
- rename(s): store `s` trimmed; an empty name is allowed in a draft (save-time validation rejects it, not this ticket).
- `snappedRatio(_:candidates:parentExtentPoints:)` is the pure snapping function used by setRatio; test it directly.
- `warnings(_ r: ResolvedLayout) -> Set<Int>`: numbers of Zones whose frame is under `Constants.usableSize` (width < 120 or height < 80 pt).
- noChord: no engine flag. The tenth Zone must simply be accepted, and `LabelModel.labels(...)` must report `noChord == true` for Zone 10 and false for 1 through 9.
- `UndoStack` (in `UndoStack.swift`, public, Hashable, Sendable): `var undo: [EditorDraft]`, `var redo: [EditorDraft]`; `mutating func record(before: EditorDraft, after: EditorDraft)` pushes `before` and clears `redo` only if `before != after`; `mutating func undo(current:) -> EditorDraft?` and `redo(current:) -> EditorDraft?` move drafts between the arrays. Every changing command, `select` included, is recorded, so 100 changing commands need exactly 100 undos. EditorModel (T30) wires it into `EditorState` later.

## Test plan
Red-green, one slice per commit, in this order. All use Swift Testing, suite `EditorCommandTests`. Test function names must be exactly as listed, since the Verify commands filter on them.
1. `splitKeys` (AC-127; EditorCommand, EditorEngine): from a one-leaf draft with leaf selected, `split(.horizontal)` gives a root `.split(.horizontal, 0.5, .leaf, .leaf)` and 2 leaves; `split(.vertical)` on the new selection gives 3 leaves; V stacks (axis `.vertical`). No selection returns `.nothingSelected`, draft unchanged.
2. `mergeSiblingsOnly` (AC-129; EditorEngine, EditorError): leaf with leaf sibling collapses the parent. In `A | (B / C)`, merging A returns `.notSiblings(hint: "split the parent the other way first")` and the draft is `==` the input.
3. `noChordBadgeAndRootMerge` (AC-137; EditorEngine, LabelModel): split until 10 Zones (every split succeeds on a 1920x1080 geometry); resolve and assert `LabelModel.labels` has `noChord` only on number 10. `merge` on the root leaf returns `.rootMerge`.
4. `minimumFractionAndWarning` (AC-135; LayoutValidator, EditorEngine.warnings): `setRatio` to 0.05 returns `.tooSmall` and the draft is unchanged; 1/12 itself is accepted. Grid 9 (zero margin and gap) on a 300x200 frame (Zones about 100x67) warns on all nine; Grid 4 on 1920x1080 gives an empty set; a Zone of exactly 120x80 does not warn.
5. `dividerSnapAndNudge` (AC-128; EditorEngine.snappedRatio, constants): with geometry `(CGRect(0,0,1000,800), scale 2)` and zero surround, 0.504 snaps to 0.5 and 0.34 to 1/3 with `snap: true`; with `snap: false` both stay. 0.58 (80 pt away) does not snap. A collinear same-axis divider within 6 pt attracts. `nudge(path, points: 10)` moves a root horizontal split from 0.5 to 0.51; `1` moves 0.001; `-10` moves back.
6. `templatePicker` (AC-138; Templates): draft named "My Layout" with `template(.grid, count: 4)` has the Grid 4 tree, `name == "My Layout"`, same `id`; a count outside `t.counts` returns `.invalidRatio`. Also assert `rename` and `setMargin` / `setGap` update the fields and set `dirty`.
7. `undoRedoRoundTrip` (AC-130; UndoStack, EditorEngine; property): `Generator(seed:)` over several fixed seeds. Start from a draft with a few splits. Propose random commands (select, split, merge, setRatio, nudge, setMargin, setGap, template, rename), keep only those that return `.success` with a result `!=` the input, until 100 are accepted, calling `record(before:after:)` each time. Then 100 `undo` calls must give a draft `==` the original and 100 `redo` calls `==` the final. Failure messages use `Generator.failureMessage` (carries `seed=`).
8. `spk015Formula` (SPK-015; test-local helper, nothing added to Sources): for every tree in `Templates.all(insets:)`, find every pair `A | (B | C)` of same-axis chain (A a leaf first child, second child a same-axis split whose first child is a leaf B). Apply the formula in a test-local function and assert the merged Zone frame equals the union of A and B and every other Zone frame is unchanged at 1920x1080. Print nothing; the table goes in the note.

## SPK-015 note (docs/spikes/SPK-015.md)
Write these sections, short:
- Verdict: formula is deterministic; recorded, not applied; merge remains sibling-only and AC-129 holds; a follow-up ADR amending ADR-0003 would be needed to adopt it (do not write that ADR).
- Formula: for `.split(axis, r1, A, .split(axis, r2, B, C))` with A and B leaves (same axis), merging A and B yields `.split(axis, r1 + (1 - r1) * r2, .leaf, C)`; C is reparented one level up, and its own subtree and ratios are unchanged. Show why: the merged width is r1 + (1 - r1) * r2 of the parent, so C keeps its absolute extent.
- Scope: only the right-nested chain `A | (B | C)` with A and B leaves. List any other shape found in the Templates as unsupported rather than inventing a formula.
- Undo: exact, since undo restores the stored pre-merge `EditorDraft` (value copy), not an inverse computation.
- Golden table: one row per tree from `Templates.all` (Columns 2 to 5, Rows 2 to 5, Grid 4 and 9, Priority Grid 3, Focus 1; 12 trees). Columns: template and count, pair merged by Zone number, `r1`, `r2`, resulting ratio, resulting Zone count. Compute from the actual generated trees, not from memory. Sanity example if Columns 3 is a right-nested chain with 1/3 and 1/2: merging Zones 1 and 2 gives 1/3 + (2/3)(1/2) = 2/3. Rows and Grid use the same formula on the vertical axis; Focus has no pair.
