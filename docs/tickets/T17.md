# T17: LayoutStore, assignment lookup with dormant entries, delete-needs-replacement, import Merge/Replace and whole-file validation

Kind: build. Blocked by: T10 (ZonesDocument, DocumentStore, DocumentError), T12 (Templates, LayoutValidator in ZonesLayout). Estimate: 140k tokens. Branch: ticket/T17. Module: ZonesLayout only (no AppKit, no new target). Confirm `Templates.all`, `LayoutValidator.validate`, `ZonesDocument`, `DocumentStore` exist (ls/grep Sources/) before the first slice; if one is missing, stop and return blocked-needs-human.

## Goal

- `LayoutStore` is the in-memory truth: `builtIns` are regenerated from the Appearance default Insets (`Templates.all(insets:)`), `custom` Layouts carry their own explicit Insets; `setDefaults` regenerates built-ins only, `upsert` adds or replaces a custom Layout.
- `LayoutStore.delete` refuses a Layout referenced by any Assignment unless a replacement is given; with one, every referencing Assignment is rewritten in the same transaction (all or nothing).
- `AssignmentLookup.layoutID` returns the session Assignment first, then the persisted one, else `builtin:priorityGrid:3`. An imported Assignment for a display not yet connected stays in the one map (dormant) and is used the first time that key is looked up.
- `ImportExport.export` returns a `ZonesDocument` of all Layouts or just one; `importDocument` is pure: Merge keeps mine, renames name collisions with a numeric suffix, gives colliding ids fresh ids; Replace names a timestamped backup of both documents first, then returns one swapped document.
- Import validates EVERY Layout first and, on failure, returns `.refused(.invalidLayout(name:, fault))` naming the first offender (document order) and changes nothing.

## Behaviour decisions (the contract is silent; follow these, note any deviation in the ledger)

- `LayoutStore.document` = `ZonesDocument(version: Constants.documentVersion, layouts: custom, assignments: [:])`; the store never holds Assignments and never lists built-ins in `layouts`.
- `LayoutStore.init` drops any `builtIn != nil` Layout from `document.layouts`. `upsert` of a Layout with a `builtin:` id or non-nil `builtIn` is ignored.
- `delete` returns `.failure(.io("<reason>"))` (no dedicated DocumentError case exists; do not edit CONTRACTS.md) when: the id is a built-in; the id is unknown; the Layout is assigned and `replacement` is nil; or `replacement` equals the deleted id or does not resolve via `layout(_:)`. On any failure `assignments` and the store are byte-for-byte unchanged. A Layout no Assignment references deletes without a replacement.
- `AssignmentLookup`: `.uuid(s)` checks `session[key]` first, then `assignments[s]?.layout`, else `Templates.builtInID(.priorityGrid, count: 3)`. `.unstable` keys check only `session`, then the default. Dormant needs no extra code: an entry for a never-seen key sits in the map and is returned the first time that key is looked up.
- `export(only: id)`: the document holds that one Layout and only the Assignments that reference it; an id that is a built-in or unknown yields an empty `layouts` array. `only: nil` exports all custom Layouts and all given Assignments.
- `importDocument` is pure (no I/O). The caller writes only on `.applied`. Validate every incoming Layout (in array order) with `LayoutValidator.validate` BEFORE any merge work; the first fault returns `.refused(.invalidLayout(name: layout.name, fault))`. Version checks (AC-147) and non-UUID keys belong to other tickets; do not add them here.
- Merge: current Layouts and Assignments win. Incoming Layout whose id is already in `current` gets `newID()`; incoming Layout whose name equals any existing name (current or already-accepted incoming) is renamed `"<name> 2"`, then `"<name> 3"` and so on, first free. Incoming Assignments pointing at a re-id'd Layout are rewritten to the fresh id. Incoming Assignments whose key is absent from `current.assignments` are added; present keys keep mine. Result `backup` is nil.
- Replace: result document = incoming (layouts and assignments) with `version: Constants.documentVersion`. `backup` is non-nil: the string that names the backup of BOTH current documents, built from `now` with the same `<yyyyMMdd-HHmmss>` stamp format `DocumentStore.backupName` uses (read the T10 implementation and reuse its formatter; one stamp for both files). The caller writes both backups before the swap.
- `dormant` = keys of the incoming Assignments that end up in the result and are not in `attached`, sorted ascending.

4. `LayoutStoreTests.upsertAddsAndReplaces`: upsert new id appends; same id replaces in place (order kept); built-in id upsert is ignored; `layout(_:)` finds built-in and custom. Exercises LayoutStore.

7. `ImportExportTests.exportAllAndOne`: `export(only: nil)` returns every custom Layout and all Assignments, no built-ins, `version == Constants.documentVersion`; `export(only: id)` returns that Layout and only its Assignments; the document round-trips through the ZonesDocument codec. 8. `ImportExportTests.mergeAndReplace` (AC-146): Merge: existing "Desk" and id I; incoming "Desk" (new id) and another Layout reusing id I: result keeps existing untouched, incoming Desk becomes "Desk 2", the id-colliding one gets the injected `newID()` value, a second "Desk" incoming becomes "Desk 3", `backup == nil`, existing Assignment keys keep mine.
