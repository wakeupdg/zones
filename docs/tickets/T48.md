# T48: QA fix: one owner for Layouts and Assignments; editor and Settings writes reach the running app (AC-134, AC-139)

Kind: fix (QA round 2). Blocked by T36, T35, T34 (all done). Estimate 110k tokens. Protocol: AppState (edit). Fake: FakeFileSystem, FakeClock.

## Goal

- `AppState` (App/Composition) is the single in-memory owner of Layouts and Assignments. Add `upsertLayout(_:)`, `deleteLayout(_:)` and `replaceDocument(_:)` (or `reload()` from the DocumentStore) and make every writer go through it: EditorLauncher's `upsertLive`/`documentChanged`, EditorEffectRouter writes, Settings LayoutsFlow import/replace/delete/rename/duplicate, and TopologyDriver `persistAssignment`.
- After any write, the next drag arm, Send to Zone shortcut and the status menu see the new Layouts and Assignments without relaunch.
- `AppState.setAssignment` never persists a stale dictionary: an Assignment saved from the editor and then a topology `persistAssignment` for another Display keeps both on disk.
- Keep EditorLauncher's private LayoutStore only if it is a view of AppState; no second source of truth.

## QA findings this ticket closes (verbatim evidence)

#### QA-2.7: Editor Save/Assign and Settings Layouts changes never reach the running drag, Snap, shortcut or menu state until relaunch
- Where: `App/Composition/AppState.swift:39`
- Evidence: AppState loads layouts and assignments once, in init (AppState.swift:39-41). It has no reload or upsert API: the only later writes are setDefaults (insets) and setAssignment (:82). The editor is built in AppDelegate.swift:41-43 with documentChanged: { _ in } and upsertLive: { self?.layouts.upsert(layout) } (EditorLauncher.swift:51-52). That upsert only updates EditorLauncher's own private LayoutStore (built at EditorLauncher.swift:41). EditorEffectRouter.swift:43/52 writes .layouts and .assignments to disk, and .replaceLive (:57-58) goes to that private store. Settings' ImportExportController.live builds a third DocumentStore and LayoutsFlow (ImportExportController.swift:62-71) for pick, delete, rename and import, and never notifies the root. Every consumer reads root.state: DragDriver.makeContext (DragDriver.swift:194) and rearm, ShortcutDriver.swift:88 and MenuController.rebuild (MenuController.swift:61-64).
- Repro: 1) Launch Zones with Accessibility granted. 2) Control+Option+E, then press H, H, Cmd-S, Cmd-Shift-A, Cmd-W (AC-139). 3) Shift-drag a window on that Display. The Overlay and Snap still use the old Layout (Priority Grid by default), not three columns. The status menu's Layout picker does not list the new Layout either. Only a relaunch picks it up. The same happens after a Settings > Layouts pick, delete or import.
- Fix hint (verifiers kept it 3/3): Have one owner of Layouts and Assignments. Route the editor's upsertLive/documentChanged and the Settings LayoutsFlow writes through root.state (add AppState.upsertLayout / replaceDocument), or re-read AppState after each successful write. Then refresh the menu and session context.

#### QA-2.8: Topology or menu-pick Assignment write persists AppState's stale dictionary and erases Assignments made in the editor or Settings
- Where: `App/Composition/AppState.swift:81`
- Evidence: AppState.setAssignment (AppState.swift:81-84) sets assignments[key.uuid] on the in-memory dictionary loaded at launch (:41), then saves ZonesDocument(assignments: assignments) as the whole .assignments file. It is called for every TopologyEffect.persistAssignment (TopologyDriver.swift:94). That effect fires when a known UUID's name, visible frame or scale drifts (TopologyMonitor.swift:132-145), and for a status-menu pick (MenuController.swift:107-109 -> topology.pick -> TopologyMonitor.swift:124-128). The editor's Assign (EditorEffectRouter.swift:50-52) and Settings' LayoutsFlow write the same assignments file through separate DocumentStores, and AppState never sees those writes.
- Repro: 1) In the editor, assign a custom Layout to Display A (Cmd-Shift-A). assignments.json now holds A -> custom. 2) Without relaunching, use the status menu's Layout picker to pick 'Columns 3' for Display B, or let A's visible frame drift (show or hide the Dock, change resolution). 3) Read ~/Library/Application Support/Zones assignments: A is back to its launch-time value (or missing). The editor's Assignment is lost permanently, even after a relaunch.
- Fix hint (verifiers kept it 3/3): Fold this into the single-owner fix above. AppState must hold the latest on-disk assignments before it writes, or every writer must go through AppState.
