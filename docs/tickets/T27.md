# T27: Shortcut store, chord rules, recorder states, registration diff, dispatcher, production Carbon registrar

Kind: build. Blocked by: T02, T10, T16 (merged before you start). Estimate: 150k tokens. Branch: ticket/T27. Modules: ZonesWindowing (Shortcuts/, Adapters/); ZonesCore and App/ are not edited.

## Goal

- `ShortcutRules.defaults` equals ADR-0010 (Control+Option 1..9, Right, Left, R, E, Comma); `validate` accepts a chord only if it has Command or Control.
- `ShortcutRules.recorderState` returns `rejected`, `conflict(duplicate:)`, `warning(_)` or `accepted`, in that precedence.
- `ShortcutStore.reduce` registers openEditor/openSettings in every permission state and the 12 window actions only while granted, re-registers only the changed action, keeps the previous chord when registration returns inUse, leaves a cleared action unbound with exactly one unregister, and queues `.set` diffs while the reducer is not idle (applied on return to idle).
- `ShortcutDispatcher.dispatch` drops window commands with exactly one log line while the reducer is not idle; `DragSessionReducerTests.modifierConfigReadAtMouseDown` proves the Activation Modifier is read at mouseDown only.
- `CarbonHotkeyRegistrar` is the production `HotkeyRegistrar` over `RegisterEventHotKey` with a Key-to-keycode table. Wiring it into App/ is a later ticket; this ticket touches no App/ file.

### Reducer semantics (ShortcutStore.reduce, pure; effects in `ShortcutAction.allCases` order)
- eligible(a) = `!a.isWindowAction || state.granted`.
- `.launch`: for each eligible action with a non-nil chord not in `registered`: effect `register(chord, a)`.
- `.permission(granted:)`: unchanged value = no effects. true: set granted, register window actions with chords not registered. false: set granted false, `unregister` each registered window action and remove it from `registered`; chords stay in `shortcuts`. Applied immediately, never queued.
- `.set(a, chord)` when `idle == false`: append to `queued`, no effects. When idle:
  - chord nil: set the Shortcut's chord to nil, remove from `registered` and `pending`, effects `[unregister(a) only if it was registered, persist(shortcuts)]`. Never revert to the default.
  - chord equal to the committed chord and (registered or not eligible): no effects.
  - chord non-nil and eligible: `pending[a] = chord`, effect `register(chord, a)` only. Emit no `unregister` and do not touch `shortcuts` yet, so a failure leaves the old chord live (AC-104).
  - chord non-nil and not eligible (window action, not granted): commit to `shortcuts` now, effect `persist` only.
- `.registration(a, .registered)`: insert into `registered`; if `pending[a]` exists, commit it to `shortcuts`, clear it, and emit `persist(shortcuts)`. `.registration(a, .inUse|.invalid)`: clear `pending[a]`, emit `failed(a, result)` only; `shortcuts` and `registered` unchanged. Never queued.
- `.reducerIdle(false)`: idle false. `.reducerIdle(true)`: idle true, then fold `queued` in order through `reduce`, clear `queued`, return the concatenated effects.

### Chord rules (ShortcutRules)
- `validate(c)` = `c.hasCommandOrControl`.
- `recorderState(c, for: a, bound:)`: (1) `!validate` gives `rejected`; (2) another shortcut in `bound` with `action != a` and `chord == c` gives `conflict(duplicate: thatAction)`, first in array order, and the same action's own chord is never a conflict; (3) modifiers exactly `[command]` gives `warning(.commandOnly)`; exactly `[command, shift]` gives `warning(.commandShiftOnly)`; exactly `[control]` with key `.digit` or any arrow gives `warning(.controlOnlyWithArrowOrDigit)`; else `accepted`. Control-only with a letter or comma is `accepted`.

### CarbonHotkeyRegistrar (Sources/ZonesWindowing/Adapters/CarbonHotkeyRegistrar.swift)
- `import Carbon.HIToolbox`. If the import fails on this SDK, declare minimal `@_silgen_name` shims for `RegisterEventHotKey`, `UnregisterEventHotKey`, `InstallEventHandler`, `GetEventParameter` and write that in the ledger (event-taps-tcc.md finding 12 could not confirm the headers).
- Install one application-target handler (`GetApplicationEventTarget()`, `kEventClassKeyboard`, `kEventHotKeyPressed`) in `init`. Pass `self` via `Unmanaged` userData; the C callback reads `EventHotKeyID`, maps `id` to the action, and yields to the `presses` continuation inside `MainActor.assumeIsolated`.
- `register(chord, for: a)`: build `EventHotKeyID(signature: 0x5A4F4E45 /* 'ZONE' */, id: <stable Int per action, its allCases index + 1>)`. Register the NEW hotkey first; on `noErr` unregister that action's old `EventHotKeyRef` and keep the new one; on failure keep the old one untouched. Result: `noErr` is `.registered`; `eventHotKeyExistsErr` (-9878) is `.inUse`; any other status or an unmapped Key is `.invalid`.
- `unregister(a)` calls `UnregisterEventHotKey` and drops the ref; `bound(a)` returns the chord last registered successfully.
- Modifiers: command 256, shift 512, option 2048, control 4096 (OR together). Put the table in an internal pure `enum CarbonKeyMap { static func keyCode(for: Key) -> UInt32?; static func modifiers(_: ModifierSet) -> UInt32 }` so it is testable without Carbon.
- ANSI keycodes: digits 1..9,0 = 18 19 20 21 23 22 26 28 25 29; letters A0 S1 D2 F3 H4 G5 Z6 X7 C8 V9 B11 Q12 W13 E14 R15 Y16 T17 O31 U32 I34 P35 L37 J38 K40 N45 M46; left 123, right 124, down 125, up 126; comma 43. `digit(n)` outside 0...9 and non-single-letter strings return nil.
