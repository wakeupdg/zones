Kind: build. Blocked by: T02 (fakes, ZonesTestSupport), T04 (spike SPK-003 verdict), T16 (DragSessionReducer). Estimate: 120k tokens. Protocol: InputSource (production EventTapInputSource). Fake: FakeInputSource (consumed, not edited).

## Goal

- `EventTapInputSource` (production `InputSource`) creates one `listenOnly` session tap at `tailAppendEventTap` on its own `.userInteractive` thread, for left down, left dragged, left up and flagsChanged only. Right and other buttons never produce an event.
- Each tap callback turns a CGEvent into an `InputEvent` (kind, point, `ModifierSet.masked(flags)`, the window-under-pointer CGEvent field as `WindowID?`, time) and yields it on `events`. The callback does O(1) work and never consumes or modifies the event.
- `kCGEventTapDisabledByTimeout` / `ByUserInput` become `TapSignal.disabledByTimeout` / `.disabledByUserInput` on `signals`. `reenable()` and `recreate()` do the repair; a nil tap from `CGEvent.tapCreate` gives `TapStart.unavailable`, never a crash.
- `TapRecovery.reduce` (pure) allows five re-enables per 60 s, then returns `.tapLost` and schedules the 30 s `deadTapRetry`; the retry fires `.recreate`.
- `TapConfig.production` is `listenOnly == true`, mask `{leftDown, leftDragged, leftUp, flagsChanged}`.
- A second mouse-down while a Drag Session is not idle changes nothing (`DragSessionReducerTests.secondMouseDownIgnored`).

Implementation notes (from docs/research/event-taps-tcc.md and the contracts):
- Tap: `CGEvent.tapCreate(tap: .cgSessionEventTap, place: .tailAppendEventTap, options: .listenOnly, eventsOfInterest: mask, callback:, userInfo:)`; add `CFMachPortCreateRunLoopSource` to the thread's run loop in `.commonModes`; then `CGEvent.tapEnable(tap:enable:true)`. Dedicated `Thread` with `qualityOfService = .userInteractive`.
- The callback is `@convention(c)` and cannot capture. Pass state through `userInfo` with `Unmanaged<Box>`, where Box holds the stream continuations and the primary-frame provider behind a lock (`OSAllocatedUnfairLock`; the only `@unchecked Sendable` allowed in the repo is WindowHandle, so keep Box `Sendable` by construction).
- In the callback on `.tapDisabledByTimeout` / `.tapDisabledByUserInput`: yield the matching `TapSignal` and return the event. Do NOT re-enable inside the callback; `TapRecovery` decides, and the driver then calls `reenable()` (otherwise the rate limit means nothing).
- `reenable()` calls `CGEvent.tapEnable(tap, true)` and returns `CGEvent.tapIsEnabled(tap:)`; false when there is no tap. `recreate()` tears down (`CFMachPortInvalidate`, remove run loop source, stop the thread), runs the same setup as `start()`, yields `.recreated(started)`, returns the `TapStart`. `stop()` does the same teardown. The two AsyncStreams outlive stop/recreate (finish them only in `deinit`).
- Testability seams: `init(tapMaker: TapMaker = .live, primaryFrame: @escaping @Sendable () -> CGRect)` where `TapMaker` is an internal closure type `(TapConfig, UnsafeMutableRawPointer) -> CFMachPort?`, and `static func translate(type: CGEventType, event: CGEvent, primaryFrame: CGRect) -> InputEvent?` is internal and pure. Tests never create a live tap.
- Coordinates: `CGEvent.location` is top-left-origin CG space; convert to AppKit global with `CoordinateSpace.appKitRect(CGRect(origin: p, size: .zero), primaryFrame:).origin`. If that proves wrong for a point, record it in the ledger and stop that slice.
- Time: `Double(event.timestamp) / 1_000_000_000`.
- TapRecovery details: keep `reenables` pruned to `now - t < Constants.reenableWindow`; if count < `Constants.reenableLimit` append `now` and return `[.reenable]`, else set `.dead` and return `[.tapLost, .schedule(.deadTapRetry, Constants.deadTapRetry)]`. Initial `state` is `.alive`. A `.recreated(false)` in `.alive` means the first start failed: `[.tapUnavailable]`, state `.unavailable`, no timer. Where the contract is silent, keep to this and record the choice in the ledger.
