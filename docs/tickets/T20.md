# T20: Permission machine: trust poll, runtime-signal revocation, suspect window, relaunch gate, heartbeat isolation, wake and re-onboard

Kind: build. Blocked by: T02, T06, T16. Estimate: 150000 tokens. Branch: ticket/T20. Protocol: none (pure reducer; PermissionProbe consumed). Fake: FakeClock, FakePermissionProbe consumed. Tests: PermissionMachineTests, DragSessionReducerTests.wakeEndsSession.

## Goal
- `PermissionMachine.reduce` is a pure function over `notGranted / granted / suspect / revoked / needsRelaunch`; no Clock, no actor, no AppKit. Timers are only `schedule/cancel` effects.
- The 1 s trust poll runs only outside `granted` (notGranted, revoked, needsRelaunch); `granted` runs only the 5 s health tick. The first true probe emits `dismissOnboarding` then `startTap`.
- Runtime signals revoke: `apiDisabled` or `tapNil` in granted -> `suspect`; tap recreation plus one trivial read -> granted; otherwise 3 s later -> `revoked` with badge, showOnboarding, unregisterWindowHotkeys, drainEnhancedUI.
- In revoked with the probe true, three failed recreations over 10 s -> `needsRelaunch`, the only state that offers Quit and Reopen. Probe false keeps `revoked` forever with no button. Successful recreation from either state -> granted.
- Re-onboard goes granted -> notGranted with `showOnboarding`, touching no store. Wake emits `revalidateTap, probe, forceTopologySnapshot, orderPanelsOut`.
- The heartbeat (default gated by the SPK-006 verdict via `heartbeatEnabled`) feeds only this machine, at most one in flight, none while `reducerIdle` is false. The launched-at-login path emits no window effects.

### Reducer semantics chosen by this brief (the spec leaves them open; keep them unless a test proves them wrong, and ledger any change)
- Timers are one-shot, re-armed by the reducer; every `schedule(id, t)` is preceded by `cancel(id)` so at most one timer per id exists. Effect order below is the test-asserted order.
- Every state: `.quit` -> cancel all five permission timers (`trustPoll, healthTick, suspectResolve, relaunchGate`), `disableTap`; state unchanged.
- notGranted: `.timer(.trustPoll)` -> `[probe]`. `.probe(false)` -> `[schedule(trustPoll,1)]`. First `.probe(true)` -> granted, `[cancel(trustPoll), dismissOnboarding, startTap, badge(false), grantMenuItem(false), registerWindowHotkeys, cancel(healthTick), schedule(healthTick,5)]`. `.reonboard` -> re-emit `showOnboarding` only.
- granted: `.timer(.healthTick)` with `heartbeatEnabled && reducerIdle` -> `[heartbeat]` and NO reschedule (the result re-arms, which makes "one in flight" structural). Otherwise -> `[cancel(healthTick), schedule(healthTick,5)]`. `.heartbeat(.apiDisabled)` / `.apiDisabled` / `.tapNil` / `.probe(false)` -> suspect(since: now), `[cancel(healthTick), recreateTap, cancel(suspectResolve), schedule(suspectResolve,3)]`. Other `.heartbeat(_)` -> `[cancel(healthTick), schedule(healthTick,5)]`. `.reonboard` -> notGranted, `[cancel(healthTick), showOnboarding, cancel(trustPoll), schedule(trustPoll,1)]` (tap untouched; the driver's `startTap` on the next true probe is idempotent). `.probe(true)` -> no effects.
- suspect: `.tapRecreated(true)` -> `[heartbeat]` (the one trivial read). `.trivialRead(.ok)` or `.heartbeat(.ok)` -> granted, `[cancel(suspectResolve), cancel(healthTick), schedule(healthTick,5)]`. `.tapRecreated(false)`, other read results, repeat signals -> stay, no effects. `.timer(.suspectResolve)` when `now - since >= 3.0` -> revoked(failures:0, firstFailure:nil), `[cancel(healthTick), badge(true), grantMenuItem(true), showOnboarding, unregisterWindowHotkeys, drainEnhancedUI, cancel(trustPoll), schedule(trustPoll,1)]`. `.reonboard` ignored.
- revoked(failures, firstFailure): `.timer(.trustPoll)` -> `[probe]`. `.probe(false)` -> revoked(0,nil), `[cancel(relaunchGate), schedule(trustPoll,1)]`. `.probe(true)` -> `[recreateTap, schedule(trustPoll,1)]`. `.tapRecreated(false)` -> failures+1, `firstFailure ??= now`; on the first failure also `[cancel(relaunchGate), schedule(relaunchGate,10)]`. `.timer(.relaunchGate)` with `failures >= 3 && now - firstFailure >= 10` -> needsRelaunch, `[offerRelaunch(true)]`; with fewer failures -> revoked(0,nil), no effects. `.tapRecreated(true)` -> granted, `[cancel(relaunchGate), cancel(trustPoll), dismissOnboarding, badge(false), grantMenuItem(false), registerWindowHotkeys, cancel(healthTick), schedule(healthTick,5)]`. `.reonboard` -> re-emit `showOnboarding`.
- needsRelaunch: same poll as revoked. `.probe(true)` -> `[recreateTap, schedule(trustPoll,1)]`. `.tapRecreated(true)` -> granted, effects as in revoked plus `offerRelaunch(false)` first. `.probe(false)` -> revoked(0,nil), `[offerRelaunch(false), schedule(trustPoll,1)]`.
- `.wake` in EVERY state: state unchanged, effects exactly `[revalidateTap, probe, forceTopologySnapshot, orderPanelsOut]`.
- `launchedAtLogin == true`: drop `showOnboarding` and `dismissOnboarding` from every effect list above; keep badge and grantMenuItem. "Window effects" here means exactly those two. (notGranted needs no badge effect: `StatusItemModel.derive` shows it from state.)
- `offerRelaunch(true)` appears only on the transition into needsRelaunch; nothing else may ever emit it.
- Heartbeat results in non-granted states are ignored (no effects). A `.heartbeat` request is the only effect that asks for a trivial AX read; the driver answers it as `.heartbeat` in granted and as `.trivialRead` in suspect. Heartbeat results go to this machine only, never to `AppHealth` (AC-158).

## Test plan
Harness (private to PermissionMachineTests, written in slice 1): wraps `FakeClock`, `FakePermissionProbe`, a state and a config; `send(_ event)` calls `reduce` and interprets effects: `schedule` -> `clock.schedule` whose fire calls `send(.timer(id))`, `cancel` -> cancel that handle, `probe` -> feed `.probe(probe.isTrusted())`, `recreateTap` / `heartbeat` -> record in a `[PermissionEffect]` log for the test to answer by hand. Never touch the real AX API.
1. `pollScheduleMatchesState` (AC-006), exercises `reduce` + FakeClock: from notGranted with probe false, `clock.pending == [.trustPoll]` and three `advance(by: 1)` yield three probes; with probe true the first probe emits `dismissOnboarding` before `startTap` (index order), then `pending == [.healthTick]` with no `.trustPoll`, and three `advance(by: 5)` re-arm exactly one healthTick each time.
2. `suspectResolvesToGrantedOrRevoked` (AC-007): from granted, `apiDisabled` and `tapNil` each -> suspect(since: now). Path A: `tapRecreated(true)` -> `heartbeat` effect, `trivialRead(.ok)` -> granted. Path B: `tapRecreated(false)`, then at exactly +3 s `timer(.suspectResolve)` -> revoked with effects containing `badge(true), showOnboarding, unregisterWindowHotkeys, drainEnhancedUI`; at +2.9 s the timer is ignored (state stays suspect).
3. `relaunchOnlyAfterGateWithProbeTrue` (AC-008): revoked + probe true, three `tapRecreated(false)` at t=0,1,2, gate at t=10 -> needsRelaunch with `offerRelaunch(true)`; at t=3..9 no offer. Probe false: 100 poll cycles over 100 s stay revoked and never emit `offerRelaunch(true)`. `tapRecreated(true)` from revoked and from needsRelaunch -> granted. Add a seeded random-walk property (200 events from the full alphabet): `offerRelaunch(true)` only on a transition into needsRelaunch, and never when the last probe event was false.
4. `reonboardLeavesStoresUntouched` (AC-021): build a `DocumentStore` over `FakeFileSystem`, record its call log, run granted + `.reonboard` -> notGranted with `showOnboarding`; assert the FakeFileSystem call log is unchanged and the effect list has no `invalidateTap` or `removeRecoveryRecord`.
5. `wakeEffects` (AC-024 machine half): all five states, `.wake` -> state unchanged, effects exactly `[revalidateTap, probe, forceTopologySnapshot, orderPanelsOut]`.
6. `heartbeatIsolation` (AC-158): enabled + idle healthTick -> exactly one `heartbeat` and no `schedule`; result `.ok` / `.timedOut` -> one re-armed healthTick, no second heartbeat; not idle or disabled -> zero `heartbeat` over 10 ticks; `.heartbeat` events in notGranted / revoked produce no effects; `heartbeat(.apiDisabled)` in granted -> suspect. Also assert an `AppHealth` value built before the run is `==` after it (nothing in the machine can reach it).
7. `launchedAtLoginEmitsNoWindowEffects`: replay slices 1-3 and 5 with `launchedAtLogin: true`; no effect is `showOnboarding` or `dismissOnboarding`; revoked still emits `badge(true)` and `grantMenuItem(true)`.
8. `DragSessionReducerTests.wakeEndsSession` (AC-024 reducer half), exercises `DragSessionReducer.reduce`: for each of idle, pressed, moving, armed (build with the T01 fixtures), `.wake` -> state `.idle` and effects contain `.hideOverlay`. If the reducer already does this the slice is test-only; if it does not, make the smallest fix in the reducer's own file (locate with grep), and write which file in the ledger.
Manual, no test, implementation plus a ledger note only: AC-009 (revocation on a real Mac), AC-010 (re-grant recovery), AC-025 (wake on a docked Mac). Do not run them.
