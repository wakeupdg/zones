# T51: QA fix: AX import confined to Adapters with a Sources gate (AC-162); dev-cert keychain hardening

Kind: fix (QA round 2). Blocked by T38, T13 (all done). Estimate 60k tokens. Protocol: WindowHandle (edit). Fake: none needed.

## Goal

- `import ApplicationServices` appears only under Sources/ZonesWindowing/Adapters. Make `WindowHandle` opaque in Seams (store the element as `AnyObject`/a box type declared in Adapters, or move the AX-typed part into Adapters) so Seams has no ApplicationServices import. Keep the one `@unchecked Sendable` budget (SeamTests.uncheckedBoxCountIsOne).
- Extend `scripts/hygiene-gate.sh` (or add a second check it calls) so an `import ApplicationServices` in Sources outside Adapters/ fails the gate; keep its three output lines and add one `sources-ax-imports: N` line; update GateScriptTests.
- `scripts/dev-cert.sh`: generate a random keychain password per machine at creation, store it only in the login keychain (`security add-generic-password -s zones-dev-keychain`), read it back for unlock; set the dev keychain to auto-lock (`set-keychain-settings -t 3600 -l`); keep `-T /usr/bin/codesign` but drop the blanket `codesign:` partition entry only if signing still works non-interactively for `scripts/merge-ticket.sh`; if it does not, keep it and document the trade-off in the script header. Do not rotate the existing identity (the Accessibility grant depends on the leaf certificate hash).

## QA findings this ticket closes (verbatim evidence)

#### QA-2.9: WindowHandle seam imports ApplicationServices outside the production adapter sources (AC-162 scope)
- Where: `Sources/ZonesWindowing/Seams/WindowHandle.swift:2`
- Evidence: `grep -rn 'import ApplicationServices' Sources App` lists Adapters/AXPermissionProbe.swift, Adapters/AXObserverBridge.swift, Adapters/AXWindowSystem.swift and Seams/WindowHandle.swift:2. WindowHandle also stores an AXUIElement (line 11). AC-162 says those imports 'appear only in the production adapter sources'. scripts/hygiene-gate.sh only scans App/ (its header comment exempts Adapters and Seams), so it prints ax-imports: 0, exits 0, and cannot catch this.
- Repro: cd repo; grep -rn 'import ApplicationServices' Sources App; Seams/WindowHandle.swift:2 shows up. Then scripts/hygiene-gate.sh still exits 0.
- Fix hint (verifiers kept it 2/3): Move WindowHandle (the AXUIElement box) into Sources/ZonesWindowing/Adapters, or make the seam opaque. Then extend the gate to fail on AX imports in Sources outside Adapters/.

#### QA-2.1: dev-cert.sh lets any local process silently sign code as "Zones Dev" and inherit Zones' Accessibility grant (hardcoded keychain password, keychain never locks, codesign pre-authorized)
- Where: `scripts/dev-cert.sh:10`
- Evidence: scripts/dev-cert.sh:10 PASS="zones-dev" (password committed to the repo); :36 `security set-keychain-settings "$KC"` (no auto-lock, `security show-keychain-info` prints "no-timeout"); :38 unlock-keychain; :43-44 import with -T /usr/bin/codesign and set-key-partition-list apple-tool:,apple:,codesign: (codesign uses the private key with no prompt); :46 add-trusted-cert -r trustRoot -p codeSign. Built app DR (codesign -d -r-): `identifier "com.dganesh.zones" and certificate leaf = H"22a4d61ce3f62fd9d543f7ac1a8102ea2f952476"`. Proof on this machine: copied /bin/echo to scratch, ran `codesign --force -i com.dganesh.zones --sign "Zones Dev" probe` -> exit 0, no dialog; `codesign -v -R='identifier "com.dganesh.zones" and certificate leaf = H"22a4d61c..."' probe` -> exit 0; `codesign -dvv probe` -> Identifier=com.dganesh.zones, Authority=Zones Dev. TCC keys the Accessibility grant to that DR, so any binary signed this way is treated as Zones by TCC (full input control over every app). Probe file deleted afterwards. ADR-0025 does not mention this risk.
- Repro: 1) Run scripts/dev-cert.sh once (already done on this host). 2) As the normal user, with no Accessibility permission: `cp /bin/echo /tmp/x && codesign --force -i com.dganesh.zones --sign "Zones Dev" /tmp/x`. 3) `codesign -v -R='identifier "com.dganesh.zones" and certificate leaf = H"22a4d61ce3f62fd9d543f7ac1a8102ea2f952476"' /tmp/x` exits 0: the arbitrary binary satisfies Zones.app's designated requirement and gets the Accessibility grant made to Zones.
- Fix hint (verifiers kept it 2/3): Do not ship a fixed password: generate a random one per machine and keep it out of the repo (or store it only in the login keychain). Let the keychain auto-lock (set-keychain-settings -t <seconds> -l) and lock it again after each build. Drop the blanket codesign: partition entry so a signing prompt appears. Add the trust-of-a-local-root risk to ADR-0025 and to a --remove step that also removes the trust setting.
