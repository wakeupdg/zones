# One onboarding window; poll AXIsProcessTrusted; badge and re-onboard on revocation

First launch shows one window explaining Accessibility with a button that opens the System Settings pane; Zones polls `AXIsProcessTrusted` every second until granted. If the grant is revoked later, the menu-bar icon shows a badge and the window returns.

## Amendment 2026-10-24 (LOCKED-SPEC challenge C5)

Polling `AXIsProcessTrusted` cannot detect revocation of a running process (research: event-taps-tcc). The 1 s trust poll therefore runs only in the notGranted, revoked and needsRelaunch states; in granted it stops and a single 5 s health tick runs instead. Revocation is derived from runtime signals: an apiDisabled result from any Accessibility call or a nil event tap moves granted to suspect; a successful tap recreation plus one trivial Accessibility read returns to granted, otherwise after 3 s the state is revoked, which badges the icon, brings the onboarding window back, unregisters the window hotkeys and drains Enhanced UI. In revoked with the probe reading true, three failed tap recreations over 10 s move to needsRelaunch, the only state that offers "Quit and Reopen"; with the probe reading false the state stays revoked and never offers the button, since relaunching into an untrusted app would not help. A revocation heartbeat (a trivial Accessibility read folded into the health tick) is enabled only if SPK-006 proves macOS delivers the signal. On the launched-at-login path no window appears in any state; the badge and a "Grant Accessibility" menu item stand in for it.
