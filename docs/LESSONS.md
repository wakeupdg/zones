# LESSONS (curated; 40 lines max; one line per tool quirk or repeated mistake)
<!-- Add one line per lesson. Delete a line when a script or hook now enforces it. -->
- Run builds and tests through `scripts/q.sh`; the PreToolUse hook rewrites bare `swift build|test` and `xcodebuild` (verified live; look for `[q.sh] exit=`).
- Spend hook: a subagent in the main checkout logs under `docs/tickets/_subagents/`; only worktree agents on `ticket/<id>` update `tokens_spent`.
- Read files by line range (`sed -n 'a,bp'`); never cat a whole directory or a generated .xcodeproj.
- macOS has no `flock`; use a `mkdir` lock for shared files such as `graph.json`.
- `swift test` cannot drive AppKit UI; keep window/overlay code behind protocols so logic packages test headless.
- Ticket agents never edit `docs/tickets/graph.json`; only the orchestrator does (the hook updates `tokens_spent`).
- Keep `ticket/<id>` branches after merge; `check-state.sh` uses them to prove a `done` ticket is in `integration`.
- swift-testing `--filter Suite.name` runs 0 tests (exit 0, only a warning) when the `@Test` is a free function; an AC verify command that names `GeneratorTests.x` needs the test inside `@Suite struct GeneratorTests`.
- JSON goldens under Tests/<Target>/Fixtures/ load fine via `#filePath` but SwiftPM prints "found N file(s) which are unhandled" on every build; it is a package-manifest warning, not a swiftc one, so `treatAllWarnings(as: .error)` does not fail the build (T10 review, 2026-10-24).
- Review worktrees: the builder holds `ticket/<id>` in `.zones-worktrees/<id>`, so add a throwaway with `git worktree add --detach .build/review-worktrees/<id>-<lens> ticket/<id>` (unique per reviewer, never under /tmp, which does not persist between a subagent's Bash calls); `git worktree remove --force` it afterwards.
- Merge logs live in `.build/merge-logs/<id>.*.log`; `scripts/merge-ticket.sh` exit codes: 10 rebase, 11 build, 12 tests, 13 xcodebuild, 14 merge, 15 check-state.
- `swift test --filter` takes a regex, so `--filter 'SuiteA|SuiteB|SuiteC'` runs several suites in one build+run instead of one invocation per suite (T13 review, 2026-10-24).
- AC-style verify commands of the form `cmd 2>&1 >/dev/null | grep -c X` double-count under zsh (MULTIOS is on by default: stdout is tee-d into the pipe as well as /dev/null); run them with `bash -c` to get the real stderr-only count (T38 review, 2026-10-24).
- Under zsh a bare word starting with `=` (for example `echo ===== TEST` as a section marker in a chained command) is `=cmd` expansion and aborts the whole chain with `==== not found`; use `echo "-- TEST"` or quote the marker (T13 review, 2026-10-24).
- `FakeWindowSystem` scripted `.timedOut` answers do not advance `FakeClock` (only `latency` does), so `now` captured before a write sequence equals the clock after it; cooldown tests must `clock.advance` themselves (T15 review, 2026-10-24).
- Under zsh an unquoted `grep -r --include=*.swift` dies with `no matches found` (the glob is expanded by the shell, not grep) when the cwd holds no .swift file; quote it: `--include="*.swift"` (T15 review, 2026-10-24).
- `scripts/q.sh swift test` on the whole suite shows only the last 60 lines (`Q_LINES`), so early suites' per-test lines (and the AC-named tests you need to see) scroll off; confirm a named test ran with `--filter Suite.name` or `Q_LINES=400`, not from the tail alone (T19 review, 2026-10-24).
- Parallel reviewers of one ticket share `.build/review-worktrees/<T>`: `git worktree add` can print `fatal: already exists` yet leave a registered checkout, and a sibling's `worktree remove --force` can pull it mid-run; `git worktree list` before add and before remove, and treat `is not a working tree` on remove as already cleaned (T24 review, 2026-10-24).
- Under zsh `${PIPESTATUS[0]}` expands to nothing (the array is lowercase `pipestatus`, 1-based); when chaining `scripts/q.sh ... | tail`, read the exit from the `[q.sh] exit=N` line or `${pipestatus[1]}` (T25 review, 2026-10-24).
