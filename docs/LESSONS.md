# LESSONS (curated; 40 lines max; one line per tool quirk or repeated mistake)
<!-- Add one line per lesson. Delete a line when a script or hook now enforces it. -->
- Run builds and tests through `scripts/q.sh`; the PreToolUse hook rewrites bare `swift build|test` and `xcodebuild` (verified live; look for `[q.sh] exit=`).
- Spend hook: a subagent in the main checkout logs under `docs/tickets/_subagents/`; only worktree agents on `ticket/<id>` update `tokens_spent`.
- Read files by line range (`sed -n 'a,bp'`); never cat a whole directory or a generated .xcodeproj.
- macOS has no `flock`; use a `mkdir` lock for shared files such as `graph.json`.
- `swift test` cannot drive AppKit UI; keep window/overlay code behind protocols so logic packages test headless.
- Ticket agents never edit `docs/tickets/graph.json`; only the orchestrator does (the hook updates `tokens_spent`).
- Keep `ticket/<id>` branches after merge; `check-state.sh` uses them to prove a `done` ticket is in `integration`.
- swift-testing `--filter Suite.name` runs 0 tests (exit 0, only a warning) when the `@Test` is a free function; an AC verify command that names `GeneratorTests.x` needs the test inside `@Suite struct GeneratorTests`.
- JSON goldens under Tests/<Target>/Fixtures/ load fine via `#filePath` but SwiftPM prints "found N file(s) which are unhandled" on every build; it is a package-manifest warning, not a swiftc one, so `treatAllWarnings(as: .error)` does not fail the build (T10 review, 2026-10-24).
- Review worktrees: the builder holds `ticket/<id>` in `.zones-worktrees/<id>`, so add a throwaway with `git worktree add --detach .build/review-worktrees/<id>-<lens> ticket/<id>` (unique per reviewer, never under /tmp, which does not persist between a subagent's Bash calls); `git worktree remove --force` it afterwards.
- Merge logs live in `.build/merge-logs/<id>.*.log`; `scripts/merge-ticket.sh` exit codes: 10 rebase, 11 build, 12 tests, 13 xcodebuild, 14 merge, 15 check-state.
- `swift test --filter` takes a regex, so `--filter 'SuiteA|SuiteB|SuiteC'` runs several suites in one build+run instead of one invocation per suite (T13 review, 2026-10-24).
- AC-style verify commands of the form `cmd 2>&1 >/dev/null | grep -c X` double-count under zsh (MULTIOS is on by default: stdout is tee-d into the pipe as well as /dev/null); run them with `bash -c` to get the real stderr-only count (T38 review, 2026-10-24).
- Under zsh a bare word starting with `=` (for example `echo ===== TEST` as a section marker in a chained command) is `=cmd` expansion and aborts the whole chain with `==== not found`; use `echo "-- TEST"` or quote the marker (T13 review, 2026-10-24).
- `FakeWindowSystem` scripted `.timedOut` answers do not advance `FakeClock` (only `latency` does), so `now` captured before a write sequence equals the clock after it; cooldown tests must `clock.advance` themselves (T15 review, 2026-10-24).
- Under zsh an unquoted `grep -r --include=*.swift` dies with `no matches found` (the glob is expanded by the shell, not grep) when the cwd holds no .swift file; quote it: `--include="*.swift"` (T15 review, 2026-10-24).
- `scripts/q.sh swift test` on the whole suite shows only the last 60 lines (`Q_LINES`), so early suites' per-test lines (and the AC-named tests you need to see) scroll off; confirm a named test ran with `--filter Suite.name` or `Q_LINES=400`, not from the tail alone (T19 review, 2026-10-24).
- Under zsh `${PIPESTATUS[0]}` expands to nothing (the array is lowercase `pipestatus`, 1-based); when chaining `scripts/q.sh ... | tail`, read the exit from the `[q.sh] exit=N` line or `${pipestatus[1]}` (T25 review, 2026-10-24).
- Tap lifecycle is testable without a live tap: `CFMachPortCreate(nil,nil,nil,nil)` stands in for the tap and `CGEvent.tapEnable`/`tapIsEnabled`/`CFMachPortInvalidate` tolerate it under `swift test` (T23 review, 2026-10-24).
- `swift file.swift` (immediate/interpreter mode) crashed swift-frontend on a 4-line scratch check; `swiftc -o bin file.swift && ./bin` ran the same file fine, so compile scratch checks instead of interpreting them (T27 review, 2026-10-24).
- To check a reviewer claim against a pure reducer, drop a scratch `@Suite` file into `Tests/<Target>/` of the review worktree (it sees ZonesTestSupport fakes and the test target's own harness classes), run `scripts/q.sh swift test --filter ScratchSuite | grep MARKER` since `print` lines land in the q.sh tail, and delete it with the worktree; this is how T20's duplicate trust-poll after wake was confirmed (T20 review, 2026-10-24).
- SwiftPM does not enforce same-package module imports: `Tests/ZonesLayoutTests/EditorModelTests.swift` imports `ZonesWindowing` although `Package.swift` lists only ZonesLayout/ZonesCore/ZonesTestSupport for that test target, and `swift test` built and passed anyway because all modules land in one `.build/debug/Modules`; grep test imports against the manifest, do not trust a green build to catch a missing dependency (T30 review, 2026-10-24).
- `xcodebuild -quiet ... test` hides the per-test result lines, so the `scripts/q.sh` tail shows only "Testing started" and `exit=0` with no proof the named tests ran; rerun without `-quiet` with `Q_LOG=<file>` and grep the log for `✔ Test name()` / `Test run with N tests` (T31 review, 2026-10-24).
- This package compiles test targets with unused-value diagnostics as errors (`error: initialization of immutable value ... was never used [#no-usage]`), so a scratch `@Suite` with one leftover `let` fails the whole `swift test --filter` build instead of warning; strip unused lets before running a review scratch (T39 review, 2026-10-24).
- Under zsh `git show $R:App/File.swift` with an unbraced variable treats `:A` (and `:p`, `:h`, `:t`...) as a history modifier on `$R`, giving `ambiguous argument ...T33pp/File.swift`; write `"${R}:App/File.swift"` (T33 review, 2026-10-24).
- `git diff integration...ticket/TNN` hides files integration gained after the merge-base (T33 App/StatusItemController.swift vs T36 App/Composition/StatusItemController.swift): run `git merge-tree --write-tree integration ticket/TNN` and `git ls-tree -r <tree> --name-only` to see the merged tree; a same-named Swift type in one target is a redeclaration that no textual conflict reports (T36 UX review, 2026-10-24).
- `Zones.xcodeproj` is generated, not committed: in a fresh review worktree `scripts/q.sh xcodebuild ... test` fails with `Zones.xcodeproj does not exist` (q.sh exit=66) until `xcodegen generate` is run there first; with `-quiet` a green run prints only `Testing started` and `[q.sh] exit=0`, so read the exit line, not a test count (T36 review, 2026-10-24).
- Xcode DerivedData is keyed by project path, so `ls -t ~/Library/Developer/Xcode/DerivedData/Zones-*/Logs/Test/*.xcresult | head -1` can return a sibling worktree's bundle (it returned T35's during the T34 review); map the dir via `/usr/libexec/PlistBuddy -c "Print :WorkspacePath" <dir>/info.plist`, then `xcrun xcresulttool get test-results summary --path <that .xcresult>` gives the per-suite pass count a `-quiet` xcodebuild run never prints (T34 review, 2026-10-24).
- Review worktrees are shared per ticket and peers add/remove them mid-run: name yours with a lens suffix under `.build/review-worktrees/<id>-<lens>`, `git worktree list` before add and remove, `rm -rf` a stale unregistered dir, start shell chains with `set -e` and address the worktree with `git -C "$W"` and absolute paths so a failed `cd` never runs commands in the main checkout (T24/T30/T33/T39 reviews, 2026-10-24).
- Reviewing a ticket already merged into integration: `git diff integration...ticket/<id>` is empty; diff against the merge first parent (`git diff integration^1...ticket/<id>`), and use `git merge-tree --write-tree integration ticket/<id>` + `git ls-tree -r <tree>` to see same-named types two branches both added (T36/T39 reviews, 2026-10-24).
- `swift test --filter` is an unanchored regex over `Suite/testName`: `'A|B|C'` runs several suites in one build, `Suite.table` also runs `tableTie`, and a bare method name matches `nameCore`; anchor with `$` or `\(` when one test is meant (T13/T28/T37 reviews, 2026-10-24).
- `xcodebuild ... test -only-testing:AppTests/<SuiteName>` does filter a Swift Testing `@Suite struct` (ran exactly 1 test in ~1 min vs the full AppTests run), so red/green checks on one new AppKit test are cheap; remove the fix lines with `sed -i ''` in the review worktree to prove red (T43 review, 2026-10-24).
- A plain `NSView` with `setAccessibilityElement(true)` + role `.button` still reports `isAccessibilityEnabled() == false` (VoiceOver says "dimmed") and `focusRingMaskBounds == .zero` (no keyboard focus ring); override both on custom controls; checkable with a 5-line `swift file.swift` probe, no xcodebuild (T42 review, 2026-10-24).
- In-process AX walk from `NSWindow` down stops at `NSHostingView` (its children are an `NSAccessibilityReparentingCellProxy`, not the SwiftUI tree), so a root-down walk finds 0 hosted NSViews; prove reachability with `field.accessibilityParent()?.accessibilityChildren()` containing the field instead (T42 review, 2026-10-24).
- `grep -rn 'import ApplicationServices' Sources` (the QA-2.9 repro) also hits doc comments that mention the import (e.g. Seams/WindowHandle.swift after T51), so a re-verifier sees a false offender; anchor it as `grep -rnE '^[[:space:]]*(@preconcurrency[[:space:]]+)?import[[:space:]]+ApplicationServices'` like hygiene-gate.sh does (T51 review, 2026-10-24).
- `xcodebuild test -only-testing:AppTests/Suite/testName` (no parentheses) on a Swift Testing `@Test` matches nothing yet exits 0 with "Test run with 0 tests ... passed"; filter by suite (`AppTests/Suite`) or check the test count line (T50 review, 2026-10-24).
