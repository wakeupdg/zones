# Round 1 critique — maintainer persona

Attacker: long-term maintainability. Lens: can a fresh agent build it from the ticket, can a test prove it without a GUI, will it still be true in five years, does it contradict a locked ADR or the glossary.

## Attacks on power-user

1. **Focus Template as `inert` leaves (Implementation Decisions, Layout model; C4).** Wrong: ADR-0003 says every leaf is a Zone, ADR-0004 numbers every Zone, CONTEXT defines a Zone as a region a window can snap into. An `inert` leaf is a leaf that is not a Zone, so every property test stated later ("numbering is a bijection onto 1..N", "hit-test maps every point to exactly one zone or nearest") needs an exception clause, and the Overlay, HitTester, SpanUnion and editor each grow an `if inert` branch forever. Fix: Focus is a 20/60/20 three-column tree whose center is Zone Number 2 (no new concept), or a decision ticket amends ADR-0005 before the Templates ticket. Never a per-leaf flag.
2. **Merge by re-treeing (US-080, US-081, C3, Layout model).** Untestable as written: "expressible as a split tree, recomputed by a re-treeing function" names an algorithm nobody has specified, and the draft's own open question admits it may not be simple enough for v1. The failure reason `notExpressible` cannot have a decision table until the algorithm exists. It also contradicts ADR-0003 ("merge = collapse a node into one leaf") without the ADR text being amended. Fix: v1 merge is sibling-only per the ADR; non-sibling rectangular merge is a spike ticket that must deliver the algorithm plus a golden table of accepted and rejected unions before any story depends on it.
3. **Whole-point rounding inside `resolve` with "the last Zone absorbs rounding".** Hurts users and maintainers: on a 2x Display half-points are legal, so rounding to whole points makes the Overlay and the Snap disagree by up to a point, and "last Zone absorbs" makes Zone widths depend on traversal order, which breaks the "numbering is invariant under scaling" property the same draft asserts. Fix: `resolve` stays in CGFloat points and tiles exactly; rounding happens once, at the AX write boundary, in the single ConversionUtility, and the tiling property test runs on unrounded output.
4. **`WindowRecord { key: WindowKey (pid + AX element hash) }` in ZonesCore.** Contradicts ADR-0002 dependency direction: an AX-derived hash is a Windowing concept leaking into Core, and CFHash collisions between two windows of one app are not impossible. Fix: Core holds an opaque `WindowHandle` (Hashable, Sendable value); only the production adapter in Windowing knows it wraps an AX element and uses CFEqual for equality.
5. **`placement` cleared "when an observer reports a move or resize that Zones did not issue".** Untestable and racy: Zones' own write fires the same notification, so the registry must correlate notifications with in-flight writes under a 250 ms timeout; mis-correlation either strands a stale placement or wipes a good one. Fix: drop stored placement; cycle from the Zone whose rect best matches the current frame (platform draft does this). One rule, no race, pure function.
6. **Span clears on Span Modifier release and re-press (US-034); Drag Session text repeats it.** Hurts users: a 50 ms slip of the Control key throws away a three-Zone sweep. ADR-0008 says accumulation happens while the modifier is down; it says nothing about clearing. Fix: release freezes the set, re-press continues accumulating; the one escape is releasing the Activation Modifier, which already returns to `moving` and clears the set. Reducer test: release-and-re-press preserves the set.
7. **US-061 "include Control or Option" versus ShortcutStore "requires Control or Command".** Contradiction inside one draft. Research (event-taps-tcc) says defaults must include Command or Control; Option-only is the broken case. Fix: the validator rule is "contains Command or Control"; rewrite US-061 to match and add the rejection test.
8. **`WriteResult = applied | clamped | refused(reason)` with no timeout or dead-element case.** The draft's own unresponsive-app rule has nowhere to come from: a timeout must be smuggled through `refused` and pattern-matched on an AXError code outside the actor. Fix: `applied, clamped, refused(code), timedOut, elementGone`; the cooldown keys only on `timedOut`; eviction keys only on `elementGone`.
9. **Performance stories without a test (US-017 one frame, US-115 50 ms, US-116 under 1 percent CPU, Overlay arm under 4 ms).** Untestable on the build machine and not falsifiable in a bug report. Fix: keep the numbers as targets in Implementation Decisions, add headless budget tests that are deterministic (allocation count zero on the hot path, reducer throughput on synthetic events with a generous bound), and put CPU and frame pacing on the manual Instruments checklist.
10. **US-105 (Finder Shift-click multi-select still arms).** Not Zones' behaviour to promise: a listen-only tap never swallows the event, so Finder sees Shift regardless; what the story really wants is "the tap is listen-only", which is a configuration assertion. Fix: replace with a maintainer acceptance criterion on the InputSource ticket: the production tap is created listen-only and the test asserts the option.
11. **US-114 (Overlay modifier hint that disappears after three Spans).** Scope creep and hot-path risk: a counter in Preferences, text layout on the Overlay during a drag, and a feature absent from the BRIEF MVP list. Fix: move to Out of Scope for v1; the cheat sheet (US-113) covers discoverability.
12. **Import semantics (US-097, US-098, Persistence).** Missing Replace: every import grows the list, so a user restoring a backup after a bad edit cannot get back to exactly the backup, and renamed collisions ("Columns 3 2") accumulate. "Export one Layout" also implies a partial document the stated shape does not model. Fix: Merge or Replace on import; one document shape with both arrays optional and validated as a whole; any failure leaves disk untouched.
13. **Template picking in the menu has no Layout identifier.** Assignment is `DisplayUUID: LayoutID`, Templates are read-only and not in layouts.json, yet the menu lets the user assign a Template. Unspecified: does picking create a Layout, and what identifier does the default Priority Grid Assignment carry? Fix: built-in Layouts carry deterministic identifiers derived from template name and count; they are generated at load, never persisted, and may appear in assignments.json by identifier. (This gap exists in all three drafts; see Steal list.)
14. **Unresponsive cooldown "5 seconds" as a literal in prose.** Platform draft says 10 s. Neither is tested or owned. Fix: one named Clock-driven constant in ZonesWindowing with a fake-Clock test; the value is a ticket decision, not spec prose.
15. **`EditorState { displayKey, selection, dirty, undo, redo }` tested in ZonesLayout.** Puts UI concerns (selection, Display identity, dirty flag) into the pure layout package, so ZonesLayout now knows about Displays. Fix: ZonesLayout owns a draft Layout plus a command list with undo and redo; selection, dirty and displayKey live in the App view model and are not unit tested.
16. **1 Hz resync "while any WindowRecord has a placement" with purpose undefined.** It wakes the process every second for as long as one window is snapped, which is most of the day for the persona, and contradicts US-117. Fix: evict on the destroyed notification and on `elementGone` at next use; no periodic sweep in v1.

## Attacks on platform

1. **Permission state machine: `Suspect -> Revoked (poll false ...)` and `Revoked -> NeedsRelaunch (poll returns true again)`.** The draft's own Challenge 1 cites research that `AXIsProcessTrusted` does not go false for a running process after revocation, so "poll false" never fires and "poll returns true again" has nothing to return from. The 5 s poll while granted is therefore pure wakeups. Fix: revocation is derived only from runtime signals (nil tap, unrecoverable tap-disabled, apiDisabled); `Revoked` always offers Relaunch; no poll while granted.
2. **Diagnostics = last 10 SnapRecords plus permission and tap transitions.** Too thin to act on a bug report: no Displays and frames, no Assignments, no Preferences, no skip reasons ("why did my window not get an Overlay" is the top support question). Fix: one "Copy Diagnostics" text block with version, macOS, permission and tap state, DisplaySnapshots, Assignments, Preferences, and the last ~200 events including every ExclusionPolicy skip reason. Still no titles.
3. **Enhanced UI recovery file written before every frame write (US-116, Cross-cutting rules, Launch step 1).** Hurts the hot path (disk I/O per Snap) and is unsafe: pids are reused after reboot, so "any pid listed and still running" can flip Enhanced UI on an unrelated app. It is also a second persisted format with no version. Fix: in-memory set of pids with EUI turned off, restored in a defer, on Quit, and on entering `Revoked`; the crash-mid-write case is a v2 hardening ticket that keys on bundle identifier plus process start time if it is ever built.
4. **OriginalFrameRegistry with a 1 Hz sweep while non-empty.** Every second it issues an AX read per remembered window, against possibly hung apps, with 250 ms timeouts stacking on the single WindowActor. Fix: evict on `uiElementDestroyed` and on `elementGone` at the next touch; no sweep.
5. **`WindowHandle` is the CFHash of the AX element plus pid.** A hash is not an identity; collisions are rare but the failure is silent (Restore writes one window's frame onto another). Fix: an opaque handle that wraps the element, `==` via CFEqual, `hash` via CFHash; the hash is never the key by itself.
6. **Stories that promise unverified platform behaviour (US-029 Space switch mid-drag, US-031 wake, US-079 Stage Manager, US-083 identifier change recovery).** Research marks Space coverage and post-wake behaviour [Unverified]; Stage Manager is unresearched; US-083 is a new reconciliation UI absent from the BRIEF. None can be tested headless or promised today. Fix: US-029, US-031 and US-079 become manual checklist items gated by spikes 6, 11 and 12; US-083 moves to Out of Scope with a note that assignments.json keeps presentation names so a future UI has data.
7. **US-111 (edit a Layout for a detached Display at its last known size) with no stored frame.** `AssignmentsDocument` carries `displayNames` only, so the feature has no data. Fix: either add `lastVisibleFrame` per DisplayKey to the document (bumping the version) or drop the story; do not leave a story the data model cannot satisfy.
8. **Span freeze (US-038, US-052) versus `Armed(highlight = zone under cursor)`.** If the Span is frozen and the cursor moves to a Zone outside it, the state machine highlights the cursor Zone while the drop uses the Span; the Overlay lies. Fix: highlight is the Span rect when the set is non-empty, else the Zone under the cursor; reducer invariant test: the highlighted set always equals the set a mouse-up would snap to.
9. **`Pressed --dragged & frame != frame0--> Moving`.** Any frame change, including an edge-resize with Shift held, becomes `Moving` then `Armed` and snaps a window the user was resizing. Fix: `Moving` requires origin changed with size unchanged within tolerance; size change with origin fixed ends the session (power-user US-027 gets this right).
10. **ADR-0009 policy baked into LayoutEngine (`hitTest` "expands Gap and Margin to the nearest Zone").** If the decision ticket on ADR-0009 goes the other way, the pure layout package changes and every hit-test property test is rewritten. Fix: HitTester returns facts, `zone(n) | nearest(n) | none`; the Drag Session reducer applies the policy. One place to flip.
11. **No Challenge entry for ADR-0018 although US-087 and SnapService deviate from it.** ADR-0018 skips windows whose size *or* position is not settable; the draft positions size-locked windows. That may be the right call (research agrees) but it is a silent deviation. Fix: add it to Challenges with the research citation so the synthesizer can decide once for all drafts.
12. **Template picker and default Assignment have no Layout identifier.** Same gap as power-user attack 13: `assignments: [DisplayKey: LayoutID]` cannot reference a Template unless built-in Layouts have identifiers. Fix: deterministic built-in identifiers generated at load, never persisted in layouts.json.
13. **HotkeyService and LoginItemService excluded from protocol seams.** Both are cheap to seam and both carry logic the draft wants tested (US-068 conflict surfacing, US-071 unbound command, US-093 toggle derived from status only, US-094 requiresApproval caption). Without fakes those stories are manual-only. Fix: protocols with scriptable fakes; the toggle derivation and the registration diff become table tests.
14. **Performance budget tests with absolute microsecond and millisecond bounds on CI.** Shared macOS runners make "hit test under 20 microseconds" flaky; a flaky gate gets disabled within a month. Fix: assert allocation counts (zero on the hot path) and relative budgets on CI; absolute timing runs locally and on the release checklist.
15. **Nil display UUID "retry after the next event".** If no further topology event arrives the Display never receives an Assignment and the default is applied every drag without being recorded. Fix: Clock-driven retry (fake-Clock tested) and the research fallback key (vendor, model, serial) when the UUID stays nil.
16. **US-090 "Exclude <App>" names both "frontmost app" and "window under the cursor".** Ambiguous on a menu click (the cursor is over the menu). Fix: the item uses the frontmost application captured when the menu opens; the label shows its name and the Exclusion stores its bundle identifier.

## Steal list (what the other drafts have that mine lacks)

From power-user:
- Tri-state hit result `zone | nearest | none` with the Restore-versus-Snap policy in the reducer, not in layout math.
- Span set scoped to one Display and cleared on crossing a Display boundary.
- A second mouse-down during a Drag Session is ignored; the Overlay hides on mouse-up before any AX write begins.
- Imported Assignments for Displays not present stay dormant and apply when that Display appears.
- Cycle start rule when the window matches no Zone: Right starts at Zone 1, Left at the last Zone.
- Settings General shows permission state and tap health; the menu-bar icon badges for either.
- Templates are read-only; duplicating one creates a custom Layout with a fresh identifier.
- Shortcut recorder: a registration failure leaves the previous chord active; every action may be unbound.
- Idle budget stated as a rule: zero timers while idle; polling only during a Drag Session.

From platform:
- Launch sequence with the status item created last so the menu never shows before state exists.
- Sleep and wake handling: re-validate the tap, force one TopologyChanged, order panels out.
- Span freeze on Span Modifier release; both modifiers held from the start arm and begin the Span immediately.
- Right and middle mouse buttons are ignored during a Drag Session.
- The keyboard path captures the Original Frame on the first Snap exactly like the mouse path.
- Shortcut re-registration is deferred until the current Drag Session ends.
- Restore clamps an Original Frame that is now off every Display onto the nearest Display.
- Backup before migration; coercion of invalid hand-edited preferences to defaults with a one-time notice.
- Enhanced UI pids tracked in memory and restored on Quit and on revocation (weakened from the file-based version).
- Headless budget tests for the hot path (allocation count, reducer throughput with generous bounds).
- Quit tears down the tap and panels; a "Grant Accessibility" menu item while not granted.
- `Suspect` as an intermediate permission state that confirms with a trivial AX read before badging.

Self-fix surfaced by the attacks (missing from all three drafts): built-in Layouts need deterministic identifiers so Assignments can reference a Template.
