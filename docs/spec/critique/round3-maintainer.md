# Round 3 critique — maintainer persona

Lens: will this still be healthy in five years. Small interfaces, every rule headless-testable, protocol seams around AX/CG/AppKit, data formats where illegal states are unrepresentable, failure detected where it happens, nothing on the menu-bar path that blocks, and tickets a fresh agent can build alone. Each attack quotes the story or section, says what breaks and for whom, and proposes a fix the synthesizer can lift. Judged against the locked ADRs, CONTEXT.md and the research Implications and Gotchas.

## Attacks on power-user

1. **Window service, "a small recovery record (pid, bundle identifier, process launch date) is written only when a toggle actually happened and cleared after".** A toggle happens on nearly every Snap, so this is a file write plus a file delete per Snap, on the WindowActor, inside the eight-call sequence the same draft budgets. Fix: the set of touched pids transitions from empty to non-empty once per launch; write the record on that transition only, asynchronously off the WindowActor, keyed by pid plus bundle identifier plus process launch date; delete it on clean Quit; never touch disk per Snap.

2. **Window service "frame polling at about 60 Hz" versus Performance "one CGWindowList lookup for the dragged window per dragged event".** Two sources of frame truth, which ADR-0006 forbids ("the mouse-down frame from the same source"), and both keep running through `moving` and `armed` where the frame is not needed: the highlight follows the cursor, and the Snap reads the frame once at mouse-up. Fix: one AX frame sample stream, running only in `pressed` until the move is confirmed or the press ends; zero per-event CGWindowList calls; one frame read at mouse-up for the no-op check. The WindowActor idles during the whole armed phase.

3. **Reducer, "`windowGone`, `tapLost`, `appUnresponsive` and `wake` in any state go to `idle`".** A frame sample that times out while `armed` kills a drag the user is in the middle of: the Overlay vanishes with the button still down and the drop does nothing, for an app the WindowServer is still happily moving. Fix: a `timedOut` sample ends `pressed` only (no Overlay has shown yet); in `moving` and `armed` nothing polls (attack 2), so the event cannot arise; the write at mouse-up reports `timedOut` and sets the cooldown.

4. **Input, ShortcutStore "warns on a built-in list (Mission Control, Spaces arrows, screenshot chords, Command+digit, Command+arrow)".** Mission Control and screenshot chords are user-remappable in System Settings, the list drifts with every macOS release, there is no public API to read the truth, and no test can assert it is right. It is a bug-report generator ("it warned about a chord I changed years ago"). Fix: drop the list. Keep the validator (Command or Control), duplicate rejection within Zones and the Carbon registration result inline. If a hint is wanted, make it one static sentence in the recorder ("Command+digit and Command+arrow are used by most apps"), not a table.

5. **Editor, "M merges with the sibling chosen by the next click".** A binary split tree gives every leaf exactly one sibling, so the second click is redundant, and a keyboard command completed by a mouse click is a modal state the view model must track and the tests must script. Fix: M merges the selected Zone with its sibling when that sibling is a leaf (or its same-axis chain neighbour); otherwise the editor shows the `notSiblings` hint. One key, one command, no mode.

6. **Layout model, `margin: Points?`, `gap: Points?` with nil meaning "use the Appearance defaults".** A custom Layout with nil Margin exports as nil and resolves differently on the importing Mac; golden fixtures for the document then depend on a Preferences value outside the document. Fix: nil never reaches disk or the export. Templates are generated at load from the defaults and never persisted; a custom Layout always stores numbers (Duplicate copies the current defaults in). An "inherit defaults" affordance in the editor, if wanted, resolves to numbers on Save.

7. **Persistence, `assignments.json` keyed by `DisplayKey` whose `unstable` case is "never persisted".** The type admits what the prose forbids; a future ticket that forgets the rule writes an unstable key and the collision bug ships. Fix: the document key type is a distinct `PersistentDisplayKey` holding only the UUID case; the decoder rejects any other kind as a validation failure; the in-session map for unstable keys is a separate type that cannot be encoded.

8. **Layout model, `grid` "every distinct edge coordinate is snapped once ... so neighbours keep sharing the edge".** With Gap greater than zero neighbours do not share an edge; the two edges on either side of a Gap round independently, so some Gaps come out one pixel wider than others and US-147 ("no one-pixel seams") fails on Columns 5 at 1x. Fix: round the dividers (the tree's split lines), not the Zone edges: each divider is snapped once to the backing grid, the Gap is rounded once to whole grid units, and the two neighbouring edges are divider minus floor(Gap/2) and divider plus Gap minus floor(Gap/2). Every Gap is identical in pixels, nothing depends on traversal order, and a property test asserts uniform pixel Gap at scales 1, 2 and 3.

9. **Templates, "Priority Grid as a vertical split 25/50/25", `SplitNode.split(axis: horizontal|vertical, ...)` with no definition of what the axis means.** Half the industry reads "vertical split" as a vertical divider (columns), the other half as stacked children (rows). ADR-0003 does not define it; three drafts and the glossary are silent; the first ticket author picks, the second flips Columns and Rows. Fix: one sentence in Implementation Decisions ("the axis names the direction along which the two children are laid out: horizontal places them side by side, vertical stacks them") and a golden test that Columns 2 yields two Zones with equal top edges.

10. **US-116 "invisible in Activity Monitor" and the idle budget "tap health check at 2 s while granted; permission heartbeat at 5 s while granted".** "Invisible in Activity Monitor" is untestable; two idle timers where one suffices doubles the wake-ups the story is about. Fix: one 5 s health tick while granted (tap-enabled check plus the spike-gated heartbeat read); a headless test with the fake Clock asserts, per permission state, exactly which timers are scheduled and nothing else. That test is the story's acceptance.

11. **US-022 "if the overlay spike proves the panel is visible there".** A story whose acceptance depends on a spike verdict cannot be closed by a ticket and cannot be tested until the spike runs. Fix: write the promise unconditionally as "where macOS allows the drop", put the expected result on the manual checklist row for the full-screen Space, and let the spike answer the Open question; the ticket that implements the panel has a fixed acceptance either way.

12. **Testing, "App target: SwiftUI views are smoke-built by the CI xcodebuild step; no logic beyond wiring".** Nothing enforces the second clause; in six months an AX read lands in a view model because it was convenient. Fix: a CI import gate: `import ApplicationServices` (and the CG window-list API) is permitted only in the production adapter files of ZonesWindowing; the App target imports neither. Mechanical, one grep, zero false positives.

13. **US-009 and Settings section, "the Display whose menu bar I clicked".** With "Displays have separate Spaces" off there is one menu bar, so the rule is undefined for every other Display; ADR-0019 says "the display under the cursor", which covers both modes with one rule because the cursor is on the menu bar you clicked. Fix: use the ADR wording in the story and the section. (Platform raised this in round 2; it is still in the draft.)

14. **US-041 "because the size is written again after the position".** A story that explains ADR-0022's write order in the user's voice ties the story to a mechanism; if the order changes the story is wrong without being untrue. Fix: the story states the outcome ("lands at the Zone's size on arrival"); the mechanism lives in the Window service section.

15. **Reducer, "Both modifiers held before `moving` arm at once and start the Span from the first Zone entered".** When the cursor is already inside a Zone at the arming sample, "first Zone entered" is ambiguous: is that Zone a member, or only the next one the cursor enters? One reading highlights a Zone the drop does not include, breaking the draft's own invariant. Fix: the Span begins with the Zone under the cursor at the arming sample; a scenario test covers arming inside a Zone and arming on a Gap.

## Attacks on platform

1. **Permission state machine, "There is no separate relaunch state ... the relaunch button is always offered".** The trust probe is unreliable for detecting revocation, but when it reads false the grant is certainly absent, and "Quit and Reopen" then relaunches into an untrusted app, teaching the user that the button is dead. Fix: `Revoked` shows no relaunch button; `NeedsRelaunch` is entered only when the probe reads true and tap creation has failed three times over ten seconds on the Clock, and shows the button with its one-sentence explanation. Two states, one fixture test each.

2. **DisplayTopology, `DisplayKey = uuid | hardware | unstable` with the hardware key "persisted as `hardware` only when unique among attached Displays".** Persistence that depends on which other Displays happen to be attached today: unique at the desk with one panel, colliding at the desk with two, so the saved Assignment flips between them on the next arrangement. A third key kind also triples the decoder, migration and topology test surface. Fix: two kinds. A hardware fallback is `unstable`, accepts an in-session Assignment held in memory, is never persisted, and is explained in the Layouts pane; recovery of a changed identifier is the user-driven Copy Assignment (US-141), which the draft already has.

3. **Stores, `AssignmentsDocument { assignments, dormant, displays }`.** Two maps for one concept create an invariant (a key in both, or in `dormant` while attached) that import, Merge, Replace and every migration must police, and a derived fact (dormancy) is stored. Fix: one `assignments` map keyed by `PersistentDisplayKey`; a key absent from the current snapshot is dormant at read time; `displays` keeps its presentation record. Fewer states, no invariant to test.

4. **SnapService "stores `LastSnap` on the handle" versus OriginalFrameRegistry `Entry { originalFrame, lastSnap? }`.** Two owners for one record, and `WindowHandle` is an opaque Hashable value in ZonesCore that cannot carry mutable state. Fix: the registry is the single owner of both the Original Frame and the last Snap record; SnapService returns the result and the registry records it.

5. **InputTap, "The 5 s health tick checks `CGEventTapIsEnabled`; re-enable is rate-limited".** When macOS disables the tap mid-drag no mouse-up can arrive, so the reducer sits in `Armed` with the Overlay up for as long as five seconds before the tick notices. The tap-disabled conditions are delivered as event types to the tap callback itself. Fix: handle the disabled events in the callback: re-enable there under the rate limiter and emit `tapLost` immediately when the limit is hit; the 5 s tick is a watchdog for the case where the callback never runs.

6. **WindowActor "Frame polling at about 60 Hz" in `Pressed`, `Moving` and `Armed`, and reducer "`any --app unresponsive--> Idle`".** Same defect as power-user attack 2 and 3: the frame is needed only to confirm the move, polling through the armed phase burns AX round trips on the serial actor, and a timeout mid-drag kills a live session. Fix: poll only in `Pressed`; a `timedOut` sample there ends the press as `skip(unresponsive)`; nothing polls afterwards; one frame read at mouse-up.

7. **ExclusionPolicy phase 1 "at mouse-down from CG facts only: ... `unresponsive`, `ambiguousMatch`".** Ambiguity is, by the draft's own WindowResolver and US-023, settled by the first frame sample, not known at mouse-down. Listing it as a phase-1 fact puts a reducer outcome into a pure policy's input and the table test cannot construct it. Fix: `ambiguousMatch` is a reducer transition (three returned samples without exactly one mover) that emits the skip log; the policy's inputs are facts only.

8. **Menu-bar shell, "activate the app on open and return it to accessory behaviour on close".** Returning to accessory behaviour implies the activation policy was changed to regular, which shows a Dock icon for the life of the Settings window and flashes it on every open, against ADR-0019. Fix: the policy stays accessory; activating the app and making the window key is enough for an accessory app to receive focus; nothing toggles on close.

9. **Launch sequence step 2, "register window hotkeys too, gated at dispatch by PermissionState".** A registered Carbon hotkey is swallowed system-wide whether Zones can act or not; while untrusted, Control+Option+1 through 9 are stolen from every other app for nothing. Fix: register window hotkeys on entering `Granted` and unregister on leaving it; editor and Settings hotkeys stay registered in every state. A registration-diff table test covers both transitions.

10. **US-038 and reducer, "`span up, cursor hits zone outside union(span)` -> `span = {zone}`".** The drop target changes with no key pressed: the user releases the Span Modifier to drop, drifts one point past the union on a 120 Hz Display, and a three-Zone Span silently becomes one Zone. The reducer must also carry a geometric region the user cannot see. Fix: release freezes the set, re-press resumes adding, Activation Modifier release clears; a drop then depends only on key state and the highlighted set, which the invariant already guarantees. Two of three drafts hold this rule.

11. **Challenge 4 and SnapService, "a hung app costs up to 2 s on the WindowActor".** The actor is serial, so those two seconds also stall the next drag's frame sample on any other app and every window shortcut: head-of-line blocking for the whole system from one hung app. Fix: the first `timedOut` in a write sequence stops the sequence (only the Enhanced UI restore still runs), so the worst case is two timeouts, half a second; combined with attack 6 the actor is idle during drags, so the stall cannot hit a live gesture.

12. **LayoutEngine "minimum fraction per axis (0.05)" versus 1/12 in the other two drafts, cooldown "10 s initial value" versus 5 s elsewhere.** Three drafts, two constants each; whichever the synthesizer forgets to reconcile becomes two sources of truth in code. Fix: name every tunable once (minimum fraction, cooldown, debounce, suspect window, retry count) in one constants section with a one-line rationale each; tests reference the names, never the numbers.

13. **US-091 "Zone color, opacity, Margin and Gap in Appearance" versus `Layout { margin: Points, gap: Points }` non-optional and `Preferences.appearance { color, opacity, labelsVisible }`.** Built-in Layouts are "generated at load" from no stated Margin and Gap, and the Appearance pane has no field to store them. Fix: `appearance` gains `defaultMargin` and `defaultGap`; built-ins are generated from them at load; custom Layouts store explicit values; Appearance says which Layouts follow the defaults.

14. **Reducer events include `hotkey` and "`any --hotkey(window command)--> same state (dropped, logged)`".** A hotkey is not a Drag Session event; routing it through the reducer couples shortcut dispatch to the reducer's event type, and every reducer test must now account for an event that never changes state. Fix: the dispatcher reads the reducer's idle flag and drops window commands itself with one log line; the reducer's event set stays what the gesture needs.

15. **WindowActor, "AX observers (destroyed, moved, resized) are registered on one dedicated thread".** Nothing consumes moved or resized: cycling uses the read-back comparison and no placement is invalidated by observers. Two dead subscriptions per snapped window are AX traffic and run-loop sources that leak when the forwarding breaks. Fix: observe `destroyed` only, plus the workspace app-terminated notification; moved and resized stay in the research notes until a story needs them.

16. **Out of Scope "Restoring Enhanced UI for apps a crashed Zones left changed" versus US-042 ("after every write even if the write fails") and US-116.** A crash during the write is the one path those stories do not cover, and the draft's own round-2 attack already named the safe key (bundle identifier plus process launch date). A record written once per launch on the empty-to-non-empty transition, off the hot path, closes the gap for a few lines. Fix: adopt it, or amend US-042 to say the crash case is excluded so a VoiceOver user is not promised more than the code does.

## Steal list

What the other drafts have that the maintainer draft lacked; all are folded into the revised maintainer draft.

From power-user:
- Rounding on dividers rather than Zone sizes, adapted so the Gap is rounded once and shared edges derive from the rounded divider (replaces "remainder to the last Zone").
- An unstable DisplayKey accepts an in-session Assignment held in memory, labelled "not saved" in the Layouts pane (US-154).
- A suspended Span stays drawn on its Display in a dimmer style while the live highlight follows the cursor (US-155).
- Cycling from a Span goes to the Zone after its highest member (US-158), via the last-Snap record.
- Assign from inside the editor in one click (US-086) and the `notSiblings` hint text (US-081).
- A named fixture set (3-Display arrangement with a 2x Display left and a 1x portrait Display above, a hung-app fake, a clamping fake, a size-locked fake, two serial-0 Displays).
- A one-page acceptance walk-through run per release, distinct from the per-area manual matrix.

From platform:
- Two-phase ExclusionPolicy: CG facts at mouse-down, AX facts on the first frame sample.
- AX observers on a dedicated run-loop thread forwarding value-type notifications to the WindowActor, with the open question on callback thread and sleep.
- A last-Snap record (Zone set, DisplayKey, read-back frame) used for cycling only while the current frame still matches it; no observer.
- "Reset and re-onboard" in General (US-143).
- Eviction of every handle of a pid on the app-terminated notification (US-114).
- One 5 s health tick while granted that folds the tap check and the gated heartbeat.
- The launched-at-login signal named (open-application event flag, read only inside the did-finish-launching callback).
- Zones beyond nine badged "no chord", never refused (US-110).
- Window shortcuts dropped while a Drag Session is in progress (US-142), implemented in the dispatcher.
- Zone Number labels with a contrasting outline independent of fill opacity (US-147).
