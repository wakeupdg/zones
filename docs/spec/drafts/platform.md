# Zones — platform correctness spec (draft, persona: macOS platform engineer, revised after round 3)

## Problem Statement

A person with one or more Displays wants windows to land in predictable rectangles without hand-resizing them. On macOS the tools that do this either need private APIs (fragile across OS updates, blocked by SIP), demand Screen Recording or Input Monitoring on top of Accessibility, or fall apart on real Macs: the grant silently vanishes after a rebuild or revocation, an unresponsive app freezes the menu bar, Chromium windows animate to the wrong place, Java windows refuse resizes, the Overlay never appears over a full-screen Space, a display unplug scrambles which Layout belongs where, and a 120 Hz drag stutters. The person does not care about any of this; they care that holding a key while dragging shows Zones and letting go puts the window there, every time, on every Display, after sleep, after a Display swap, and after they revoke and re-grant the permission.

## Solution

Zones is a menu-bar app that asks for exactly one permission (Accessibility), explains why, and notices when it is lost. During a Drag Session with the Activation Modifier held, a click-through Overlay on every Display shows the active Layout; the Zone under the cursor highlights; adding the Span Modifier accumulates Zones; releasing the mouse Snaps the window into the Zone or Span, reads back what the app actually accepted, and remembers the Original Frame so Restore works. Shortcuts move the focused window to Zone N, cycle, Restore, or open the editor and Settings. Every Display has its own Assignment keyed by a stable identifier so topology changes never lose a Layout. Zones sends nothing to another app until a Snap is armed, and every call it does make runs off the main thread with a short timeout, so a hung app can never hang Zones. Windows that cannot or should not move (sheets, popovers, full-screen windows, Zones itself, excluded apps) are skipped silently rather than half-moved. Every rule that decides what Zones does is a pure function over value types; the OS sits behind protocols with fakes.

## User Stories

Story ids are stable. Removed in round 2: US-070, US-079, US-083. New in round 3: US-148 to US-155.

### Permission and onboarding
- US-001: As a first-time user, I want one onboarding window that explains why Zones needs Accessibility and opens the exact System Settings pane, so that I grant it in under a minute.
- US-002: As a first-time user, I want Zones to notice the grant within a second without relaunching, so that onboarding dismisses itself and the menu-bar icon goes live.
- US-003: As a user, I want Zones to never ask for Screen Recording or Input Monitoring, so that I am not confused by extra prompts or privacy worries.
- US-004: As a user who revoked Accessibility while Zones ran, I want the menu-bar icon badged and the onboarding window back, so that I understand why dragging stopped working.
- US-005: As a user whose grant was lost, I want the returned onboarding window to offer both "Open System Settings" and "Quit and Reopen", with one sentence saying that a re-granted switch may need the relaunch, so that I am never left with a dead app that claims to be trusted.
- US-006: As a user whose event tap was disabled by the system (timeout or another process), I want Zones to re-enable it quietly and rate-limited, so that a transient hiccup does not end the feature.
- US-007: As a user launched at login, I want no onboarding or Settings window to appear when the grant is already present, so that login stays quiet.
- US-008: As a user on a Mac where the grant is missing at login, I want only the badge and a menu item "Grant Accessibility", so that a login-time window does not steal focus.
- US-009: As a developer, I want dev builds signed with a stable identity, so that rebuilding does not drop the Accessibility grant.
- US-010: As a user, I want Zones to treat a nil event tap as "not permitted" and show onboarding instead of crashing, so that permission problems are always recoverable.
- US-118: As a first-time user, I want onboarding to end with a one-page cheat sheet (hold Shift to see Zones, add Control to Span, Control+Option+N to send), so that I can use Zones before opening Settings.
- US-119: As a user, I want the General pane to show two status rows, Accessibility granted or not and event tap alive or dead, so that I can diagnose a dead drag in seconds.
- US-120: As a user who revoked the grant while Zones sat idle, I want the badge at the first failed call or tap signal, and within 5 s if the heartbeat spike proves the API-disabled signal arrives, so that the icon tells me before a failed gesture does where macOS allows it.
- US-143: As a user, I want a "Reset and re-onboard" action in General that returns Zones to the not-granted flow, so that I can recover from a confused permission state without deleting preferences.

## Implementation Decisions

### Module map (interfaces, not files)
- **PermissionMonitor** (MainActor). Owns `PermissionState`. Inputs: `AXIsProcessTrusted` poll (0.5 s while the onboarding window is visible, 1 s while not granted otherwise, never while granted), event-tap health, `apiDisabled` from any AX call, and, only if spike 14 passes, a 5 s heartbeat (one trivial AX read of the system-wide element on the WindowActor, one in flight, skipped during a Drag Session, folded into the single health tick). Heartbeat results feed only this monitor, never `AppHealth`. The trust probe is never a revocation signal. It is the only place that decides "revoked".
- **InputTap** (dedicated user-interactive thread). One listen-only session tap at tail-append for left mouse down/dragged/up and flagsChanged; other buttons are filtered at the source and never emitted. Emits value-type `PointerEvent { kind, location, flags(masked), timestamp, windowUnderPointer? }` over a bounded channel: `dragged` is newest-wins; down, up and flagsChanged are never dropped. The 5 s health tick checks `CGEventTapIsEnabled`; re-enable is rate-limited to 5 per minute with backoff; beyond that `tapLost`, badge, and an automatic retry every 30 s. Nil on create reports `tapUnavailable`. Acceptance criterion: the production tap is listen-only, so Zones never consumes a modifier or a click.
- **DragCoordinator** (MainActor). Runs the Drag Session reducer and executes its effects through OverlayController, WindowResolver and SnapService. Effects are values: `startMoveTracking(ids)`, `stopMoveTracking`, `resolve(windowID)`, `showOverlay(model)`, `updateHighlight(set | dimAll, suspended: Set?)`, `hideOverlay`, `snap(plan)`, `restore(handle)`, `log(event)`.
- **WindowResolver** (two halves). CG half, no IPC to any app: at mouse-down the CGEvent window field, then a front-to-back CGWindowList hit test (layer 0, own pid excluded, system agent bundles excluded), yields at most two candidate `(windowID, pid, bounds)` by z-order; more than two is `ambiguousMatch`. Movement is confirmed by polling `CGWindowListCreateDescriptionFromArray` for the candidate ids at about 60 Hz from the first `dragged` event, comparing to the mouse-down bounds from the same source (ADR-0006). AX half, on the WindowActor, only on the transition into `Armed`: map the moved window to an AX element by pid, equal size and nearest position among that pid's windows, with `AXUIElementCopyElementAtPosition` under the cursor as the tie-breaker; no unique match is `ambiguousMatch`, fail closed. A plain click or plain drag never reaches the AX half (US-151).
- **WindowActor** (serial actor). Every AX read and write. Per-app messaging timeout 0.25 s; process-wide 1 s at launch. Tracks `AppHealth { responsive | unresponsive(until) }` per pid; `timedOut` -> one immediate retry of the same call, then unresponsive for a Clock-driven cooldown (named constant, 10 s initial value). AX observers (destroyed) are registered on one dedicated thread with a running CFRunLoop and forward value-type notifications to the actor; the actor itself never owns a run loop source. Exposes `frame(of:)`, `isMovable(_:)`, `isResizable(_:)`, `isFullScreen(_:)`, `setFrame(_:to:)`, `role/subrole(of:)`, `heartbeat()`.
- **SnapService** (WindowActor). Protocol per ADR-0022: read EUI (skip the pair when the attribute is absent or already off); set off; size; position; size; read back position and size; restore EUI in a defer. The sequence aborts at the first `timedOut`: no further frame calls, only the EUI restore, pid marked unresponsive; the hung-app worst case is one timeout plus one retry, 0.5 s on the actor, never the main thread. Returns `FrameWriteResult = applied(actual) | clamped(actual) | refused(AXError) | timedOut | elementGone | noOp`. On `clamped` where actual size exceeds the Zone, exactly one follow-up position write aligns the top-left and keeps the window inside the visible frame. Skips size writes when size is not settable. A target equal to the current frame within tolerance returns `noOp` and records nothing. Each `applied` or `clamped` stores `LastSnap { zones: Set<ZoneNumber>, displayKey, frame: actual }` on the handle for cycling. Governed by `EnhancedUIPolicy = toggle | leave | auto` (default `toggle`; `auto` toggles only when the attribute reads on; no bundle lists). Enhanced UI safety: the pids whose EUI Zones turned off live in an in-memory set drained by the defer, on Quit and on entering `Revoked`; the first time an app is touched in a session, before its first EUI-off write, one record `{ bundleID, pid, processLaunchDate, priorValue }` is appended to a small recovery file (once per app per session, never per Snap); the file is deleted on clean quit; at launch, entries whose process still matches all three and whose prior value was on are restored, the rest discarded.
- **OverlayController** (MainActor). One panel per Display per ADR-0023; created at launch, kept forever, rebuilt only on `TopologyChanged`. Zone layers and label layers persist; an arm sets frames, colors and label text inside one CATransaction with actions disabled, so arming allocates nothing. `show(model)`, `updateHighlight(Set<ZoneNumber> | dimAll, suspended: Set<ZoneNumber>?)`, `hide()`. Two highlight styles from Appearance: active, and suspended-Span (dimmer; an outline under Reduce Transparency). Labels are drawn with a contrasting outline and the correct `contentsScale` per Display. Honors reduce motion and reduce transparency. Panels and layers are not accessibility elements. `hide()` runs before any Snap write is issued; panels are re-asserted front on `spaceChanged` if spike 6 shows new Spaces lose them. Displays whose active Space cannot receive a drop (spike 6) are left out of the arm snapshot and draw nothing.
- **DisplayTopology** (MainActor). Observes screen-parameters notification and the CG reconfiguration callback; debounces 200 ms; emits `TopologyChanged(before: [DisplaySnapshot], after: [DisplaySnapshot])`. `DisplaySnapshot { key: DisplayKey, frame, visibleFrame, scale, isMain, mirrorOf: DisplayKey?, separateSpaces: Bool, name }`. `DisplayKey = uuid(String) | hardware(String) | unstable(String)`: the CGDisplay UUID when present; a nil UUID is retried three times one second apart on the Clock (a late success emits `TopologyChanged` so consumers re-key), then the vendor-model-serial key is used and persisted as `hardware` only when unique among attached Displays, else `unstable`. An `unstable` key accepts an in-session Assignment held in memory, labelled "not saved" in the Layouts pane and usable from the menu picker; nothing is persisted for it. Mirror sets collapse to the mirror master (the member that mirrors nothing); its key is a real UUID, so Assignments made while mirroring persist normally.
- **LayoutEngine** (pure, ZonesLayout). Tree -> `[ZoneRect]` in normalized 0..1; `resolve(layout, visibleFrame, margin, gap) -> [CGRect]` in exact points, no rounding (apply surround if the Focus decision adopts it, then Margin at the outer edges and half a Gap per shared edge); `grid(rects, scale) -> [CGRect]` is the single rounding step: every distinct edge coordinate is snapped once to the backing grid (1 divided by scale) so neighbours keep sharing the edge, with no remainder and no order dependence; both the Overlay model and the Snap target come from the same `grid` output. `hitTest(point) -> zone(n) | nearest(n) | none` (facts only: `nearest` is inside the visible frame on Gap, Margin or surround, `none` is outside it; what the reducer does with each is policy), `union(zones) -> CGRect`, `zoneNumbers()` row-major with an epsilon on edges, template generators (Columns and Rows as a right-leaning chain whose k-th split of n uses ratio 1/(n-k+1); Grid as rows of columns; Priority Grid 25/50/25), edit operations. Validator enforces a minimum fraction per axis (1/12) and ratios strictly inside 0..1. Built-in Layouts (every Template at every supported count) are generated at load with identifiers derived from Template name and count and the Appearance default Margin and Gap; they are read-only, never written to layouts.json, and may be referenced from assignments.json; the default Assignment references the Priority Grid identifier.
- **CoordinateSpace** (pure). Exactly one converter between AppKit bottom-left and AX/CG top-left using the primary Display's frame height, and `display(for axRect)` by maximum intersection area, used only where there is no cursor (keyboard path, Restore clamp).
- **OriginalFrameRegistry** (WindowActor). `[WindowHandle: Entry { originalFrame, lastSnap? }]`. `WindowHandle` is an opaque Hashable, Sendable value in ZonesCore; the production box in ZonesWindowing wraps the AX element, equality is CFEqual, hashing is CFHash, and it is the single documented unchecked-Sendable type. Original Frame is written only when absent, on `applied` or `clamped`: on the mouse path it is the mouse-down bounds of the resolved window (converted once), on the keyboard path the read-back frame before the write. Entries are removed on a successful Restore, on `uiElementDestroyed`, on `invalidUIElement` or `elementGone` at the next touch, and on the NSWorkspace app-terminated notification for that pid. No periodic sweep. Restore of a frame intersecting no Display clamps it into the visible frame of the Display the window currently occupies.
- **ExclusionPolicy** (pure, two phases). Phase 1 at mouse-down from CG facts only: `ownProcess`, `systemAgent` (Dock, WindowManager, Notification Center, Control Center, loginwindow, UserNotificationCenter by bundle), `excludedBundle`, `unresponsive`, `ambiguousMatch`. Phase 2 on the transition into `Armed` from AX facts: `notStandardWindow`, `sheetOrPopover`, `systemDialog` (subrole systemDialog or systemFloatingWindow), `fullScreen`, `positionNotSettable`. Size-not-settable is not a skip; it becomes a position-only plan. Both phases run before any Overlay appears; every skip is logged and counted.
- **HotkeyService** (MainActor, behind a protocol with a scriptable fake). Carbon hotkeys for the commands; `Shortcut { keyCode, modifiers }` with a validator requiring Command or Control; `RecorderState = idle | recording | conflict(reason) | warning(reason) | failed(reason)`; duplicates within Zones are `conflict`; a Command-only or Command+Shift-only modifier set, or Control-only with an arrow or digit, is a `warning` that can be accepted (rules, no chord list); registration failure surfaces as `failed(inUse)` and leaves the previous chord registered. Editor and Settings hotkeys are registered in every `PermissionState`; window hotkeys are registered only in `Granted` and unregistered on leaving it. On a preferences change only shortcuts whose value changed re-register; while the Drag Session is not idle the diff is queued and applied on return to idle. Window commands that fire while the Drag Session is not idle are dropped with one log line.
- **LoginItemService** (MainActor, behind a protocol with a scriptable fake). Wraps register/unregister/status; status is read on every Settings appearance and app activation, never stored; the toggle is on only for `enabled`.
- **Stores** (ZonesCore). `LayoutsDocument { version, layouts: [Layout] }`; `AssignmentsDocument { version, assignments: [DisplayKey: AssignmentRecord { layoutID, display: DisplayRecord { name, lastFrame, lastVisibleFrame, scale, lastSeen } }] }`, one map; dormancy is derived at read time (key absent from the current snapshot) and never stored; the export document bundles both, or one Layout, under one version with both arrays optional. Writes are synchronous and atomic (temp file then rename) on Save, Assignment change and import; no debounce; nothing pending at quit. Decoding dispatches on version: older migrates through an ordered chain after a backup; equal decodes; newer is left untouched and reported. A file that fails to decode is renamed aside with a timestamp and defaults load. `Preferences { schemaVersion, activationModifier, spanModifier, shortcuts: [Command: Shortcut?], appearance: { color, opacity, labelsVisible, defaultMargin, defaultGap }, exclusions: Set<BundleID>, enhancedUIPolicy, warnedSeparateSpaces, launchedBefore }` in UserDefaults, decoded field by field with per-field defaults so one bad value never resets the rest. `Clock` protocol (now, sleep) drives every cooldown, retry, poll and debounce.
- **Core shapes.** `Layout { id, name, root: Node, margin: Points?, gap: Points?, surround: Fraction (default 0, present only if Challenge 6 adopts it), origin: template(name, count) | custom }`; nil `margin` or `gap` means "use the Appearance defaults" (Templates always do, custom Layouts may override). `Node = split(axis, ratio in (0,1), first: Node, second: Node) | zone`; `ZoneNumber` is derived, never stored. `WindowRef { pid, bundleID, cgWindowID, handle? }` lives only in memory for one session. `SpanState { displayKey, zones: Set<ZoneNumber>, frozen: Bool, suspended: Bool }`.
- **Diagnostics**. One Logger facade with subsystem and per-module category; production sink is the unified log, test sink an array. Ring buffer of the last 200 events: `SnapRecord { time, pid, bundleID, zone(s), result }`, permission and tap transitions, skip reasons with counts, topology events. The report adds app and macOS versions, signing identity, Displays with keys and frames, Assignments and preferences, is shown in a window before copying, and never records titles.

### State machines
Permission:
```
Unknown -> Granted | NotGranted            (launch check, no prompt)
NotGranted -> Granted                      (poll true)
Granted -> Suspect                         (tap nil | tapLost | apiDisabled from any call or the gated heartbeat)
Suspect -> Granted                         (tap recreated OK and one trivial AX read succeeds)
Suspect -> Revoked                         (Suspect persists 3 s on the Clock)
Revoked -> Granted                         (tap recreated OK and read succeeds; retried every 3 s)
```
In `Revoked`: badge, onboarding window with "Open System Settings" and "Quit and Reopen", drag disabled, window hotkeys unregistered, editor and Settings shortcuts kept, Enhanced UI set drained. There is no separate relaunch state: the trust probe cannot tell a re-granted switch from a stale one for a running process, so a probe-gated state would be reached by elapsed time alone; the relaunch button is always offered with one sentence explaining when it is needed. The General pane shows the state and the tap health as two rows plus "Reset and re-onboard".

Drag Session (pure reducer; events: mouseDown, dragged, cgSample, resolved, flagsChanged, mouseUp, windowGone, tapLost, topologyChanged, spaceChanged, wake, hotkey):
```
Idle --mouseDown(1..2 candidates pass phase 1)--> Pressed(candidates, bounds0)
Pressed --dragged (first)--> Pressed                     (startMoveTracking; CG polling begins)
Pressed --cgSample: exactly one moved, size unchanged--> Moving(windowID)
Pressed --cgSample: any size change--> Idle               (a resize from any edge; terminal for this press)
Pressed --cgSample: more than one moved--> Idle           (ambiguous, fail closed)
Pressed --cgSample: none moved--> Pressed                 (a pause; kept until mouseUp)
Pressed --mouseUp--> Idle                                (a click; nothing recorded)
Moving --activation down--> Arming(windowID)             (resolve: AX map + phase 2 + frame read)
Arming --resolved(handle, facts pass)--> Armed(snapshot = topology minus drop-impossible Displays; highlight = hitTest(cursor))
Arming --resolved skip(reason) | timedOut--> Moving(unarmable)   (no Overlay this press; logged)
Armed --activation up--> Moving                          (hideOverlay; span cleared)
Armed --span down, zone hit on span.displayKey or span empty--> Armed(span += zone)
Armed --span up--> Armed(span.frozen; highlight = union while cursor on span.displayKey)
Armed --span down again--> Armed(span resumes adding to the same set)
Armed --cursor leaves span.displayKey--> Armed(span.suspended; highlight = zone under cursor; suspended set drawn dim)
Armed --cursor returns to span.displayKey--> Armed(span resumed)
Armed --topologyChanged--> Armed(snapshot refreshed; showOverlay(model) again)
Armed --spaceChanged--> Armed                            (re-assert panels; re-hit)
Armed --mouseUp, span non-empty and cursor on span.displayKey--> Snapping(union) -> Idle
Armed --mouseUp, hit zone|nearest--> Snapping(zone) -> Idle
Armed --mouseUp, hit none--> Restoring -> Idle
Armed --mouseUp, cursor on a Display outside the snapshot--> Idle   (no-op, logged)
Moving --mouseUp--> Idle                                 (plain move, untouched)
Pressed|Moving --topologyChanged--> same state           (snapshot refreshed)
any --mouseDown--> same state                            (second press ignored)
any --hotkey(window command)--> same state               (dropped, logged)
any --windowGone | tapLost | wake | app unresponsive--> Idle   (hideOverlay, stopMoveTracking)
```
Modifier state is latched from flagsChanged and confirmed at mouse-up from the up-event flags masked to Shift, Control, Option, Command; the check is containment. Both modifiers down before `Moving` arm at once and begin the Span at the first Zone entered. CG move tracking runs only from the first `dragged` event to `Idle`; AX is touched only in `Arming`, `Snapping` and `Restoring`. The Overlay shows only on the transition to `Armed`; `hideOverlay` is emitted before `snap` or `restore` in the same reducer step as mouseUp. Hit testing and the `none` check always use the Display under the cursor, never the Display the window overlaps most; the write converts into that Display's coordinates. Invariant: the highlighted set always equals the set a mouse-up would snap to; in `Armed` with hit `none` the highlight is empty and every fill dims. Policy for hits lives here: `zone` and `nearest` snap, `none` restores (ADR-0009 as refined in Challenge 2).

Snap result handling: `applied` records the Original Frame if absent and stores `LastSnap`; `clamped` does the same and logs; `refused` records nothing and logs; `timedOut` sets the cooldown; `elementGone` evicts the handle; `noOp` records nothing.

### Window command path (shortcuts)
Every keyboard command runs: Drag Session must be idle -> resolve focused app and focused window on the WindowActor -> ExclusionPolicy (both phases) -> `isFullScreen` -> Display by maximum intersection -> Assignment for that DisplayKey (default Template if none; the in-session Assignment for `unstable`) -> resolve Zones in the fresh visible frame -> target Zone -> SnapService. Target for cycling: if the handle has a `LastSnap` whose frame equals the current read-back frame within 1 pt, Right starts from the highest Zone Number in its set and Left from the lowest; otherwise from the Zone with the largest intersection with the current frame, ties by lower Zone Number; with no intersection Right starts at 1 and Left at the last Zone. Any step that yields nothing ends the command silently and writes one diagnostics line. No observer is needed: the read-back comparison detects a hand move.

### Menu-bar shell
Status item with a template icon and an optional badge (permission or tap lost). Menu, top to bottom: Display name and active Layout for the Display under the cursor as a disabled header; an inline radio list of Layouts (Templates with Zone counts in the name under one disabled group header, custom Layouts under another, active one checked) that sets that Display's Assignment immediately and synchronously; a checkable "Exclude <App Name>" for the frontmost app captured when the menu opened, checked when excluded so the same click removes the Exclusion; Edit Layouts; Settings; Grant Accessibility (only when not granted); About; Quit. Menu construction reads cached state and NSWorkspace only; it never waits on the WindowActor, so it opens instantly while an app hangs. Settings and the editor are ordinary windows that open on the Display under the cursor; from the menu they activate the app and become key; from a hotkey they order front and become key where macOS 14+ cooperative activation allows (yielding path, manual row); the app returns to accessory behaviour on close.

### Editor
The editor works on a draft copy of a Layout through a command stack (split, merge, setRatio, setMargin, setGap, clearMarginGap, rename); undo and redo walk the stack; the validator runs after each command and a failing command is rejected with a reason (`tooSmall`, `notSiblings` with the hint "split the parent the other way first") leaving the draft unchanged. Save validates again, writes synchronously, then replaces the live Layout and rebuilds Overlay models; Cancel discards; Assign sets the current Display's Assignment to the Layout being edited in one click; Save and Close have shortcuts. Divider drags snap to halves, thirds, quarters of the parent and to collinear dividers within 6 points, free with Option; arrows nudge one point (ten with Shift); H and V split the selection; M merges with the sibling chosen by the next click; ratios are stored as fractions. The editor shows the resolved point size for the Display being edited and warns under about 120x80 points. Templates are read-only; duplicating one creates a custom Layout with a fresh id. Deleting an assigned Layout requires choosing a replacement. The editor is a standard resizable window defaulting to the visible frame of the Display being edited, Zones at real scale over a translucent backdrop; it can switch Displays, prompting when dirty; a disconnected Display is edited against its `DisplayRecord` (frame, visible frame, scale) in a window on the current Display. Selection, dirty flag and Display identity live in the app view model; the draft and command stack live in ZonesLayout.

### Launch sequence
1. Set process-wide AX messaging timeout; load documents (migrate with backup, quarantine corrupt, leave newer alone); read Preferences field by field; generate built-in Layouts with the default Margin and Gap; restore Enhanced UI for recovery-file entries whose process still matches and whose prior value was on, then delete the file.
2. Register Carbon hotkeys for editor and Settings (no permission needed); window hotkeys wait for `Granted`.
3. DisplayTopology takes its first snapshot; OverlayController pre-creates one hidden panel per Display with its layers.
4. PermissionMonitor checks trust without prompting. Granted: InputTap starts, window hotkeys register, the health tick begins. Not granted: onboarding unless launched at login (then badge only).
5. Status item appears last so the menu never shows before state exists.

### Cross-cutting rules
- Full-screen: `isFullScreen` true on the target makes every window command a silent no-op; the Overlay still shows for other windows on that Display. A Display whose active Space cannot receive a drop is left out of the arm snapshot (spike 6 decides which Spaces those are).
- Sleep and wake: `wake` ends any Drag Session; PermissionMonitor re-validates the tap and re-polls trust once, DisplayTopology forces a `TopologyChanged`, OverlayController orders panels out.
- Space change: re-evaluate focused window and Display only; re-assert panels front if spike 6 shows new Spaces lose them.
- Stage Manager: no special casing in v1; the Overlay level is above Stage Manager chrome; Snap targets only the resolved window; behaviour is a manual checklist line.
- Enhanced UI safety: in-memory set of pids drained on every write path, on Quit and on `Revoked`; the recovery file is written once per app per session, keyed by bundle identifier, pid and process launch date with the prior value, never consulted on the hot path after that first write.
- Launched at login: detected from the launched-as-login-item flag on the open-application Apple event, read only inside the did-finish-launching callback; suppresses onboarding and Settings windows unless permission is missing (then badge only).
- Chromium/Electron/Java: no bundle lists; behaviour follows the write protocol and read-back. Java windows that report size not settable are positioned only.
- No AX before arming: a plain click or plain drag in any app issues no AX call to that app; move confirmation is a window-server query; the first AX traffic is the resolve step on the transition into `Armed`.
- Idle budget: no timers except the trust poll while not granted and one 5 s health tick while granted (tap enabled check, plus the heartbeat if spike 14 passes); no AX reads otherwise.
- ADR-0013 contingency: if the Space spike passes, `AssignmentRecord` gains an optional Space token and `AssignmentsDocument` bumps to version 2 with a migration that leaves the token absent; lookups already take an Assignment, so nothing else changes shape.
- HIG: template menu-bar icon, standard Settings window with toolbar-style tabs, no Dock icon, Quit in the menu, checkable menu items for toggles, About with version, signing identity, license and the single "inspired by FancyZones" line.

## Testing Decisions

A good test here injects the platform (displays, events, CG samples, AX responses, clock) and asserts on decisions or emitted effects, not on macOS. Every module above except InputTap and OverlayController rendering has a protocol boundary with a scriptable fake in ZonesTestSupport (queued responses, call log, fake-clock latency); fakes are the only test doubles. Each production adapter also has a manual contract test that runs the same scripted scenario against the real OS when a human invokes it, so fake and production cannot drift silently.

Property tests (seeded generator per ADR-0016, failing seed and Layout printed):
- LayoutEngine: for random trees, unrounded `resolve` output tiles the visible frame with no overlap and no gap when Margin and Gap are 0; with Margin and Gap, every pair is separated by exactly Gap and the outer edge by exactly Margin; after `grid`, every edge lies on the backing grid for scales 1, 2 and 3, neighbours still share edges, and separation is within half a backing pixel (exact when Gap and Margin lie on the grid); hit test maps every point in the visible frame to exactly one `zone` or `nearest` and every point outside to `none`; `nearest` is the Zone with minimum edge distance, ties by lower Zone Number; union of any Zone set is the bounding rect; Zone Numbers are a permutation, row-major, and stable under sub-epsilon edge changes; the validator rejects any leaf below the minimum fraction; built-in identifiers are stable across runs; Columns and Rows Zones are equal within epsilon.
- Edit closure: split then merge of the new siblings yields the original tree; setRatio keeps the leaf count; random edit sequences never produce an invalid tree.
- Template generators produce the stated zone counts and are idempotent across display sizes.
- CoordinateSpace: round-trip identity for random rects across random display sets including Displays above and left of primary and mixed scales; `display(for:)` picks the maximum-intersection Display.
- JSON documents: encode/decode round-trip; every migration from golden version 1..n yields a valid document; corrupt input is rejected without partial writes; a Preferences blob with one unknown value loses only that value.
- Reducer invariants: an Overlay is shown only in `Armed`; every path to `Idle` emits `hideOverlay` if one was shown; `snap` is emitted only with the Activation Modifier down at mouse-up; `restore` is never emitted from `Moving`; `hideOverlay` precedes `snap`; the highlighted set equals the set a mouse-up would snap to in every `Armed` state; a Span Modifier release then re-press preserves the set; leaving and returning to the Span's Display preserves the set; no `resolve` effect is emitted before the Activation Modifier is down; no AX-bound effect is emitted from `Pressed` or `Moving`.

Headless deterministic tests on the build machine:
- Drag Session reducer with scripted `PointerEvent` and `cgSample` streams and a fake WindowActor: click (no tracking started), plain drag (tracking started, no resolve), modifier-first, modifier-late, modifier release, span accumulate, freeze, resume, span suspended across a Display seam and resumed with the suspended set in the highlight effect, drop in Gap (nearest), drop outside visible frame (Restore with dimAll), drop on a Display outside the snapshot (no-op), resize from each edge and corner (no session), two stacked candidates resolved by the first moved sample, three candidates fail closed at mouse-down, pause before moving keeps Pressed, both candidates moving fails closed, resolve returns skip (unarmable; later modifier presses do not re-resolve), resolve times out (unresponsive), second mouse-down ignored, hotkey during a session dropped, topologyChanged while armed re-arms with the new snapshot, spaceChanged re-asserts, wake ends the session, window destroyed mid-drag, tap lost.
- Permission state machine with scripted tap and AX signals: revoked-while-idle detected on the first failed call (and by the heartbeat when enabled), Suspect returning to Granted on a transient error, Revoked retrying tap creation on the Clock, Enhanced UI set drained and window hotkeys unregistered on entering Revoked, heartbeat `timedOut` never touching `AppHealth`, heartbeat skipped during a Drag Session, poll period 0.5 s while onboarding is visible.
- DisplayTopology diff with injected snapshot sequences: add, remove, resize, mirror (key is the master, Assignment persisted), unmirror, UUID reappearing, nil UUID retried three times then hardware key with a late success re-emitting, hardware key collision yields unstable, unstable accepts an in-session Assignment and persists nothing, callback storms collapsed to one event.
- ExclusionPolicy against a table of synthetic window descriptors, phase 1 (CG facts, including each system agent bundle) and phase 2 (AX facts, including systemDialog by subrole), size-not-settable (allowed, position-only) and position-not-settable (skipped).
- Modifier masking: flags with Caps Lock, Fn and numpad bits still match.
- SnapService write protocol against a fake AX element that clamps, refuses, times out on the second call, lacks EUI, or has EUI already off: EUI restored on every path; EUI pair skipped when absent; sequence aborts after the first timeout with the call count asserted; `noOp` records nothing; one follow-up position write on clamp, never two; `LastSnap` stored with the read-back frame; recovery file written once per app per session with the prior value and not on the second Snap.
- OriginalFrameRegistry: first-Snap-only capture; mouse path captures the mouse-down bounds, keyboard path the pre-write frame; cleared by Restore; the Snap-Restore-hand-move-Snap-Restore sequence returns the hand-placed frame; app-terminated notification evicts every handle of that pid; two handles wrapping equal elements compare equal; Restore of an off-Display frame clamps onto the Display the window occupies.
- Shortcut validator rejects Option-only and plain keys; the warning rules fire for Command-only, Command+Shift-only and Control-only with arrow or digit and for nothing else; registration diffing re-registers only changed shortcuts; a diff during a Drag Session is queued and applied on idle; failed registration keeps the previous chord; cleared command stays unbound; window hotkeys absent while not granted (HotkeyService fake).
- LoginItemService fake: toggle on only for `enabled`; `requiresApproval` and `notFound` show the caption and keep the toggle off; register from `notFound`.
- Window command path with a fake WindowActor: no focused window, excluded app, full-screen, Zone N absent, command during a Drag Session dropped, cycle from a `LastSnap` whose frame still matches (clamped Calculator at 3 cycles to 4; a Span of 1 and 2 cycles Right to 3 on both Priority Grid and equal Columns), cycle after a hand move falls back to largest intersection, cycle from no match starts at 1 (Right) or last (Left).
- Stores: corrupt file renamed aside, newer version left untouched and reported, import of a newer document refused naming both versions, Merge renames incoming collisions, Replace writes a backup then swaps both documents in one transaction, an Assignment for an absent key is reported dormant and applied when the Display appears, `DisplayRecord` written on every topology event and used by Copy Assignment and Forget, atomic write leaves no half file when the fake filesystem fails mid-write, after Save returns the file decodes to the saved document, export of one Layout round-trips through import.
- WindowActor with a fake that delays beyond the timeout: result is `timedOut`, one immediate retry, cooldown set, next call skipped, retry after cooldown; a tick with a sample outstanding is dropped.
- Editor command stack: undo and redo round-trip, rejected command leaves the draft unchanged with its reason, Save validates and writes once, Cancel writes nothing, Assign writes the Assignment, delete of an assigned Layout requires a replacement, clearing a custom Layout's Margin and Gap makes it follow the defaults.
- Recovery file: entries whose pid, bundle identifier and launch date all match and whose prior value was on are restored at launch; any mismatch is discarded; the file is removed afterwards.

Needs a human on a real Mac (ticketed as manual checklists with expected results):

## Out of Scope
- Re-snapping or re-laying out windows after a Display change, Space change or resolution change.
- Tiling, eviction, or moving any window other than the one being snapped or restored.
- Per-Space Assignments unless the ADR-0013 spike passes.
- Screen Recording, Input Monitoring or any permission other than Accessibility.
- Private APIs for Spaces, window ordering or focus.
- Reading or storing window titles.
- Auto-update, cloud or iCloud sync, App Store distribution, localization beyond English, telemetry or network access.
- Special handling of Stage Manager beyond working on the current stage.
- Window-level animation of Snaps.
- Snapping windows that are full-screen, sheets, popovers, or belong to Zones.
- A helper process or XPC service.
- Snapping by click (without a Drag Session) or by window menu; the keyboard and the modifier-drag are the two paths.
- Escape key to cancel an armed Drag Session (requires key tapping).
- Remembering per-window Zone membership across relaunch; the in-session `LastSnap` is memory only.
- Text or hints drawn on the Overlay beyond Zone Numbers.
- A built-in list of specific system chords in the recorder; warnings are rules over modifier sets.
- Non-sibling merge in v1 (spike first, with a golden table).
- Guessing that a new Display identifier is an old Display; recovery is the user-driven Copy Assignment (US-141).

## Further Notes

### Challenges to ADRs
1. **ADR-0021 (poll AXIsProcessTrusted to detect revocation).** Evidence in event-taps-tcc.md: the trusted check and the CG preflight do not reflect revocation for an already-running process, and Apple DTS advice is to accept a quit and relaunch. Polling alone keeps reporting granted after the user revokes. Refinement, not reversal: revocation is detected from runtime signals (tap creation nil, tap disabled and not re-enablable, `apiDisabled` from any AX call, plus a 5 s heartbeat if spike 14 proves it), the badge and onboarding follow those signals, the re-onboard window always offers "Quit and Reopen" next to "Open System Settings" because the probe cannot distinguish a re-granted switch (a probe-gated relaunch state would fire on elapsed time alone, while the user is still in System Settings), and `Revoked` keeps retrying tap creation so a re-grant that does not need a relaunch recovers by itself. The poll stays for the first grant, at 0.5 s while the onboarding window is visible.
2. **ADR-0009 (modifier-drag ending "outside every zone" restores).** With Margin and Gap greater than zero, a drop one point into a Gap is "outside every zone" and would Restore the window, which users will read as a bug. Refinement: hit testing reports Gap, Margin and surround as `nearest`; the reducer snaps them to that Zone; "outside every zone" means outside the Display's visible frame (menu bar strip, Dock strip), which exists on every Display without relying on Appearance defaults; the Overlay dims as the cue. Also refined: the Original Frame on the mouse path is the mouse-down frame, since "before its first Snap" must mean before the grab, not after the drag.
3. **ADR-0022 (toggle Enhanced UI off during every write).** Evidence in ax-window-moves.md: Enhanced UI is what VoiceOver relies on, and the toggle is itself a write that can fail. Refinement: keep the protocol but (a) restore in a defer on every path, (b) drain the in-memory set on Quit and on revocation, (c) skip the toggle pair when the attribute is absent or already off, (d) expose `EnhancedUIPolicy` (toggle, leave, auto) defaulting to toggle, with `auto` defined by the attribute's read value and never by a bundle list, (e) a once-per-app-per-session recovery record carrying the prior value so a crash mid-write is repaired at the next launch without touching a reused pid.
4. **ADR-0015 (250 ms timeout).** Budget note: one Snap is up to eight AX calls; without an abort rule a hung app costs 2 s on the serial WindowActor, which blocks the next Drag Session and every shortcut even though the main thread is idle. Refinement: abort the sequence at the first `timedOut` (one immediate retry of that call, then the cooldown), keep only the EUI restore, so the worst case is 0.5 s; together with the two-phase ExclusionPolicy, no AX before arming, and the single in-flight sample, the ADR delivers "never freezes".
5. **ADR-0018 (skip windows whose size or position is not settable).** Research recommends writing position when only size is locked; fixed-size utility windows (Calculator, inspectors) are common and the position write is safe. Refinement: skip only when position is not settable; when size is not settable, place without resizing, top-left aligned. The ADR text should drop "size".
6. **ADR-0005 versus ADR-0003 and CONTEXT (Focus Template).** "One center zone at 60 percent" cannot be a split tree whose every leaf is a Zone that tiles the Display. Options: three columns 20/60/20 (Focus becomes three Zones and the named Zone is number 2) or a Layout-level normalized surround fraction applied before Margin, so the tree tiles the Layout rectangle, Focus is one Zone numbered 1, and a drop anywhere on the Display goes to the nearest (only) Zone. The surround needs a one-line amendment to ADR-0003 and CONTEXT ("tiles the Layout rectangle"). All three drafts now recommend the surround; a decision ticket must confirm it before the Templates ticket; the `surround` field exists in the shapes only if it does.
7. **ADR-0008 (span accumulation) is under-specified on release.** The ADR says Zones touched while the key is down accumulate; it does not say what release does. Decision, now shared by all three drafts: release freezes the set, re-press resumes adding to it, crossing to another Display suspends it (drawn dimmer) and returning resumes it, Activation Modifier release clears it. The FancyZones hysteresis rule (keep inside the union, replace outside) is withdrawn: it made the drop target change with no key pressed and left three drafts with three rules.
8. **ADR-0012 (displays identified by CGDisplay UUID).** The UUID can read nil mid-reconfiguration and may collide for two Displays of one model with zero serials. Refinement: Clock-driven retry (three at 1 s, late success re-emits topology), then a hardware (vendor-model-serial) key persisted only when unique among attached Displays, else an unstable key that holds an in-session Assignment and is never persisted. The UUID remains the primary key.
9. **ADR-0006 (frame polling confirms a window move) — a note, not a contradiction.** The ADR names no source for the polled frame. This draft polls the CG window description (a window-server query) rather than the AX frame, so confirming a move costs the target app nothing and a hung app cannot stall Zones until the user arms a Snap; AX is first touched on the transition into `Armed`. Spike 15 must show the AX element mapping at arm time (pid, equal size, nearest position, element under cursor as tie-breaker) is unique for two stacked same-size windows.
