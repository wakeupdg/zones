# Spaces and display topology detection (public APIs only)

Scope: macOS 14+, Swift 6, no private APIs (no CGS/SLS/SkyLight). Checked 2026-10-23 against Apple docs (DocC JSON), the local macOS SDK headers, real OSS source, and this Mac (macOS 27.0.1, 3 displays, "Displays have separate Spaces" ON). Tags: [E] = measured on this machine, [I] = my inference (not stated by the source), [U] = unverified.

## Findings

1. **Best stable display identity = the display UUID, not CGDirectDisplayID.**
   - `NSScreen.deviceDescription["NSScreenNumber"]` returns the CGDirectDisplayID, a plain `uint32_t` ([deviceDescription](https://developer.apple.com/documentation/appkit/nsscreen/devicedescription), `CGDirectDisplay.h` line 20 in the SDK).
   - `CGDisplayCreateUUIDFromDisplayID` / `CGDisplayGetDisplayIDFromUUID` are declared in `ColorSyncDevice.h` (ApplicationServices, macOS 10.4+). The header says the reverse call converts only the "first 32 bits of CFUUIDRef to displayID" ([SDK ColorSyncDevice.h](file:///Library/Developer/CommandLineTools/SDKs/MacOSX.sdk/System/Library/Frameworks/ApplicationServices.framework/Frameworks/ColorSync.framework/Headers/ColorSyncDevice.h)).
   - Apple's web docs for the UUID functions return 404 on the DocC endpoint, so Apple publishes no stability guarantee I could read [U]. Zed's source says the numeric id is "unstable across restarts" and the UUID is "stable" ([Zed screen.rs, secondary](https://git.secluded.site/zed/blob/v0.111.5/crates/gpui/src/platform/mac/screen.rs)).
   - [E] The UUID string equals the plist "Display Identifier" for each screen (LG `5F787B70-...`, built-in `37D8832A-...`, VG270K `E8EFEA41-...`). The plist also keeps entries for 3 UUIDs that are not connected now, so macOS itself keys on UUID across disconnects [I].
   - Fallback fingerprint if UUID lookup returns nil: `CGDisplayVendorNumber` + `CGDisplayModelNumber` + `CGDisplaySerialNumber` [E: all three returned values here] plus `localizedName` ([NSScreen.localizedName](https://developer.apple.com/documentation/appkit/nsscreen/localizedname)).

2. **Mirroring changes which displays are visible.**
   - `CGGetActiveDisplayList`: with hardware mirroring only the primary of the set is listed; with software mirroring all are listed. `CGGetOnlineDisplayList` also includes sleeping/hardware-mirrored displays ([active](https://developer.apple.com/documentation/coregraphics/cggetactivedisplaylist(_:_:_:)), [online](https://developer.apple.com/documentation/coregraphics/cggetonlinedisplaylist(_:_:_:)), SDK `CGDirectDisplay.h` lines 64-96).
   - `NSScreen.screens`: index 0 is the primary (menu bar, origin 0,0); with mirroring it is the largest drawable display. Apple says not to cache the array ([NSScreen.screens](https://developer.apple.com/documentation/appkit/nsscreen/screens)).
   - Callback flags include `kCGDisplayMirrorFlag` / `kCGDisplayUnMirrorFlag` ([SDK CGDisplayConfiguration.h](file:///Library/Developer/CommandLineTools/SDKs/MacOSX.sdk/System/Library/Frameworks/CoreGraphics.framework/Headers/CGDisplayConfiguration.h) lines 211-223).

3. **Resolution changes keep the display, change the geometry.**
   - `NSScreen.frame` is "the full screen rectangle at the current resolution" ([frame](https://developer.apple.com/documentation/appkit/nsscreen/frame)); `visibleFrame` excludes menu bar and Dock, "Don't cache" it ([visibleFrame](https://developer.apple.com/documentation/appkit/nsscreen/visibleframe)).
   - The CG callback reports it as `kCGDisplaySetModeFlag` (header above). Same display, so the UUID key should survive [I]. Zones should store zone geometry as fractions of `visibleFrame`, not pixels.

4. **Two public topology signals; neither is a full replacement for the other.**
   - `NSApplication.didChangeScreenParametersNotification`: "configuration of the displays ... is changed", programmatic or via Displays settings; no `userInfo`; posted on the main actor ([doc](https://developer.apple.com/documentation/appkit/nsapplication/didchangescreenparametersnotification)). It tells you "something changed", never what.
   - `CGDisplayRegisterReconfigurationCallback` (SDK header comments, `CGDisplayConfiguration.h` lines 187-231):
     - Fires once per online display BEFORE the change with `kCGDisplayBeginConfigurationFlag` and no other detail.
     - Fires again AFTER, once per added, removed and currently-online display, with `Add/Remove/Moved/SetMain/SetMode/Enabled/Disabled/Mirror/UnMirror/DesktopShapeChanged` flags.
     - In the AFTER call all CoreGraphics state is current, and it runs after the Carbon Display Manager callbacks.
     - For a removed display, "calls into the CoreGraphics API with the removed display ID will fail".
     - Runs "on the event processing thread" when the app is listening (needs a running main run loop); callbacks must not change display configuration.
   - Relative order of the AppKit notification vs the CG callback is not documented [U]. Spaceman sees `didChangeScreenParameters` and `activeSpaceDidChange` fire in quick succession and keeps a 5-update "topology grace period" ([SpaceObserver.swift](https://github.com/ruittenb/Spaceman/blob/HEAD/Spaceman/Helpers/SpaceObserver.swift), [CLAUDE.md](https://github.com/ruittenb/Spaceman/blob/HEAD/CLAUDE.md)).

5. **No public API returns a Space identifier.**
   - AeroSpace's guide: "Apple doesn't provide public API to communicate with Spaces (create/delete/reorder/switch Space and move windows between Spaces)" ([guide.adoc](https://github.com/nikitabobko/AeroSpace/blob/HEAD/docs/guide.adoc), section "Emulation of virtual workspaces").
   - `kCGWindowWorkspace` (CGWindowListCopyWindowInfo) is deprecated "No longer supported" since 10.8 ([SDK CGWindow.h](file:///Library/Developer/CommandLineTools/SDKs/MacOSX.sdk/System/Library/Frameworks/CoreGraphics.framework/Headers/CGWindow.h) lines 103-107).
   - `NSWorkspace.activeSpaceDidChangeNotification` says only "a Spaces change occurs"; object is the shared NSWorkspace, no `userInfo`; must be registered on `NSWorkspace.shared.notificationCenter` or you get nothing ([doc](https://developer.apple.com/documentation/appkit/nsworkspace/activespacedidchangenotification)).
   - Every Space-ID tool I read uses private calls: Amethyst `CGSCopyManagedDisplaySpaces` ([CGInfo.swift](https://github.com/ianyh/Amethyst/blob/HEAD/Amethyst/Model/CGInfo.swift)), SpaceId ([SpaceIdentifier.swift](https://github.com/dshnkao/SpaceId/blob/HEAD/SpaceId/Application/SpaceIdentifier.swift)), Spaceman, WhichSpace ([DisplaySpaceProvider.swift](https://github.com/gechr/WhichSpace/blob/HEAD/WhichSpace/DisplaySpaceProvider.swift)), yabai ([extern.h](https://github.com/koekeishiya/yabai/blob/HEAD/src/misc/extern.h): `SLSManagedDisplayGetCurrentSpace`, `SLSSpaceGetType`, ...). CORRECTION to the brief: none of them parse `com.apple.spaces` to find the current Space.
   - The only plist use is WhichSpace's file watch on `~/Library/Preferences/com.apple.spaces.plist` as a slow fallback tick; it states the watch "waits for cfprefsd to rewrite the plist" and is slower than both the WindowServer push and `activeSpaceDidChange` ([SpaceChangeNotifier.swift](https://github.com/gechr/WhichSpace/blob/HEAD/WhichSpace/SpaceChangeNotifier.swift), [SpaceMonitor.swift](https://github.com/gechr/WhichSpace/blob/HEAD/WhichSpace/SpaceMonitor.swift)). So the plist is NOT written synchronously with the notification; exact lag not measured [U].

6. **Real plist structure [E]** (`defaults read com.apple.spaces`, plist mtime 10:30 PM PT, read 10:33 PM PT). Top-level keys: `SpacesDisplayConfiguration`, `spans-displays` (= 0 here, meaning separate Spaces ON).
   - `Management Data` keys: `Management Mode`, `Age`, `Monitors`, `Primary`, `Secondary`, `SpaceAssignments`.
   - `Monitors[]` live entry: `Display Identifier`, `Current Space` {`ManagedSpaceID`, `id64`, `type` (0), `uuid`}, `Spaces[]` (same shape). Space entries may carry `WindowManagerInfo.windowSets`.
   - The primary display's live entry says `Display Identifier = Main`, not its UUID. Its UUID appears only in a separate `Collapsed Space` entry.
   - 8 of 11 `Monitors[]` entries are `Collapsed Space` (disconnected or stale displays, some `AutoCreated`). One UUID (built-in) appears 4 times, so the array is not keyed by display.
   - `Space Properties[]` = {`name` = Space uuid, `windows` = [CGWindowIDs]}: a window-to-Space table (3 Spaces, 4 to 8 windows each) [E]. Its freshness is unmeasured [U].
   - No full-screen Space existed during the capture, so the full-screen `type` value and shape are unobserved [U].

7. **Detecting a full-screen Space (public options, best first).**
   - AX: read `AXFullScreen` (Bool) on the focused `AXWindow`. Used by [Loop Window.swift](https://github.com/MrKai77/Loop/blob/HEAD/Loop/Window%20Management/Window/Window.swift) and [AeroSpace accessibility.swift](https://github.com/nikitabobko/AeroSpace/blob/HEAD/Sources/AppBundle/util/accessibility.swift) (`isFullscreenAttr`). The SDK has only `kAXFullScreenButtonAttribute` ("AXFullScreenButton"), so use the string literal [E: grep of HIServices headers].
   - `NSApp.currentSystemPresentationOptions` contains `.fullScreen` while the active app is full screen, and is KVO-observable ([doc](https://developer.apple.com/documentation/appkit/nsapplication/currentsystempresentationoptions), [.fullScreen](https://developer.apple.com/documentation/appkit/nsapplication/presentationoptions-swift.struct/fullscreen)). Whether Apple's own full-screen windows set it is [U]; spike it.
   - Own windows only: `styleMask.contains(.fullScreen)` ([doc](https://developer.apple.com/documentation/appkit/nswindow/stylemask-swift.struct/fullscreen)).
   - Heuristic fallback: window frame equals screen `frame` and `visibleFrame` differs (menu bar gone) [I].
   - To draw overlays above a full-screen app: `[.canJoinAllSpaces, .fullScreenAuxiliary]` ([canJoinAllSpaces](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct/canjoinallspaces): "can appear in all spaces"; [fullScreenAuxiliary](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct/fullscreenauxiliary): "displays on the same space as the full screen window"). Loop's debug overlay uses exactly this pair. `.stationary` = Mission Control does not affect the window ([doc](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct/stationary)). `.managed` is the default for normal-level windows, so such a window stays on the Space where it was created ([doc](https://developer.apple.com/documentation/appkit/nswindow/collectionbehavior-swift.struct/managed)) [I].

8. **"Displays have separate Spaces" (public flag: `NSScreen.screensHaveSeparateSpaces`).**
   - Apple: reflects the Mission Control option ([doc](https://developer.apple.com/documentation/appkit/nsscreen/screenshaveseparatespaces)). [E] true here; matches plist `spans-displays = 0`.
   - ON: each display has its own current Space and menu bar; a window cannot span monitors; moving a window to another monitor moves it to that display's Space, which AeroSpace says the public APIs do not handle correctly; it lists focus/perf bugs (#101, #247, #289, #333) and recommends OFF for stability ([guide.adoc](https://github.com/nikitabobko/AeroSpace/blob/HEAD/docs/guide.adoc), "A note on Displays have separate Spaces").
   - OFF: one Space spans all displays; windows may straddle. Rectangle branches on it for window extension and its "combined display mode" ([ScreenDetection.swift](https://github.com/rxhanson/Rectangle/blob/HEAD/Rectangle/ScreenDetection.swift), [WindowManager.swift](https://github.com/rxhanson/Rectangle/blob/HEAD/Rectangle/WindowManager.swift)).
   - Plist shape when OFF is unobserved [U]. Whether toggling needs logout is [U].

9. **Per-Space state without private APIs: what the others do.**
   - AeroSpace avoids Spaces by design: it emulates workspaces by moving windows off-screen, assumes one macOS Space per monitor, and uses one private call (`_AXUIElementGetWindow`). Its README says it "doesn't acknowledge the existence of macOS Spaces" ([README](https://github.com/nikitabobko/AeroSpace/blob/HEAD/README.md), [guide.adoc](https://github.com/nikitabobko/AeroSpace/blob/HEAD/docs/guide.adoc)). It still listens to `activeSpaceDidChange` only as a "refresh everything" trigger ([GlobalObserver.swift](https://github.com/nikitabobko/AeroSpace/blob/HEAD/Sources/AppBundle/GlobalObserver.swift)).
   - Rectangle: no per-Space state. Uses `NSScreen`, `activeSpaceDidChange` and `didChangeScreenParameters` as refresh triggers; corrects stale `visibleFrame` after Dock changes via the Dock's AX list (#467) ([ScreenDetection.swift](https://github.com/rxhanson/Rectangle/blob/HEAD/Rectangle/ScreenDetection.swift)).
   - Loop: uses `NSScreenNumber` display ids (`NSScreen+Extensions.swift`); one private SkyLight call for display-at-point; `activeSpaceDidChange` only for stash cleanup ([StashedWindowStore.swift](https://github.com/MrKai77/Loop/blob/HEAD/Loop/Stashing/StashedWindowStore.swift)).
   - Amethyst keys state by `ManagedSpaceID` using private `CGSCopyManagedDisplaySpaces`.

## Gotchas

- `activeSpaceDidChange` carries no payload: it does not say which display or which Space changed. You must re-query (focused window, `NSScreen.main`, on-screen window list).
- Plist is lagged and structurally messy: `Main` placeholder for the primary display, stale `Collapsed Space` entries, duplicate display UUIDs, `ManagedSpaceID` reassigned on reboot, wake, lid close/open and mirror/extend (Spaceman CLAUDE.md table). Never use `ManagedSpaceID` as a persistent key. Whether the Space `uuid` is stable across those events is [U].
- Spaceman's observed table: after reboot IDs may swap but per-display positions stay stable; after lid close/open or mirror toggle positions change and Spaces migrate between displays.
- CG removal callbacks: the removed id is already invalid, so snapshot your own `[UUID: geometry]` map BEFORE the change (use the Begin flag) and diff after.
- CG callback is called many times per reconfiguration (once per display, twice per change). Debounce (about 100-300 ms is my guess [U]) and re-enumerate `NSScreen.screens` instead of trusting per-call flags.
- `NSScreen.visibleFrame` can be stale after Dock changes (Rectangle #467) and with Dock auto-hide includes a thin boundary strip (Apple doc).
- `NSWindow.isOnActiveSpace` only answers for windows your process owns: visible windows -> "on the active space"; hidden windows -> "would ordering it onscreen land on the active space" ([doc](https://developer.apple.com/documentation/appkit/nswindow/isonactivespace)).
- `CGWindowListCopyWindowInfo(.optionOnScreenOnly)` lists only windows on currently active Spaces (all displays when separate Spaces is ON) ([SDK CGWindow.h](file:///Library/Developer/CommandLineTools/SDKs/MacOSX.sdk/System/Library/Frameworks/CoreGraphics.framework/Headers/CGWindow.h) lines 141-150); `.optionAll` includes other Spaces but cannot say which Space.
- NSScreen coordinates are bottom-left origin at the primary display; AX/CG window frames are top-left origin. Convert once, in one place (well-known; not re-verified here).
- Zero/negative origins are normal [E]: the built-in display here sits at x = -4808.

## Implications for Zones

1. Identity: `DisplayKey` = display UUID string (from `CGDisplayCreateUUIDFromDisplayID(NSScreenNumber)`), with vendor/model/serial + `localizedName` as a fallback. Never persist CGDirectDisplayID or NSScreen indices. Handle nil UUID (display mid-reconfiguration).
2. Topology pipeline: observe BOTH `didChangeScreenParametersNotification` and `CGDisplayRegisterReconfigurationCallback`; coalesce into one debounced `TopologyChanged` event; on each event re-read `NSScreen.screens` + `visibleFrame` fresh, never cache. Keep the last `[DisplayKey: frame]` snapshot taken before changes.
3. Persist layouts per `DisplayKey` with fractional geometry; when a known UUID reappears, restore its layout; unknown UUID gets the default layout. Mirror sets: treat the mirror group as one display (use `CGGetActiveDisplayList`), and let a layout survive unmirror.
4. Per-Space layout (v1): do NOT promise per-Space layouts. Scope layouts to the display, and treat `activeSpaceDidChange` as "re-evaluate focused window + screen + full-screen status" only. This matches AeroSpace/Rectangle/Loop (none key state by Space).
5. If per-Space is later wanted, spike a public "witness window" token [I, unproven]: one invisible, non-`canJoinAllSpaces`, `.managed` NSWindow per (display, Space) created lazily; on each `activeSpaceDidChange`, the witness with `isOnActiveSpace == true` on that display identifies the Space. Risks: first-visit creation, window migration when a Space is deleted, no witness in full-screen Spaces. Cheaper alternative: fingerprint the on-screen window-ID set from `.optionOnScreenOnly`. Treat the plist only as a hint, never as truth.
6. Full-screen: before snapping, check `AXFullScreen` on the target window; if true, refuse or no-op and hide overlays. Zone overlay windows use `[.canJoinAllSpaces, .fullScreenAuxiliary, .stationary]` and a high window level, so the drag overlay shows on whichever Space is active.
7. Read `NSScreen.screensHaveSeparateSpaces` at launch and on each topology event; if false, warn that windows may straddle and zone geometry for a display is still computed per `NSScreen`. Add a Settings note recommending ON for per-display predictability (opposite of AeroSpace's advice, which is driven by its own off-screen hiding).
8. Tests: topology logic should take an injected `[DisplaySnapshot]` (UUID, frame, visibleFrame, mirrorOf, isMain) so add/remove/resize/mirror sequences and the Begin/After flag order are unit-testable without hardware.
9. Spikes to run before locking design: (a) log timestamps of `activeSpaceDidChange` vs plist mtime vs CG callback on a real Space switch; (b) check `currentSystemPresentationOptions` and `AXFullScreen` in a Safari full-screen Space; (c) record the plist with "Displays have separate Spaces" OFF and with a full-screen Space.
