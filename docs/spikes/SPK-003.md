# SPK-003: listen-only session tap needs only Accessibility

- Date: 2026-10-24, 1:56 AM PT
- Verdict: PARTIAL: host OS only, rest PENDING-HUMAN
- Spec pass rule: listen-only session tap (left down, dragged, up, flagsChanged) is created and delivers events on clean macOS 14, 15 and current release with only Accessibility granted; latency under one frame at 120 Hz (8.33 ms).
- Probe: `Spikes/TapProbe` (`.listenOnly`, `.cgSessionEventTap`, `.tailAppendEventTap`, one definition in `TapConfig.swift`).

## Caveats on the host row (do not read it as a pass)

- The host shell chain has Screen Recording, Input Monitoring and Accessibility all granted. A scratch program outside the probe (`CGPreflightScreenCaptureAccess`, `CGPreflightListenEventAccess`, `AXIsProcessTrusted`) printed `true`, `true`, `true`. So "only Accessibility" is NOT established. TCC was not changed.
- No leftDragged events arrived, so the 120 Hz drag-rate latency was NOT measured. The delay figures come from non-drag events; the two synthetic Shift events had delay 14.692 ms in the last run, which reflects synthetic events being timestamped at creation and is not representative.
- Displays on host: Built-in Retina 120 Hz, VG270K L1 72 Hz, LG Ultra HD 60 Hz.
- `CGGetEventTapList` reports `minUsec=0.0 avgUsec=0.0 maxUsec=0.0` for this listen-only tap in every poll (12 polls in the last run), so it gave no usable latency number; the probe's own timestamps are the measurement.
- Observation that corrects the research note (event-taps-tcc.md item 8): `CGEvent.timestamp` is in nanoseconds of mach uptime on this OS, not mach ticks. The probe converts only its own `mach_absolute_time` via the timebase.
- `mouseEventWindowUnderMousePointer` returned nothing (nil) on the foreign leftDown events, which were not human-originated. Whether it is populated for real hardware clicks is UNKNOWN; the SPK-017 human run decides it.
- `--selftest-shift` posts a synthetic Shift flagsChanged via `CGEventPost`; that call is in the probe binary only (nm shows `_CGEventPost`), never planned for production.

## What the host run does show

- `CGEvent.tapCreate(.cgSessionEventTap, .tailAppendEventTap, .listenOnly, mask)` returned non-nil with Accessibility trusted.
- The tap delivered flagsChanged for a synthetic Shift down and up, and real leftDown/leftUp events. Callback body is about 0.01 ms (max 0.030 ms).
- `tapDisabledEvents=0`.
- AC-003/AC-065 support: `nm -u Spikes/TapProbe/.build/debug/TapProbe | grep -E 'CGRequestScreenCaptureAccess|CGPreflightScreenCaptureAccess|CGPreflightListenEventAccess|CGRequestListenEventAccess|IOHIDRequestAccess|IOHIDCheckAccess|_CGS|_SLS'` returns zero lines. The probe has no Info.plist.

## Run steps for a clean VM (macOS 14, macOS 15, current release)

1. Fresh VM or fresh user, no Screen Recording, Input Monitoring or Accessibility grants for any terminal host. Check System Settings, Privacy and Security: Screen Recording and Input Monitoring list neither the probe nor its host terminal.
2. Build: `swift build --package-path Spikes/TapProbe` (or copy the built `TapProbe` binary).
3. Grant only Accessibility to the built binary or the terminal that runs it (do not click any Screen Recording or Input Monitoring prompt).
4. Run `Spikes/TapProbe/.build/debug/TapProbe > /tmp/tapprobe.log`.
5. Drag a window continuously for 10 s on a 120 Hz display (note the display refresh rate), also press and release Shift once, then press Ctrl-C.
6. Fill the table row from the `SUMMARY` lines: tap created (`TAP created=`), events delivered (`SUMMARY kind=`), p99 delay (`SUMMARY dragged delayMs`), max callback (`SUMMARY dragged callbackMs`), dragged rate. PASS needs both max callback and max delay under 8.33 ms.
7. Paste the log excerpt below.
