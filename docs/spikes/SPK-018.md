# SPK-018 Sleep and wake on a lid-closed docked Mac

**Verdict: untested. The probe is built and its idle-state output verified; no real sleep/wake cycle was run (the host is the user's live machine and was not put to sleep).**

- Fixes (when run): AC-024 and AC-025.
- Host used for the dry run: MacBook Pro (Mac16,1, Apple M4), macOS 27.0.1 (26A434), 3 Displays. Not lid-closed, no sleep.
- Tool: `HardwareProbe sleepwake` (long-running) then, after wake, `HardwareProbe post-wake`.

## What the probe does

- Creates a listen-only session `CGEventTap` (left mouse down/dragged/up plus flagsChanged) and one click-through `NSPanel` per Display (`ignoresMouseEvents`, status-bar level).
- Logs tap-enabled state, panel `isVisible` and frames, and every Display UUID at startup, on `NSWorkspace.willSleepNotification`, on `didWakeNotification` (immediately, +2 s, +8 s) and on `didChangeScreenParametersNotification`.
- Logs `tap DISABLED by system` if the tap callback sees `tapDisabledByTimeout` or `tapDisabledByUserInput`.
- `post-wake` (separate process) compares current UUIDs with the snapshot saved at startup and at `willSleep`, and sends SIGUSR1 so the running probe re-prints its tap and panel state on demand.

## Dry-run evidence (no sleep)

- Startup: `tap=enabled`, 3 panels `isVisible=true` with frames matching the Display frames, 3 UUIDs.
- `post-wake` mid-run: `UUIDs vs pre-sleep snapshot: PASS (persisted)`, SIGUSR1 re-print showed the same tap, panel and UUID state.
- Tap creation succeeded in this run; if it returns nil elsewhere the probe logs `Input Monitoring not granted`.

## To finish (manual, AC-024/025 input)

1. Dock the Mac with external Displays attached; run `HardwareProbe sleepwake`.
2. Close the lid, let it sleep for more than a minute, wake it.
3. Read `didWake` lines: tap state, panel `isVisible`/frames, UUIDs at +0, +2, +8 s; run `HardwareProbe post-wake`.
4. Record: tap survived or was disabled; panels survived or went missing; UUIDs equal before and after. Pass bar: tap and panels survive or are recreated by the wake path, and each UUID persists.
