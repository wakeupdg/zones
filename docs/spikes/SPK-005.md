Part 1 verdict: PASS. The requirement contains `identifier "com.dganesh.zones"` and no `cdhash`.

Findings:

- Wording mismatch with AC-013: the requirement is `identifier ... and certificate leaf = H"<sha1>"`. It does not contain the text "Zones Dev" (that appears only as `Authority=Zones Dev` in `codesign -dvv`). LOCKED-SPEC.md was not edited.
- The Xcode project's `PRODUCT_BUNDLE_IDENTIFIER` is `dev.zones.Zones`. The build-time signature therefore carries that identifier, and AC-013 passes only after a post-build `codesign --identifier com.dganesh.zones`. See Consequences.
- A plain `codesign --force` without `--options runtime` drops the hardened-runtime flag (`flags=0x0`). Add `--options runtime` if the hardened runtime matters for the grant.
- The T01 shell has no `AXIsProcessTrusted` call (`grep -rn AXIsProcessTrusted App Sources` returns nothing), so Part 2 will use the WriteProbe stand-in (`WriteProbe --trust`) signed with the same identity and identifier.

## Consequences

- AC-013: the auto Verify passes as written (`identifier "com.dganesh.zones"` present, `cdhash` absent). Wording flag: the requirement contains `certificate leaf = H"<sha1>"`, not the text "Zones Dev"; "Zones Dev" is visible only as `Authority=Zones Dev` in `codesign -dvv`. If the spec wants the name, its Verify must use `codesign -dvv`.
- AC-013 / T01: the Xcode target's `PRODUCT_BUNDLE_IDENTIFIER` is `dev.zones.Zones`, so the build-time signature carries that identifier. The dev flow must either re-sign with `--identifier com.dganesh.zones` after the build or the project must use `com.dganesh.zones`. Not changed here (App/ is out of scope).
- T38 (release/signing): a plain `codesign --force` drops the hardened runtime (`flags=0x0`); add `--options runtime` for release builds. The stable requirement depends on the leaf certificate hash, so recreating the "Zones Dev" identity changes the requirement and invalidates the grant; `scripts/dev-cert.sh` is idempotent and does not recreate it.
- Dev-cert creation needed no keychain dialog here (identity already present, 1 valid identity).
