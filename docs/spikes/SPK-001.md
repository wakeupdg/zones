# SPK-001: Per-Space identification via hidden witness windows

Verdict: PENDING-HUMAN-RUN

The probe, the plan file and a single-Space smoke test exist. The 20 Space switches (creation, deletion, Display reconnect, full-screen) need a human.

## Machine
- Model Mac16,1 (M4), macOS 27.0.1 (Build 26A434), probe built in debug mode.
- 3 Displays (LG 60 Hz, Built-in 120 Hz, VG270K 72 Hz), separate Spaces ON.

## Method
- Mode `witness`. One hidden `.managed` `NSWindow` per (Display, Space), `collectionBehavior = [.managed]` (not `canJoinAllSpaces`), created lazily on the first visit. No private API.
- Two hidden variants are created together and judged separately:
  - A: `orderFrontRegardless()` then `orderOut(nil)` (hidden).
  - B: `alphaValue = 0`, `ignoresMouseEvents`, ordered front.
- On each `activeSpaceDidChange` the probe waits 400 ms, then reads `isOnActiveSpace` for the witnesses of the observed Display. The operator's plan file gives the expected Space label per switch. First visit: no witness may report true, then a new witness is created and bound to that label. Revisit: exactly the bound witness must report true. Anything else (none, several, another one) is incorrect.
- Full-screen Spaces get no witness. Detector: a layer-0 window (not ours) covers the Display, or the focused window reports `AXFullScreen`, and no witness is true. The detector inputs are printed per row.
- Pure verdict logic (`WitnessBook`, `parsePlan`) is covered by `--self-test` (12 checks).

## Recorded results (automated)
`witness --once` on the desktop Space, both variants on all 3 Displays:

| witness | variant | isOnActiveSpace | isVisible |
| --- | --- | --- | --- |
| W1, W3, W5 | A ordered-out | true | false |
| W2, W4, W6 | B alpha-0 ordered-front | true | true |

- Each Display reports exactly its own two witnesses as true in the current Space (per-Display query returned one witness per variant).
- Smoke plan (`0 Desktop 1`): first visit created W1 (A) and W2 (B) with no false positives.
- This shows creation works and `isOnActiveSpace` is true for a hidden (ordered-out) witness in the Space it was created in. It does NOT yet show that an ordered-out witness reports false from another Space; that is the point of the 20-switch run.

## Caveats
- Display reconnect and Space deletion move windows between Spaces; those switches are where a witness is most likely to be ambiguous.
- Full-screen detection is heuristic. A maximised borderless window could be mistaken for a full-screen Space.
- Extra `activeSpaceDidChange` events (for example from Mission Control) shift the plan by one line; the log prints every observation with its time.

## Consequences

- Fail: per-Space Assignments move to out of scope; ADR-0013 stays per-Display only.
