# SPK-011 Login item behavior on a clean account

**Verdict: untested. The probe is built and runs; the protocol needs a signed app bundle on a clean macOS account, which was not available. Only the bare-binary baseline was observed.**

- Fixes (when run): AC-027 (derivation table) and AC-028 (manual sequence).
- Host used for the baseline: macOS 27.0.1 (26A434), the user's own account (not clean).
- Tool: `HardwareProbe login [status|register|unregister|open-settings]`. Prints `LoginItemStatus` names (`enabled`, `requiresApproval`, `notFound`, `notRegistered`), the raw `SMAppService.Status`, bundle path, quarantine xattr and macOS version before and after each action.

Baseline note: a non-bundle executable reports `notFound`, so AC-027's "notFound shows toggle off" row is reachable without a bundle; the register path must be tested from a real .app.

## Protocol to run (clean account)

1. Wrap the built binary in `HardwareProbe.app/Contents/MacOS/HardwareProbe` with an Info.plist (`CFBundleIdentifier`, `LSUIElement` true) and sign it (Developer ID, or ad-hoc to record the invalidSignature case).
2. Copy to /Applications; `login status`, `login register`, `login status`; then disable it in System Settings > Login Items and `login status`. Record requiresApproval or notFound.
3. Copy the app into a DMG, mount it, `xattr -w com.apple.quarantine "0081;00000000;Safari;" <copy>`, run `login register`, record the result and status.
4. Move the registered app to another folder; `login status`. Record.
5. Log out and in once to confirm launch with no window (AC-028).
