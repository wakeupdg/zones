# SPK-009: Overlay frame time

Verdict: PENDING-HUMAN-RUN

Synthetic runs: PASS for both CALayer and SwiftUI (NSHostingView). The real-drag runs (at least 2000 dragged events each) need a human at a 120 Hz Display.

## Machine
- Model Mac16,1 (M4), macOS 27.0.1 (Build 26A434), probe built in debug mode (so numbers are conservative).
- Load Display: Built-in Retina, `NSScreen.maximumFramesPerSecond` 120, 1800x1169 points. Other Displays: LG 60 Hz, VG270K 72 Hz.
- Budget: 1 frame at 120 Hz = 8.33 ms.

## Method
- Mode `frametime`. One `ProbePanel` (frame = `screen.frame`) with 12 zone layers (4x3 grid in `visibleFrame`) plus 1 highlight layer, matching `PanelModel` worst case.
- Per event the handler hit-tests the point, sets the opacity of all 12 zone layers, and moves the highlight. Timed with `ContinuousClock` from the start of the update through the end point.
  - CALayer variant: persistent layers, `CATransaction.setDisableActions(true)`, end point `commit` (as the ticket asks) and `flush` (adds `CATransaction.flush()`).
  - SwiftUI variant: `NSHostingView`, `@Observable` state; a state change is applied on the next layout pass, so the timed path is `layoutSubtreeIfNeeded` + `displayIfNeeded` + `CATransaction.flush()`.
- 60 warm-up events discarded, then 2400 timed events per run.
- Synthetic drivers: display link at 120 Hz requested, and a 240 Hz run-loop timer.
- Pass rule (coded in `frameTimeVerdict`): p99 within 8.33 ms and under 1 percent of events over 8.33 ms.

- The display link delivered 16.667 ms intervals even though the panel is 120 Hz capable and `preferredFrameRateRange` asked for 120. So the display-link runs were effectively 60 Hz event cadence; the 240 Hz timer runs cover the faster cadence (4.16 ms intervals).

## Caveats
- The timer measures CPU time to build and commit the transaction. It does not measure GPU time or the compositor, so "under one frame" here means the main thread is not the bottleneck. Instruments frame pacing is the cross-check.
- Debug build; display link capped at 60 Hz cadence in the synthetic run.
- The 11.24 ms outlier shows one-off hiccups exist; real-drag p99 and max decide.

## Consequences
- AC-040 and AC-039 (overlay update budget): the 8.33 ms budget is met by a wide margin (about 90x on p99) with persistent CALayers; SwiftUI is about 10x slower than CALayer but also far under budget in synthetic runs.
- ADR-0023 says SwiftUI is adopted only if it also passes. Synthetic evidence: it passes. Real-drag evidence: pending. Until then the lower-risk, measured-faster choice is CALayer.
- T31 builds the hot path (highlight movement) with persistent CALayers; SwiftUI stays acceptable for static zone chrome only.
