# SPK-007: AX moved and resized notification cadence

Verdict: PENDING-HUMAN-RUN. The `cadence` mode is implemented and smoke-tested with no drag (zero counts, no crash); live drags in each app need a human.

- Environment: macOS 27.0.1 (26A434). Smoke test 2:00 AM PT, 2026-10-24, host = Claude Code desktop session. Probe commit: ticket/T06 commit "T06 slice 6: revoke mode, SPK-006 and SPK-007 pending notes".
- Smoke result: `cadence --app finder --seconds 5` registered window-level and app-level observers (all four of kAXWindowMoved/WindowResized/Moved/Resized returned success on both elements), created the listen-only tap, logged mouse down/up markers, and printed "no notifications observed (zero counts)".

## Human procedure (one trial per app, two if unclear)

For each app, open one ordinary window in front, run the command, then within the 40 s window press the mouse on the title bar, drag the window around for 2 to 3 s, and release. Do one separate drag that resizes from a corner.

- Finder: `swift run --package-path Spikes/AXSignalsProbe AXSignalsProbe cadence --app finder --seconds 40`
- Safari: `... cadence --app safari --seconds 40`
- Chrome: `... cadence --app chrome --seconds 40` (the probe sets `AXManualAccessibility` on Chrome so its AX tree is live)

Logs: `docs/spikes/logs/cadence-<app>-<run>.jsonl`. The printed summary gives, per notification name: count, count between down and up, count within 50 ms after up, min/median/max inter-arrival ms, and the verdict line `end-of-gesture-only` or `continuous`.
