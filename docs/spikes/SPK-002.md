# SPK-002: Click-through panel during a drag

Verdict: PENDING-HUMAN-RUN

Automated half (no mouse, no Space changes): PASS. Hardware half (real Shift + title-bar drag, full-screen, Split View, new Space, second Display full-screen): not run, needs a human.

## Machine
- Model Mac16,1 (M4), macOS 27.0.1 (Build 26A434), probe built in debug mode.
- 3 Displays, separate Spaces ON (`screensHaveSeparateSpaces` true):
  - 0 LG Ultra HD, 60 Hz, frame 3008x1692.
  - 1 Built-in Retina, 120 Hz, frame 1800x1169, visibleFrame top inset 38.
  - 2 VG270K L1, 72 Hz, frame 3008x1692.

## Method
- Probe: `Spikes/PanelProbe`, mode `panel`. Recipe is ADR-0023 (borderless + nonactivatingPanel, `.screenSaver`, `canJoinAllSpaces, fullScreenAuxiliary, stationary, ignoresCycle`, `ignoresMouseEvents`, never key or main, no shadow, clear, `.accessory`). One panel per screen, frame = `screen.frame`.
- Drag arm: global `NSEvent` monitor. Mouse down in the top 52 pt of a layer-0 window, then Shift held and 3 pt of movement arms. `orderFrontRegardless()` once; `orderOut` on mouse up.
- Per run it logs frontmost pid, `NSApp.keyWindow`, the frontmost layer-0 window (key proxy), the AX focused window, and the CGWindowList layer of each panel, at before, during and after.
- Per Space change it logs, 300 ms later, a per-Display table (frame, visibleFrame, panel on screen at layer 1000, `isOnActiveSpace`, occlusion, menu bar window, full-screen guess), with `--reassert` also 300 ms after `reassert()`.

## Findings so far
- `isFloatingPanel = true` resets `level` to `.floating`. Set `level = .screenSaver` AFTER it, or AC-043 fails. (Found by the `--self-test` red run.) T31 must keep this order.

## Expected results (provisional, fixed by the verdict)
- AC-044 (manual): during an armed Drag Session frontmost pid and key window are unchanged and CGWindowList shows Zones panels at layer 1000 only while armed. Observed on the desktop Space (synthetic); real-drag confirmation pending.
- AC-046 (manual): expectation depends on the pending drop test. If macOS refuses the drop on a full-screen Display, Zones shows no Overlay there and does nothing on drop. If it allows it, the Overlay must show there.

- AC-043 (auto): confirmed buildable as specified, with the level-after-isFloatingPanel ordering.
- `hide()` vs `orderOut()`: in this probe both are `orderOut(nil)` on every panel (panels are kept, not closed). T31 should do the same; `hide()` additionally clears the highlight model.
- Shift-drag visibility on all three Space kinds: NOT YET MEASURED.

## Caveats
- The key window is judged by a proxy (frontmost layer-0 window and AX focus), because `NSApp.keyWindow` only sees this process.
- Title-bar detection is a 52 pt heuristic.
- The "full-screen guess" is a heuristic (a layer-0 window covering the Display) and can false-positive.
