## Smoke-test observations (no revocation, trusted)

- `AXIsProcessTrusted()` read `true` on every 250 ms row.
- Listen-only tap (mouseMoved, leftMouseDragged, flagsChanged) was created and `CGEvent.tapIsEnabled` stayed `true`; events were counted per row.
- Brief's trivial read (`AXUIElementCopyAttributeValue(systemWide, kAXFocusedApplicationAttribute)`) returned raw -25204 (`cannotComplete`) on every row while trusted, immediately (about 0 ms) and independent of the messaging timeout (0, 0.25, 1, 3 s all identical). The same host read system-wide `kAXRoleAttribute` as 0 (success), `AXFocusedUIElement` as -25204, and an app-element role read as 0.
- Consequence for T20: the heartbeat must treat only raw -25211 (`apiDisabled`) as the revocation signal; `ok` and `cannotComplete` both mean "still granted". The probe therefore also logs an alternate read (system-wide `kAXRoleAttribute`, columns `altRaw`, `altStatus`) beside the brief's read, so the trials show which of the two actually returns -25211 after revocation. T20 should prefer whichever returns `ok` when trusted AND `apiDisabled` when revoked.

## Human procedure (three trials, one invocation each)

1. System Settings > Privacy & Security > Accessibility: ensure the host terminal is ON.
2. In that terminal, from the repo root: `swift run --package-path Spikes/AXSignalsProbe AXSignalsProbe revoke --seconds 90`
3. Wait for rows to scroll. Press Return in the terminal at the instant you turn the toggle OFF. Keep moving the mouse until the run ends.
4. Repeat for trials 2 and 3 (turn the toggle ON again before each).
5. Logs land in `docs/spikes/logs/revoke-system-<run>.jsonl`; the printed summary gives: first apiDisabled latency (pass if at most 5.0 s), `AXIsProcessTrusted` values over 10 s after the marker, tap events after the marker, tap enabled flag at the end.
